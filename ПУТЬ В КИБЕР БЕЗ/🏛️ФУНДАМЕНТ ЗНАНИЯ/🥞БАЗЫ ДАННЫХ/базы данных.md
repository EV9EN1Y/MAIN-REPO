Темы по базам данных для кибербезопасности и пентеста можно 
База данных — это набор данных, хранящихся в структурированном виде

> Система управления базами данных — это совокупность языковых и программных средств, которая осуществляет доступ к данным, позволяет их создавать, менять и удалять, обеспечивает безопасность данных и т.д.

Если говорить более простыми словами, то СУБД — это система, позволяющая создавать базы данных и манипулировать сведениями из них.

## [Рейтинг СУБД](https://sql-academy.org/ru/guide/basic-database-concepts#rejting-subd)

На данный момент рейтинг систем управления базами данных на основании [db-engines](https://db-engines.com/en/ranking) имеет следующий вид:

	- PostgreSQL - реляционная СУБД
	 MongoDB - документоориентированная СУБД

Можно обратить внимание, что 7 из 10 самых популярных СУБД — реляционные - В такой базе данные структурированы в виде таблиц, которые содержат строки и столбцы.

## [Особенности реляционных БД](https://sql-academy.org/ru/guide/relation-databases#osobennosti-relyacionnyh-bd)

- Модель данных в реляционных БД определена заранее и является строго типизированной
- Данные хранятся в таблицах, состоящих из столбцов и строк
- На пересечении каждого столбца и строчки допускается только одно значение
- Каждый столбец проименован и имеет определённый тип, которому следуют значения со всех строк в данном столбце
- Столбцы располагаются в определённом порядке, который определяется при создании таблицы
- В таблице может не быть ни одной строчки, но обязательно должен быть хотя бы один столбец
- Запросы к базе данных возвращают результат в виде таблиц

# [Документоориентированные БД](https://sql-academy.org/ru/guide/document-oriented-databases#dokumentoorientirovannye-bd)

> Документоориентированные базы данных – это тип баз данных, направленный на хранение и запрос данных в виде документов, подобным [[Json]].

В отличие от других баз данных, документоориентированные оперируют «документами», сгруппированными по коллекциям. Документ представляет собой набор атрибутов (ключ и соответствующее ему значение). Значения могут быть как простыми типами данных (строки, числа или даты), так и более сложными, такими как вложенные объекты, массивы и ссылки на другие документы.

## [Особенности документоориентированных БД](https://sql-academy.org/ru/guide/document-oriented-databases#osobennosti-dokumentoorientirovannyh-bd)

В реляционных базах данных структура записей строго определена и каждая запись содержит одни и те же поля. Даже если поле не используется, оно присутствует, хоть и пустое.

В документоориентированных же БД используется другой подход: в них отсутствует схема данных, что позволяет добавлять новую информацию в некоторые записи, не требуя при этом, чтобы все остальные записи в базе данных имели одинаковую структуру.

Документы в базе данных адресуются с помощью уникального ключа, обычно это строка, которая генерируется автоматически. По нему можно, например, извлекать запись или ссылаться на другие документы.

Другой значимой особенностью документоориентированных баз данных является то, что, помимо простого поиска документов по ключу, как в key-value базах данных, они предоставляют свой язык запросов, функционал, синтаксис и производительность которого отличается от одной реализации к другой.

###  ПОЛНЫЙ СИНТАКСИЧЕСКИЙ КАРКАС SQL (С ФОКУСОМ НА ИНЪЕКЦИИ)

#### **1. DDL (Data Definition Language) — Редко используется, но опасно**

sql

-- 1. CREATE (создание объектов для persistence-атак)
CREATE DATABASE dbname;
CREATE TABLE tabname (col1 INT, col2 VARCHAR(255));
CREATE INDEX idx_name ON tabname(col);
CREATE VIEW view_name AS SELECT ...; -- Возможность скрыть вредоносный запрос

-- 2. ALTER (модификация структуры)
ALTER TABLE tabname ADD col3 TEXT;
ALTER TABLE tabname DROP COLUMN col2;
ALTER USER username IDENTIFIED BY 'newpass'; -- Смена пароля через инъекцию

-- 3. DROP/TRUNCATE (деструктивные операции)

#### **2. DML (Data Manipulation Language) — Ядро SQLi**

sql

-- 1. SELECT (100% синтаксис с точками инъекции)
SELECT [ALL|DISTINCT|DISTINCTROW]  -- DISTINCT может менять вывод
    [TOP n] [PERCENT]              -- MSSQL-специфика
    [HIGH_PRIORITY] [STRAIGHT_JOIN]
    [SQL_SMALL_RESULT] [SQL_BIG_RESULT] [SQL_BUFFER_RESULT]
    [SQL_CACHE|SQL_NO_CACHE] [SQL_CALC_FOUND_ROWS]
    column1 [[AS] alias1],
    {scalar_function() | (subquery)} -- Точка инъекции!
FROM table1 [[AS] alias1]
    [{INNER|LEFT|RIGHT|FULL|CROSS} JOIN table2 
     [ON condition | USING (col_list)]] -- JOIN для сложных payload
    [[NATURAL] JOIN table2]
    [{STRAIGHT_JOIN|STRAIGHT_LEFT_JOIN}] -- MySQL оптимизация
[WHERE where_condition]          -- Основная точка инъекции
[GROUP BY {col_name|expr|position}
    [WITH ROLLUP]]               -- MySQL для субагрегатов
[HAVING having_condition]        -- Вторичная точка инъекции
[ORDER BY {col_name|expr|position}
    [ASC|DESC], ...]
[LIMIT {[offset,] row_count | row_count OFFSET offset}] -- MySQL/PostgreSQL
[PROCEDURE procedure_name(argument_list)] -- Опасная возможность MySQL
[INTO OUTFILE 'file_name'        -- Запись в файл (требует прав)
    [CHARACTER SET charset_name]
    export_options
 | INTO DUMPFILE 'file_name'     -- Бинарный дамп

[FOR UPDATE|LOCK IN SHARE MODE]; -- Блокировки для DoS

-- 2. INSERT (инъекция для добавления/модификации данных)

    [IGNORE]

{VALUES ({expr|DEFAULT}, ...), (...)
 | SELECT ...}                    -- Опасная возможность подстановки SELECT!
[ON DUPLICATE KEY UPDATE col=expr]; -- MySQL upsert

-- 3. UPDATE (модификация всех записей через инъекцию)
UPDATE [LOW_PRIORITY] [IGNORE] tabname
    SET col1=expr1 [, col2=expr2] ...
[WHERE where_condition]          -- Без WHERE обновит ВСЕ строки!
[ORDER BY ...]
[LIMIT row_count];

-- 4. DELETE (удаление через инъекцию)
DELETE [LOW_PRIORITY] [QUICK] [IGNORE]
    FROM tabname
[WHERE where_condition]          -- Критично: без условия удалит ВСЕ!
[ORDER BY ...]
[LIMIT row_count];
