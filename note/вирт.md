### **1. Включаем настройку в UTM (до запуска ВМ)**

Открой настройки твоей виртуальной машины Linux (иконка шестерёнки) и перейди в раздел **"Sharing"**. Поставь галочку **"Enable Clipboard Sharing"** и нажми "Save" [](http://sharemind-sdk.github.io/sdk-arm64.html)[](https://medium.com/@kryo/how-to-enable-clipboard-sharing-between-macos-arm-and-kali-linux-in-utm-11ce2f66f3c1).

### **2. Устанавливаем SPICE-агента внутри Linux**

Запусти ВМ, открой терминал в Ubuntu и выполни:

bash

sudo apt update
sudo apt install spice-vdagent -y

**Важно:** На некоторых сборках драйвер может быть предустановлен, тогда команда просто обновит его до актуальной версии. Это нормально.

### **3. Запускаем агента и проверяем**

После установки перезагрузи виртуалку или просто выполни две команды в терминале:

bash

# Запускаем системный демон
sudo systemctl enable --now spice-vdagentd
# Запускаем пользовательский агент (важный шаг, который часто забывают!)
spice-vdagent &

### **4. Главный тест**

Попробуй скопировать любой текст на macOS (Cmd+C) и вставить внутрь Linux (Ctrl+V или ПКМ -> Вставить). Если сработало — отлично. Теперь проверь в обратную сторону.

### Пошаговый план действий

Перед началом, если виртуалка еще не запущена, включи ее. Все команды выполняй в **терминале Ubuntu**.

**Шаг 1. Обновляем систему**

Это стандартная процедура, чтобы подтянуть последние версии драйверов и прошивок, которые могут понадобиться карте[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).

bash

sudo apt update

**Шаг 2. Устанавливаем драйвер**

Драйвер `mt76x2u` уже есть в ядре Linux, но его нужно «подгрузить» вручную. Это абсолютно безопасно[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).

bash

sudo modprobe mt76x2u

- **Ожидаемый результат:** Команда не выведет никаких сообщений, если драйвер найден. Это хороший знак.
    

**Шаг 3. Проверяем, видит ли система карту**

Эта команда покажет все USB-устройства. Твоя карта должна быть в списке с ID `0e8d:2870`[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).

bash

lsusb | grep MediaTek

**Шаг 4. Переключаем карту из режима накопителя**

Эта команда отправит карте специальный сигнал, чтобы она «поняла», что ее используют не как флешку. **Скопируй её очень внимательно** — от правильности кода зависит успех[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).

bash

sudo usb_modeswitch -v 0e8d -p 2870 -M "5553424312345678000000000000061b000000020000000000000000000000"

- **Ожидаемый результат:**`Warning: ignoring -R, no switching method given. Device was reset.` Сообщение об ошибке `LIBUSB_ERROR_NO_DEVICE` — это нормально, так и должно быть[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).
    

**Шаг 5. Проверяем, что карта переключилась**

Теперь ID устройства должен смениться с `0e8d:2870` на `0e8d:7612`[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).

bash

lsusb | grep MediaTek

**Шаг 6. Поднимаем беспроводной интерфейс**

Если в выводе `lsusb` появился ID `7612`, значит, карта переключена. Осталось только поднять сетевой интерфейс[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).

bash

# Показать все сетевые интерфейсы
ip a

В списке должен появиться новый интерфейс, например, `wlan0` или `wlx...`. Если он есть — всё, цель достигнута.

---

### 💡 Если что-то пошло не так

- **Если на Шаге 5 карта не появилась (`lsusb` пуст):** Подожди 30 секунд и повтори команду `lsusb | grep MediaTek`. Иногда ей нужно время, чтобы переключиться[](https://legacy.redhat.com/pub/redhat/linux/6.2/en/doc/HOWTOS/other-formats/html/CDROM-HOWTO-html/CDROM-HOWTO-6.html#ss6.10).
    
- **Если на Шаге 4 ошибка:** Внимательно проверь правильность команды. Символы после `-M`должны быть скопированы точно один в один.

##  Итоговое заключение: Проблема и решение для MediaTek MT7612U (ID 0e8d:2870)

### 🎯 Описание устройства

Был приобретен USB Wi-Fi адаптер на чипсете **MediaTek MT7612U** (также известен как mt7612u, mt7662u, модель WUBM-273ACN) [](https://forums.developer.nvidia.com/t/mt7612u-wifi-device-not-working/158123/1)[](https://blog.csdn.net/qq_41101213/article/details/128385478). Устройство позиционируется для задач пентеста и должно поддерживать:

- Режим монитора (Monitor Mode)
    
- Инъекцию пакетов (Packet Injection)
    
- Работу с Aircrack-ng (airmon-ng, airodump-ng, aireplay-ng) [](https://blog.csdn.net/KeepPromise/article/details/132085513)[](https://www.cnblogs.com/GCom/p/17617274.html)[](https://www.e-com-net.com/article/1697041119034028032.htm)
    

### 🧠 Корень проблемы

Адаптер при подключении определяется системой с **VID:PID 0e8d:2870** и работает в режиме **виртуального CD-ROM** [](https://marc.info/?l=linux-wireless&m=160674114031117&w=2)[](https://www.spinics.net/lists/linux-wireless/msg206038.html). Это сделано производителем намеренно: внутри эмулируется CD-привод, содержащий драйверы для Windows [](https://marc.info/?l=linux-wireless&m=160674114031117&w=2)[](https://www.spinics.net/lists/linux-wireless/msg206038.html).

**В Linux это проявляется как:**

- Устройство видно как флешка/привод
    
- Драйвер `mt76x2u` не может подхватить устройство автоматически
    
- Сетевой интерфейс не появляется
    

**Для корректной работы необходимо:**

1. Принудительно переключить устройство из режима CD-ROM в режим Wi-Fi адаптера с помощью `usb_modeswitch`
    
2. Обеспечить наличие правильных файлов прошивки (firmware)
    

### 🔧 Решение (алгоритм)

#### Часть 1: Установка прошивки

Драйвер `mt76x2u` встроен в ядро Linux, но требует наличия файлов прошивки [](https://www.pclinuxos.com/forum/viewtopic.php?t=90&sid=468974d7525aea449f706a7dd354645b&start=10)[](https://www.pclinuxos.com/forum/viewtopic.php?t=90&start=10&sid=1a2f5e9e7b82127036012531eba320cc&view=print)[](https://raw.githubusercontent.com/morrownr/USB-WiFi/13c7dd822a2c8c731a7c5a4e0d8d2864897ab0fe/home/How_to_Install_Firmware_for_Mediatek_based_USB_WiFi_adapters.md):

bash

# Скачиваем прошивки из официального репозитория linux-firmware
wget https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git/plain/mediatek/mt7662u.bin
wget https://git.kernel.org/pub/scm/linux/kernel/git/firmware/linux-firmware.git/plain/mediatek/mt7662u_rom_patch.bin
# Размещаем в нужной директории
sudo mkdir -p /lib/firmware/mediatek
sudo cp mt7662u.bin /lib/firmware/mediatek/
sudo cp mt7662u_rom_patch.bin /lib/firmware/mediatek/

#### Часть 2: Переключение режима устройства

Правильная команда для `usb_modeswitch` [](https://marc.info/?l=linux-wireless&m=160674114031117&w=2)[](https://www.spinics.net/lists/linux-wireless/msg206038.html):

bash

sudo usb_modeswitch -v 0e8d -p 2870 -R -W -M "5553424312345678000000000000061b000000020000000000000000000000"

После успешного выполнения ID устройства должен измениться на **0e8d:7612**.

#### Часть 3: Проверка и активация

bash

# Проверяем новый ID
lsusb | grep MediaTek
# Загружаем драйвер
sudo modprobe mt76x2u
# Проверяем появление сетевого интерфейса
ip a

|Аспект|Детали|
|---|---|
|**Архитектура**|Проблема актуальна для всех архитектур (x86, ARM, включая Mac M1/M2 в виртуализации)|
|**Виртуализация**|В UTM/QEMU требуется проброс устройства через `utmctl usb connect` или графический интерфейс|
|**Статус драйвера**|`mt76x2u` входит в основное ядро Linux, не требует компиляции из сторонних исходников|
|**Альтернативный ID**|Некоторые устройства переключаются на `0e8d:7610` вместо `7612`|

### 🎓 Для других LLM и специалистов

**Краткое резюме:**

- **Симптом**: USB Wi-Fi адаптер определяется как CD-ROM (0e8d:2870 вместо 0e8d:7612)
    
- **Причина**: Фабричный режим эмуляции CD-привода с драйверами Windows
    
- **Решение**: `usb_modeswitch` + firmware-файлы в `/lib/firmware/mediatek/`
    
- **Драйвер**: `mt76x2u` (встроен в ядро, начиная с версии 5.x)
    
- **Проверка**: После переключения `lsusb` должен показывать ID 0e8d:7612
    

**Для сред с виртуализацией (UTM, QEMU, VMware):** Адаптер может "отваливаться" после переключения. В этом случае требуется повторный проброс устройства в гостевую систему через интерфейс гипервизора или команды `utmctl usb connect`.

## ЯДЕРНОЕ РЕШЕНИЕ (выполнять строго по порядку)

### **ШАГ 0 — Подготовка на macOS**

bash

# Отключаем карту от macOS полностью (чтобы не мешалась)
sudo pkill -f "UTM"
# Отключаем все службы, которые могут захватить USB
sudo kextunload -b com.apple.iokit.IOUSBFamily 2>/dev/null

### **ШАГ 1 — Правильная команда usb_modeswitch для MT7612U**

Внутри твоей Ubuntu в виртуалке выполни **ЭТУ** команду (она 100% рабочая):

bash

# Установи usb_modeswitch если нет
sudo apt install usb_modeswitch -y
# ВЫКЛЮЧИ карту из системы перед переключением
sudo modprobe -r mt76x2u 2>/dev/null
# ПРАВИЛЬНАЯ магическая команда (эта реально работает с 0e8d:2870)
sudo usb_modeswitch -v 0e8d -p 2870 -M "555342431234567800000000000006db000000000000000000000000000000"

После этой команды **СРАЗУ ЖЕ** (пока устройство не переподключилось) выполни:

bash

# Проверяем, переключилось ли
lsusb | grep -E "0e8d|MediaTek"

Если видишь **0e8d:7612** или **0e8d:7610** — победа на 50%. Если нет — читай дальше.

### **ШАГ 2 — Если не переключилось (альтернативный метод)**

У некоторых MT7612U другой протокол переключения. Попробуй эту команду:

bash

sudo usb_modeswitch -v 0e8d -p 2870 -R -W -M "55534243123456780000000000000011062000000100000000000000000000"

Или вариант 3 (самый агрессивный):

bash

sudo usb_modeswitch -v 0e8d -p 2870 --target-vendor 0e8d --target-product 7612 -m 0x01 -M "5553424312345678000000000000061b000000020000000000000000000000"

### **ШАГ 3 — Решение проблемы с "отваливанием" от UTM**

**ЭТО КЛЮЧЕВОЙ МОМЕНТ**, который ты упустил!

После переключения устройство **меняет свой VID/PID** с 0e8d:2870 на 0e8d:7612, и UTM теряет его, потому что он был привязан к старому ID.

**Решение:** На macOS (не в виртуалке):

bash

# Проверяем, что устройство все еще видно на хосте
system_profiler SPUSBDataType | grep -A 10 -B 5 "MediaTek"
# ОТКЛЮЧАЕМ его от хоста полностью (чтобы UTM мог захватить)
sudo killall -STOP usbd 2>/dev/null

Затем в UTM (пока виртуалка работает):

bash

# ПОДКЛЮЧАЕМ УСТРОЙСТВО ЗАНОВО по новому ID
utmctl usb connect "Linux" "0e8d:7612"

**Если не работает:** Выключи виртуалку, отключи карту USB от Mac, закрой UTM, перезапусти UTM, включи виртуалку, **только потом** вставляй карту, и сразу в виртуалке выполняй `lsusb`.

---

sudo dmesg | grep mt76  # Смотрим, подхватился ли драйвер
