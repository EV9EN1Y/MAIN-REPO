  # MASTG-TEST-0270: Ссылки на API для обнаружения изменений в биометрических данных при регистрации



Смысл теста в следующем:

 ситуация

У меня на телефоне стоит Face ID для разблокировки самого телефона

Я скачиваю приложение банка
Приложение просит мне ввести локальный пароль для доступа к самому приложению банка
После чего приложения может предложить использовать Face ID чтобы не вводить каждый раз этот пароль
Этот пароль сохраняется в кейчейн + face-id
И вот тут уже раскрывается данный тест, тем что можно выбрать два способа использовать Face ID + Keychain

1 способ - для того чтобы достать пароль из Keychain - iPhone потребует тот Face ID который использовался при установке данного пароля (система сохранит хеш его)

2 способ (небезопасный) - для получения пароля из Keychain - будет достаточно использовать Face ID точно тот же что в данный момент будет использоваться для разблокировки iPhone, что не безопасно, так как любой злоумышленник который знает код-пароль от телефона сможет установить, добавить свой Face ID в настройки телефона, потом разблокировать приложение.

Если при использовании `SecAccessControlCreateWithFlags` 
Используются атрибут `BiometryAny` - это опасно
Если используются атрибут `BiometryCurrentSet` - то это правильно и безопасно 

Правильно использовать вот такое `kSecAccessControlBiometryCurrentSet`
Если используется что-либо кроме вот этого атрибута kSecAccessControlBiometryCurrentSet - значит тест провален!

А теперь я объясняю почему так:

Если использовать kSecAccessControlBiometryCurrentSet - тогда данный Face ID разблокирует доступ только для того человека который первый раз установил этот пароль для этого банка. И даже если поменять Face ID в настройках самого телефона, то банк всё равно не получится разблокировать с другим лицом, получит разблокировать только с тем лицом кто установил это приложение и установил вот этот пароль.

То есть например если я скачал приложение банка и установил там свой Face ID с правильным флагом `kSecAccessControlBiometryCurrentSet` , тогда,  если например, моя супруга, зная пароль от телефона из четырёх цифр или шести, сможет зайти в настройки моего телефона, с помощью этого пароля, сможет сменить Face ID на свой, и несмотря на то что сам телефон будет разблокироваться теперь по её лицу, она всё равно не сможет попасть приложение моего банка, потому что там был установлен правильное настройка при установке Face ID- `kSecAccessControlBiometryCurrentSet`!!!!\
