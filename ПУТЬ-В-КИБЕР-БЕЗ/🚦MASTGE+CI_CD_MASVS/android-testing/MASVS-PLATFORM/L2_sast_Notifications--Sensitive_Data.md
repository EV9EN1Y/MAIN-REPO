# MASTG-TEST-0315: Sensitive Data Exposed via Notifications
https://mas.owasp.org/MASTG/tests/android/MASVS-PLATFORM/MASTG-TEST-0315/

не светит ли приложение чувствительными данными в уведомлениях, которые видны всем на экране блокировки или в шторке

Уведомления - это частый источник утечек. Если в них выводится текст сообщения, код подтверждения, сумма платежа или другая личная информация, её может увидеть кто угодно: через экран блокировки, при случайном взгляде на телефон или в истории уведомлений. Этот тест требует, чтобы приложение не показывало чувствительные данные в уведомлениях, либо скрывало их содержимое на заблокированном экране

-------
- **Нужно найти уведомления в коде.** искать вызовы `Notification.Builder` или `NotificationCompat.Builder` (особенно методы `setContentTitle`, `setContentText`, `setStyle`).
   
- **Проверь `AndroidManifest.xml`**:
   
    - Узнать `minSdkVersion`. Если он меньше 33, приложение может отправлять уведомления без специального разрешения. Если 33 или выше, должно быть разрешение `POST_NOTIFICATIONS`

**где формируются уведомления:**

| Файл | Метод | Назначение |
|--|--|--|
| `MeetWayMessagingService.kt` (строка 252) | `showNotification()` | Push-уведомления о новых сообщениях |
| `MeetWayMessagingService.kt` (строка 548) | `showLocalNotification()` | Локальные уведомления (когда приложение в фоне) |
| `MeetWayApp.kt` (строка 255) | `createNotificationChannels()` | Создание каналов (CHAT, SOCIAL, SYSTEM) |

**че показывается в уведомлениях:**

| Поле | Источник | Пример | Чувствительность |
|--|--|--|--|
| `setContentTitle` | Имя отправителя из FCM | `"Анна"` | Низкая – имя, ожидаемо для чата |
| `setContentText` | Текст сообщения из FCM | `"Привет, как дела?"` | **Средняя** – может содержать личные данные |
| `showLocalNotification` body | Количество сообщений | `"Новое сообщение"` | Низкая – generic текст |

**защита экрана блокировки:**

| механизм                              | Где                                  | Статус                      |
| ------------------------------------- | ------------------------------------ | --------------------------- |
| `setVisibility(VISIBILITY_PRIVATE)`   | `showNotification()` строка 261      | ✅ Включено                  |
| `setVisibility(VISIBILITY_PRIVATE)`   | `showLocalNotification()` строка 557 | ✅ Включено                  |
| `setLockscreenVisibility()` на канале | `createNotificationChannels()`       | ❌ Не задан (дефолт системы) |

`VISIBILITY_PRIVATE` означает: на экране блокировки содержимое уведомления (title + body) скрывается, показывается только "1 новое сообщение" и иконка приложения. В шторке уведомлений контент отображается полностью

**разрешения и targetSdk:**

| параметр                         | значение                            | статус                         |
| -------------------------------- | ----------------------------------- | ------------------------------ |
| `minSdkVersion`                  | 33 (Android 13)                     | ✅ Требует `POST_NOTIFICATIONS` |
| `POST_NOTIFICATIONS` в манифесте | `AndroidManifest.xml` строка 15     | ✅ Задекларировано              |
| Запрос разрешения runtime        | `MainActivity.onCreate()` строка 74 | ✅ Есть                         |

**Действия в уведомлениях:**

| Action | Тип | Описание |
|--|--|--|
| `REPLY_ACTION` | `PendingIntent` на BroadcastReceiver | Ответить на сообщение |
| `MARK_AS_READ` | `PendingIntent` на BroadcastReceiver | Отметить как прочитанное |

Оба действия не используют `RemoteInput` – ввод текста ответа не реализован в Android-уведомлениях (в отличие от iOS).

**Оценка утечки данных:**

1. **На экране блокировки:** ✅ Безопасно - `VISIBILITY_PRIVATE` скрывает title и body
2. **В шторке уведомлений:** ⚠️ Текст сообщения виден - это штатное поведение для мессенджера, ожидаемо и предсказуемо для пользователя
3. **История уведомлений:** ⚠️ Те же риски, что и в шторке - текст сообщения может храниться системой


### **Итог:  ✅✅✅  тест пройден, максимум - это текст самих смс виден в уведомлениях только при разблок экране   ✅✅✅ 



Тест пройден: приложение использует `VISIBILITY_PRIVATE` для всех уведомлений, что защищает данные на экране блокировки. Разрешения настроены корректно (minSdk 33 + POST_NOTIFICATIONS)

Единственный момент: в шторке уведомлений и в истории виден полный текст сообщения. Для мессенджера это нормальное поведение, но если в приложении есть особо чувствительные данные (платежи, коды подтверждения), стоит рассмотреть показ generic-текста ("Новое сообщение от Анны") и открытие полного текста только внутри приложения

**Рекомендации (опционально):**
- Добавить `setLockscreenVisibility()` на каналы для явного контроля (сейчас работает через `setVisibility` на уведомлении, что достаточно)
- Если требуется повышенная приватность - заменить `setContentText(body)` на `setContentText("Новое сообщение")` в `showNotification()` и добавить `setStyle(NotificationCompat.DecoratedCustomViewStyle())` для кастомной разметки
