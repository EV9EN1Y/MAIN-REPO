## Если кратко: SSL — это старая версия, TLS — это новая и безопасная

## а теперь про SSL/TLS   **транспортный**  уровень 4 osi

TLS технически находится между 4 и 5-6 уровнями. Он берёт данные с 7 уровня (твой HTTP, WebSocket), шифрует их и только потом отдаёт TCP на 4 уровень.

```js
7 . Прикладной (Application)    <- Твои API, WebSocket, HTTP
6 . Представления (Presentation) <- TLS работает здесь (шифрование)
5 . Сеансовый (Session)          <- И здесь (управление сессией)
4 . Транспортный (Transport)     <- TCP, UDP
3 . Сетевой (Network)            <- IP
2 . Канальный (Data Link)        <- Ethernet, Wi-Fi
1 . Физический (Physical)        <- Кабели, радиоволны
```

## Как именно шифрует TLS 

TLS использует **гибридную схему**, о которой я говорил здесь [[Асимметричное&Симметричное]]:

1. **Асимметричное шифрование (публичный/приватный ключ)** — только для рукопожатия. Сервер показывает сертификат с публичным ключом, клиент шифрует им Pre-master Secret 
    
2. **Симметричное шифрование (общий сессионный ключ)** — для всех данных после рукопожатия. Используются AES, ChaCha20 
    
3. **Коды аутентификации (MAC)** — чтобы никто не подменил биты в зашифрованном сообщении (помнишь атаку с 100 → 900 баксов?)

###  TLS 1.3 — это пуленепробиваемый танк""

В TLS 1.3 разработчики просто выпилили всё, что можно было взломать

- ❌ **Нет RSA для обмена ключами** — только Diffie-Hellman с прямой секретностью (PFS)
    
- ❌ **Нет сжатия** — CRIME больше не работает
    
- ❌ **Нет устаревших шифров** — RC4, DES, EXPORT пошли на свалку
    
- ❌ **Нет CBC-режимов** — только AEAD (AES-GCM, ChaCha20-Poly1305)
    
- ✅ **Forward Secrecy по умолчанию** — даже если украдут приватный ключ сервера, прошлые сессии не расшифруют


| Протокол    | Статус           | Можно ли взломать?                                     |
| ----------- | ---------------- | ------------------------------------------------------ |
| SSL 2.0/3.0 | 💀 Мёртв         | Вскрывается как консерва                               |
| TLS 1.0/1.1 | 💀 Устарел       | POODLE, BEAST, CRIME — легко                           |
| TLS 1.2     | ✅ Работает       | Безопасно, если отключить слабые шифры и старые версии |
| TLS 1.3     | 🚀 Рекомендуется | Практических атак нет, если реализация без багов       |

## вывод по взлому

TLS нельзя взломать математически (если у тебя нет квантового компьютера). Но можно:

- Заставить сервер использовать старую версию (downgrade attack)
    
- Найти баг в реализации (OpenSSL, библиотеки)
    
- Подменить сертификат (если пользователь тупой и игнорирует красный экран)
    
- Украсть приватный ключ с сервера (админ лох)

поэтому в реальном мире TLS ломают не через криптографию, а через кривые руки админов и баги в коде

#### SSL/TLS Handshake — ритуал доверия
Перед тем как начать шифровать данные, клиент и сервер должны **договориться и проверить друг друга**


### Сценарий 1: Классическое HTTPS-рукопожатие

```js
Клиент (браузер): "Привет! Я хочу открыть защищённое соединение. 
                  Понимаю TLS 1.2 и 1.3. Умею шифровать AES, ChaCha20.
                  Вот моё рандомное число (Client Random)"
                  
                  
Сервер: "Привет! Договорились, используем TLS 1.2 и AES. 
         Вот моё рандомное число (Server Random).
         А вот мой SSL-сертификат (X.509) — глянь, я настоящий!"
         
         
Клиент: (Проверяет сертификат: подпись CA, имя сайта, срок годности)
        "Всё чётко, ты настоящий сервер!
         Лови Pre-master Secret (зашифровано твоим публичным ключом)"
         
         
Оба: (Вычисляют из трёх чисел общий Session Key)

Клиент: "Всё, у меня ключ готов. Работаем! (зашифровано Session Key'ом)"

Сервер: "И у меня готово. Погнали! (тоже зашифровано)"

// Дальше все данные шифруются этим Session Key'ом
Клиент: "GET /api/data (зашифровано)"
Сервер: "{data: 123} (зашифровано)"
```

### Сценарий 2: Возобновление сессии (Session Resumption)

Если ты уже заходил на сайт недавно, можно сократить рукопожатие:


```js
Клиент: "Привет! Я тут уже был. Помнишь сессию 12345?"

Сервер: "А, помню! Давай продолжим с теми же ключами."

// Дальше сразу шифрованный обмен
```
 экономит время и ресурсы

##  Как это настраивается и где живёт

### На сервере (бэкенд)

Настройка TLS — это **конфиг веб-сервера**, а не код приложения.

**Nginx:**

```nginx
server {
    listen 443 ssl;
    server_name example.com;
    
    ssl_certificate     /etc/ssl/certs/example.com.crt;  # X.509 сертификат
    ssl_certificate_key /etc/ssl/private/example.com.key; # Приватный ключ
    
    location /api {
        proxy_pass http://backend;  # Внутри уже шифрование не нужно
    }
}
```


---

**Node.js (Express):**


```js
const https = require('https');
const fs = require('fs');
const options = {
    key: fs.readFileSync('server.key'),      // Приватный ключ
    cert: fs.readFileSync('server.crt')      // Сертификат X.509
};
https.createServer(options, app).listen(443);
```

**Важно:** Твой код внутри приложения **не знает про TLS**. 
Он просто получает уже расшифрованные данные

```nginx
app.post('/api/login', (req, res) => {
    // req.body уже расшифрован TLS-слоем
    const { username, password } = req.body;
    // Ты работаешь как обычно, TLS уже отработал внизу
});
```

### В мобильных приложениях

**iOS (App Transport Security):**


```xml
<!-- Info.plist -->
<key>NSAppTransportSecurity</key>
<dict>
    <key>NSAllowsArbitraryLoads</key>
    <false/>  <!-- Запретить HTTP, только HTTPS -->
</dict>
```

**Android (Network Security Config):**

```xml
<!-- res/xml/network_security_config.xml -->
<network-security-config>
    <domain-config cleartextTrafficPermitted="false">
        <domain includeSubdomains="true">example.com</domain>
    </domain-config>
</network-security-config>
```

### В браузере

Браузер делает всю магию автоматически:

1. При вводе `https://` — сразу начинает TLS-handshake
    
2. Проверяет сертификат по встроенному списку CA
    
3. Если сертификат просрочен или не тот — орёт красным экраном
    
4. Отображает замочек в адресной строке
    

**Как разработчик ты можешь влиять через заголовки:**

```http
HTTP/1.1 200 OK
Strict-Transport-Security: max-age=31536000; includeSubDomains

// Говорит браузеру: "Всегда используй HTTPS, даже если юзер вбил HTTP"
```

## Кому и зачем это нужно

|Кто|Зачем использует TLS|
|---|---|
|**Владелец сайта**|Чтобы браузер показывал замочек, пользователи доверяли, Google не штрафовал в выдаче|
|**Разработчик API**|Чтобы пароли, токены, номера карт не летели в открытом виде|
|**Пользователь**|Чтобы хакер в кафе не украл пароль от соцсетей|
|**Мобильное приложение**|Чтобы защитить данные пользователя и выполнить требования App Store/Google Play|
|**Интернет-магазин**|Чтобы принять оплату картой (PCI DSS требует шифрование)|
