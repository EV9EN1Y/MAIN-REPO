## MASTG-TEST-0296 - Sensitive Data Exposure Through Insecure Logging

-------

**«Чувствительные данные не должны попадать в системные логи»**

- Нужно поймать логи приложения (`idevicesyslog`, Xcode console) во время работы.
    
- Тест провален, если в логах есть пароли, токены, сессии, личные данные.


---------

###### devicesyslog - это консольная утилита для просмотра логов

`idevicesyslog` - это командная строка, которая выводит системные логи с подключенного iPhone прямо в терминал. Никакого GUI, только чистый поток событий. Она входит в набор инструментов `libimobiledevice` и работает как на macOS, так и на Linux

> это аналог `adb logcat` для Android, только для iOS

### **`<private>`** - означает , что система специально скрыла само значение, при попытке прочесть его через терминал

Вывод -  приложение постоянно читает и пишет чувствительные данные (`key_1_enter`, `kkr15`) в `UserDefaults` (через `CFPrefsPlistSource`). Это подтверждение уязвимости - данные хранятся в открытом виде в `.plist` файле, который попадает в бэкап

то есть ключи логируются, и попали в эти логи, система спрятала их, но так как ключи есть в логах - значит они вероятно и в бекап попадают: что явзяется уязвимостью!

##  находки

`kkr15` - соль для AES-шифрования

- Где: `UserDefaults` (код) + системные логи
    
 КРИТИЧНАЯ

-------

Вторая часть соли в открытом виде

- Где: структура `jkg` в коде
   
 КРИТИЧНАЯ

------------

AWS Access Key + Secret Key

- Где: хардкод в коде (`configureAWS()`)
   
 КРИТИЧНАЯ

---------

 `key_1_enter` - флаг первичного входа

- Где: логи + `UserDefaults`
   
- Критичность:  НИЗКАЯ (влияет только на отображение подсказок)

---------

####  Почему это критично

**соль AES в открытом доступе** - любой, кто извлечёт бинарник или бэкап, может расшифровать личные данные пользователей

**AWS-ключи в коде** - злоумышленник получает доступ к облачному хранилищу MeetWay с возможностью читать и записывать медиафайлы

**логирование операций с ключами** - подтверждает, что приложение постоянно обращается к чувствительным данным, увеличивая поверхность атаки

---

ПРИ считывании логов с помощью idevicesyslog:

iOS скрыла реальные значения ключей за `<private>` - система защитила данные от прямой утечки в логи. Сами имена ключей и факт их использования остались видны
