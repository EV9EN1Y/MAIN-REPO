# MASTG-TEST-0313
предотвращения кэширования текстовых полей в клавиатуре
Провожу тестирование на приложении MeetWay

-------

На ios при использовании текстовых полей, все уникальные слова, что вписываются в эти TextField поля , - сохраняются навсегда в глобальный кеш телефона! 
и чтобы защититься , нужно добавить защиту
1 - выключить автокоррекцию

```swift
TextField("Поле", text: $value)
    .autocorrectionDisabled(true)  // ← ЭТО ГЛАВНОЕ
    .textInputAutocapitalization(.never) // Отключает автокапс (опционально)
```

а для паролей, чтобы они не попадали в кеш нужно использовать:

__ в swiftUI  
```swift
SecureField("Пароль", text: $password)
    // SecureField автоматически отключает кэширование и скрывает ввод
    // Дополнительных модификаторов не требуется
```

__ в UIkit  
```swift
let passwordField = UITextField()
passwordField.isSecureTextEntry = true  // Включает режим пароля (скрывает ввод и отключает кэш)
```

для обычных полей с личными данными 
```swift
TextField("Имя", text: $name)
    .autocorrectionDisabled(true)  // ← ОТКЛЮЧАЕТ КЭШИРОВАНИЕ
```


если этого не делать, тогда слова, пароли, введенные в эти поля - попадают в глобальный кеш телефона, и тогда это уже опасно!

так как:

⭐️ Любой, кто получит физический доступ к телефону, может (при определенных условиях) извлечь этот файл
   
⭐️ При форензике (криминалистике) этот файл извлекают и анализируют, чтобы восстановить, что человек печатал 
   
⭐️ Если злоумышленник сделает бэкап твоего телефона, этот файл попадет в бэкап
   
⭐️ При джейлбрейке любой может прочитать этот файл

поэтому, в полях где вводится пароль, номер карты, личные данные, ключи  - все эти поля не должны сохранять в кеш введенный текст !

причем, по умолчанию, все они - это делают - то есть сохраняют в кеш эти данные!

#### как это тестировать

###### ⭐️ 1 SAST - просмотреть исходный код или  бинарник , проверить текстовые поля

(через xcode или radare2, или strings)

проверяем, что к чувствительным полям стоят атрибуты защиты от кеширования

###### ⭐️ 2 DAST - ручной тест 

в приложении целевом - ввожу слово несуществующее  (или через настройки сбросить кеш)
и потом захожу например в заметки я пытаюсь снова ввести данное слово, если клавиатура предлагает это слово как подсказку - то это уязвимость (если то было текст поле для пароля например)

###### ⭐️ 3 - DAST - анализ файла кэша клавиатуры (нужен джейлбрейк или доступ к файловой системе) 

```bash
# Подключиться по SSH к устройству
ssh root@<IP-адрес>

# Найти файл кэша
find /private/var/mobile/Library/Keyboard -name "*.dat"

# Скопировать на компьютер и проанализировать
scp root@<IP>:/private/var/mobile/Library/Keyboard/dynamic-text.dat ~/Desktop/

-----

ну и потом анализировать данный файл

strings dynamic-text.dat | grep -i "testpassword\|testnick"

```

###### ⭐️ 4 DAST  - через бекап

1 - вводим спец-слова в целевых текст полях приложения
2 - делаем бекап 
3 - использую ==iBackupBot== для просмотра
4 - ищу этот файл  кэша клавиатуры. В интерфейсе программы  нужно найти файл с именем, заканчивающимся на **`.dat`**, который находится в следующих папках (путь зависит от версии iOS):
   
   `Library/Keyboard/` - здесь может лежать файл `dynamic-text.dat` 
   
   `KeyboardDomain/Library/Keyboard/` - иногда системные файлы лежат в специальном домене 

   Нужно искать файлы не только по прямому пути, но и в подпапках с названиями языков, например, `en_GB-dynamic.lm` или `ru_RU-dynamic.lm`. Внутри таких папок и будет искомый `dynamic-lexicon.dat`
