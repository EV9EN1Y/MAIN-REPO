Это если доступен полностью весь исходник ios прилы

Вот чем Xcode полезен для AppSec инженера.

###### 1. ГЛОБАЛЬНЫЙ ПОИСК (Cmd+Shift+F)
   

Самая важная фишка. Ты ищешь опасные функции,  ключи, уязвимые паттерны 

Что искать:

```q
- isExcludedFromBackup (проверка бэкапов)
    
- UserDefaults.standard.set (хранение токенов в открытом виде)
    
- Keychain (используется ли вообще)
    
- URL(string: (хардкодные URL)
    
- print, NSLog, os_log (утечка данных в логи)
    
- Alamofire, URLSession (сетевые запросы)
    
- eval, UIWebView (опасные WebView)
```
   

###### 2. АНАЛИЗ СБОРОК (Build Settings)
   

Ты смотришь, включены ли защиты на уровне компиляции

Что проверять:

```q
- DEBUG vs RELEASE (не осталось ли дебаг-кода в продакшене)
    
- Optimization Level (Fastest vs No Optimization)
    
- Dead Code Stripping (удаляется ли неиспользуемый код)
    
- Symbols hidden by default (не торчат ли наружу имена функций)
```
    

###### 3. АНАЛИЗ ЗАВИСИМОСТЕЙ (Swift Package Manager / CocoaPods)
   

Ты смотришь, какие сторонние библиотеки тянет приложение, и нет ли в них известных CVE

Что проверять:
```q
- Версии библиотек (не устаревшие ли)
    
- Известные уязвимости (через SPM или отдельные инструменты)
    
- Лицензии (если важно для юристов)
    
```

###### 4. СХЕМЫ И ТАРГЕТЫ

Ты смотришь, как настроены разные сборки (Debug, Release, App Store)

Что проверять:

```q
- Отключен ли дебаг в Release (DEBUG=0)
    
- Включена ли оптимизация
    
- Не осталось ли тестовых эндпоинтов в продакшене
    
- Правильно ли настроены entitlement (Push, Keychain, App Groups)
    
```

###### 5. АНАЛИЗ КОДА ВРУЧНУЮ

Ты просто читаешь код и ищешь логические ошибки, которые не найдет никакой сканер

Что искать:
```q
- Неправильная валидация ввода (инъекции)
    
- Ошибки в аутентификации (можно ли подменить ID)
    
- Проблемы в бизнес-логике (можно ли обойти проверку)
    
```

###### 6. СТАТИЧЕСКИЙ АНАЛИЗАТОР (Xcode Built-in)
   

Xcode умеет сам находить потенциальные проблемы

```q
Как использовать:

- Product → Analyze (Cmd+Shift+B)
    
- Смотрит на утечки памяти, неиспользуемые переменные, проблемы с потоками
```
   
------






###### 7. ТЕСТЫ (XCTest)
   

можно писать автоматические тесты безопасности

Что проверять:

	- Не сохраняются ли токены в UserDefaults
	    
	- Не хардкодят ли ключи
	    
	- Правильно ли настроены entitlement
	   

Пример простого теста:  
```swift
func testNoHardcodedKeys() {  
let code = String(contentsOfFile: ...)  
XCTAssertFalse(code.contains("api_key"), "Найден хардкодный ключ")  
}
```

-------

###### 8. ИНСТРУМЕНТЫ (Instruments)
   

 смотришь, что происходит в памяти и с сетью в реальном времени

Что проверять:

```q
- Leaks (не утекают ли данные)
    
- Allocations (что выделяется в память)
    
- Network (какие запросы уходят, даже без Burp)
    
```

----

 ТИПОВОЙ ФЛОУ В XCODE (когда есть исходник)

1. Открываешь проект в Xcode
    
2. Жмешь Cmd+Shift+F и ищешь опасные паттерны (isExcludedFromBackup, UserDefaults, Keychain)
    
3. Смотришь Build Settings для Release схемы
    
4. Жмешь Product → Analyze (Cmd+Shift+B) и смотришь предупреждения
    
5. Читаешь код вручную в местах, где есть чувствительные данные
    
6. Запускаешь приложение через Instruments (Network, Leaks)
