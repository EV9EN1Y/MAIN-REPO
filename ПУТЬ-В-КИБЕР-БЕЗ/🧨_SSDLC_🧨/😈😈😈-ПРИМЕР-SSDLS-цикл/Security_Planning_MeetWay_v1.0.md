## 1. Цель и задачи этапа Planning

Цель – превратить результаты анализа (реестр рисков RSK-001..020, worst-case сценарии) в исполнимый план: роли, ресурсы, бюджет, приоритеты и график, при этом не срывая дедлайны разработки.

Задачи:
- Закрепить роли и ответственность (RACI) за митигациями.
- Определить приемлемые базовые уровни риска (risk appetite) и критерии go/no-go релиза.
- Приоритизировать митигации с учётом дедлайнов (высокорисковые – в первую очередь).
- Сформировать бюджет: инструменты, обучение, пентесты.
- Построить дорожную карту безопасности по спринтам.
- Определить метрики и порядок отчётности.

## 4. Политика рисков и приемлемые базовые уровни

### 4.1. Risk appetite

| Уровень риска | Политика |
|---|---|
| Critical | Не допускается ни в одной среде. Блокирует релиз до устранения. |
| High | Обязательно митигировать до Medium до релиза. Временные компенсирующие меры – только с одобрения Security Lead. |
| Medium | Принимается с зафиксированным планом и датой закрытия. |
| Low | Принимается, мониторится. |

### 4.2. Критерии go/no-go релиза (security release gates)

Релиз НЕ выходит, если:
- [ ] Есть открытые риски Critical или High без утверждённого плана митигации.
- [ ] SAST/SCA-скан не прогнан или содержит критичные находки.
- [ ] Секрет-скан нашёл секреты в репозитории.
- [ ] Пентест (если запланирован для этого релиза) не завершён.
- [ ] Критерии DoD (SEC-16.1) не выполнены.

### 4.3. Базовые стандарты

- OWASP ASVS Level 1 – минимум для всех функций, Level 2 – для критичных (авторизация, чаты, платежи).
- OWASP MASVS – для мобильных клиентов (V2-V8).
- OWASP Top 10 – обязательный чек-лист на каждом PR.

## 6. Бюджет безопасности

| Статья | Назначение | Оценка (ориентир) | Период |
|---|---|---|---|
| SAST (Semgrep) | Статический анализ в CI | Бесплатный open-source / коммерч. лицензия | Постоянно |
| DAST | Динамическое тестирование API | Лицензия или open-source (ZAP) | Постоянно |
| SCA + SBOM | Анализ зависимостей | Бесплатно (Dependabot) / лицензия | Постоянно |
| Секрет-скан (gitleaks) | Поиск секретов в репо | Бесплатно | Постоянно |
| MobSF | Анализ мобильных приложений | Бесплатно | Постоянно |
| Burp Suite Pro | Pen-test / ручное тестирование | Подписка | Год |
| Инструменты мобильной защиты (обфускация) | Защита клиента | Лицензия (при необходимости) | Год |
| Внешний пентест | Независимая проверка перед релизом | Разовый контракт | Перед релизом |
| WAF / CDN-защита | Защита от DDoS | Облачный сервис | Год |
| Обучение команды | Тренинги, сертификаты | Бюджет обучения | Год |
| Резерв (10-15%) | Непредвиденное | От суммы статей | – |

Оценка трудозатрат: Security Lead – 0.5 ставки на период разработки + Dev/DevOps по 10-20% на митигации.

## 7. Инструменты и интеграция в CI/CD (security gates)

### 7.1. Карта инструментов

| Инструмент | Тип | Где запускается | Порог блокировки |
|---|---|---|---|
| Semgrep (SAST) | Статический | На каждый PR | Critical/High – блок merge |
| gitleaks | Секреты | На каждый PR | Любая находка – блок merge |
| SCA (Dependabot/аналог) | Зависимости | Nightly + на PR | Critical CVE – блок merge |
| DAST (ZAP/аналог) | Динамический | Nightly + перед релизом | High+ – блок релиза |
| MobSF | Мобильный | На каждый билд приложения | High+ – блок релиза |
| SBOM-генерация | Цепочка поставок | На каждый релиз | – |

### 7.2. Пайплайн (схема)

```text
Commit -> PR:
  [SAST] -> [Секрет-скан] -> [SCA] -> Code Review -> Merge
Nightly:
  [DAST] -> [Полный SCA] -> [Отчёт в дашборд]
Релиз:
  [MobSF] -> [SBOM] -> [Пентест (если запланирован)] -> [Go/No-Go] -> Deploy
```

## 11. Коммуникация и отчётность

- Еженедельный статус безопасности: список открытых рисков, прогресс митигаций, блокеры.
- Дашборд рисков: обновляется автоматически из CI и реестра рисков.
- Эскалация: риск High/открытый > 10 дней -> Security Lead -> PM; Critical -> немедленно CTO/владельцу продукта.
- Релизный отчёт: результаты gates + пентест + остаточные риски (для go/no-go).

## 13. Риски плана и допущения

### Допущения

- Бюджет на инструменты и пентест согласован руководством.
- AppSec-ресурс выделен на 0.5 ставки на весь период разработки.
- Cloud-провайдер предоставляет необходимые сервисы (Lockbox, Security Groups, шифрование).
- Юридическое заключение по 152-ФЗ/GDPR получено до этапа Design.

### Риски плана

| Риск плана | Влияние | Митигация |
|---|---|---|
| Срыв дедлайнов из-за митигаций | Высокое | Приоритизация по DREAD + дедлайнам, компенсирующие меры |
| Нехватка AppSec-ресурса | Высокое | Аутсорс пентеста, Security Champion в команде |
| Бюджет урезан | Среднее | Фаза 3 (усиление) переносится, фундамент не трогаем |
| Инструменты не интегрируются в CI | Среднее | Выбор open-source решений (Semgrep, ZAP, gitleaks) |

## 14. Выводы и передача в Design (этап 4)

На этап 4 Design передаются:

Критерий готовности этапа: RACI утверждён, бюджет согласован, дорожная карта принята командой, все High-риски имеют владельца и дату закрытия.
