## 1. Цель и задачи этапа Deployment

Цель – развернуть систему в защищённой среде, не допустив внесения уязвимостей через конфигурацию, и обеспечить возможность быстрого отката.

Задачи:
- Выполнить релизный процесс с утверждением (go/no-go).
- Применить hardened-конфигурации окружений.
- Проверить безопасность после деплоя (post-deploy checks).
- Обеспечить откат (rollback) и мониторинг сразу после релиза.

## 2. Релизный процесс

```text
Решение go/no-go (этап 7) -> Заморозка ветки релиза -> Сборка и подпись артефактов
-> Генерация SBOM -> Сканирование образов (trivy) -> Деплой на stage -> Проверки
-> Деплой на prod (blue/green или canary) -> Post-deploy security checks -> Мониторинг
```

Контрольные точки:
- Каждый шаг выполняется по runbook'у (этап 6) и логируется.
- Деплой в prod – только по утверждённому запросу (approval от Security Lead и PM).
- Изменения конфигурации – через IaC (terraform), не вручную.

## 3. Hardening окружений (baseline)

| Область | Требование |
|---|---|
| Образы | Минимальные, без root, read-only FS (где возможно), скан trivy |
| Сеть | Security Groups: только нужные порты, БД/внутренние сервисы без публичного доступа |
| TLS | 1.3 (мин. 1.2), HSTS, корректные сертификаты |
| Заголовки | CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy (для веб-частей/админки) |
| Секреты | Только из Lockbox/CI secrets, ротация перед релизом |
| Логи | Ship в централизованное хранилище, append-only для audit |
| Время | NTP, синхронизация для корреляции логов |
| Обновления | Патчи ОС/рантайма применены до деплоя |

## 4. Безопасность артефактов и цепочки поставок

- Подпись: iOS (codesign), Android (apksigner), проверка подписи при деплое.
- SBOM: формируется на релиз, хранится с артефактом.
- Проверка целостности: хэши артефактов (SHA-256) фиксируются.
- Образы: только из проверенного registry, подпись образов (cosign, если применимо).

## 5. Управление секретами при деплое

- Перед деплоем: ротация ключей (JWT signing, ключи БД, ключи S3), если были подозрения.
- Секреты передаются в рантайм через Lockbox, никогда через env в коде/логах.
- Доступ к секретам: только сервисным аккаунтам с минимальными правами.
- Аудит доступа к секретам (кто и когда читал).

## 6. Post-deploy security checks

После деплоя в prod (в течение 30 минут):
- [ ] Все эндпоинты отвечают, TLS корректный (SSL-скан).
- [ ] DAST-прогон на прод-окружении (безопасный профиль).
- [ ] Проверка заголовков безопасности.
- [ ] Проверка доступа к БД/S3 извне (порты закрыты).
- [ ] Алерты мониторинга активны, логи пишутся.
- [ ] Метрики ошибок 4xx/5xx в норме.

## 7. Мониторинг после деплоя (watch window)

- Период усиленного наблюдения: 24-72 часа после релиза.
- Отслеживание: аномальные ошибки, всплеск неудачных логинов, rate limit срабатывания, ошибки БД.
- Дежурный: определён, эскалация по IRP.
- Откат при критичных аномалиях – по runbook отката (RTO <= 4 часа).

## 8. Откат (rollback)

- Автоматический откат: при падении health-check'ов выше порога.
- Ручной откат: при обнаружении уязвимости/аномалии (по решению Security Lead/дежурного).
- Бэкапы БД/S3 перед деплоем обязательны (RPO <= 1 час).
- После отката: анализ причины, запись в ченджлог, повторная подача на релиз после фикса.

## 9. Передача в Maintenance (этап 9)

На этап 9 Maintenance передаются:
1. Задокументированная конфигурация прод-среды (инвентарь).
2. Runbook'и (деплой, откат, инциденты, БК/DR).
3. Настроенный мониторинг и алерты.
4. SBOM и подписанные артефакты релиза.
5. Отчёт о деплое и post-deploy проверках.

## 10. Приложения

### 10.1. Релизный чек-лист безопасности

- [ ] Go/no-go решение зафиксировано (подписи Security Lead, QA, PM).
- [ ] Артефакты подписаны, SBOM сформирован.
- [ ] Образы отсканированы (0 Critical/High).
- [ ] Секреты ротированы (при необходимости), в Lockbox.
- [ ] Security Groups/IAM проверены (БД и внутренние сервисы закрыты).
- [ ] Бэкапы БД/S3 сделаны.
- [ ] Post-deploy checks запланированы/выполнены.
- [ ] Дежурный назначен, runbook отката под рукой.

### 10.2. Чеклист завершения этапа Deployment (выход на этап 9 Maintenance)

- [ ] Прод развёрнут по runbook, конфигурация задокументирована.
- [ ] Post-deploy security checks зелёные.
- [ ] Watch window завершён без критичных инцидентов.
- [ ] Мониторинг и алерты активны.
- [ ] Документация эксплуатации обновлена.
