# SSDLC (IBM) – 9 этапов: краткое содержание

Комплект шаблонов документов для MeetWay. Каждый этап = файл `.md` + `.docx` в этой папке.

---

## 1. Requirements (Требования) – `SRS_MeetWay_v1.0.md`

Собираем и фиксируем все требования, включая безопасность, с первого дня.
- Цель и рамки проекта, платформы, ограничения.
- Функциональные требования (FR): регистрация, профили, посты, чаты, поиск.
- Нефункциональные (NFR): производительность, доступность, масштабируемость.
- Требования безопасности (SEC-1..SEC-16): аутентификация, доступы, шифрование, OWASP Top 10, приватность (152-ФЗ/GDPR), мобильная безопасность.
- Критерии приёмки, приоритизация MoSCoW, риски.
- Выход: утверждённый SRS + список рисков для Analysis.

## 2. Analysis (Анализ) – `Security_Analysis_MeetWay_v1.0.md`

Оцениваем уязвимости и строим карту угроз, планируем худшие сценарии.
- Инвентаризация активов и классификация данных (PII).
- Модель угроз STRIDE по компонентам (клиент, API, БД, S3, админка, CI/CD).
- Реестр рисков (RSK-001..020): вероятность x влияние, митигации.
- DREAD-оценка топ-рисков.
- Worst-case сценарии (WC-1..WC-6) с планами реагирования.
- Анализ поставщиков и зависимостей.
- Выход: реестр рисков и приоритеты для Planning.

## 3. Planning (Планирование) – `Security_Planning_MeetWay_v1.0.md`

Назначаем роли, ресурсы, бюджет и приоритеты, не срывая дедлайны.
- Роли и ответственность (RACI-матрица).
- Политика рисков (risk appetite) и критерии go/no-go релиза.
- Приоритизация митигаций по фазам/спринтам (DREAD + дедлайны).
- Бюджет безопасности (инструменты, пентест, обучение).
- CI/CD security gates (SAST, SCA, gitleaks, DAST, MobSF, SBOM).
- Дорожная карта, KPI, подготовка IRP.
- Выход: план работ, бюджет, роли для Design.

## 4. Design (Проектирование) – `Security_Design_MeetWay_v1.0.md`

Проектируем систему так, чтобы безопасность была встроена в архитектуру.
- Архитектурные принципы: defense in depth, least privilege, fail secure.
- Диаграммы потоков данных (DFD) и trust boundaries.
- Полноценный threat modeling (STRIDE) по утверждённой архитектуре (THR-реестр).
- Криптографические решения (TLS 1.3, AES-256-GCM, argon2id, RS256).
- Дизайн API, БД (YDB), медиа (S3), мобильных клиентов, CI/CD.
- Security design review и ADR.
- Выход: архитектура + модель угроз для Development.

## 5. Development (Разработка) – `Security_Development_MeetWay_v1.0.md`

Пишем код по стандартам безопасной разработки, выявляем уязвимости сразу.
- Secure coding: валидация ввода, параметризация, экранирование, криптография.
- Защита сессий, авторизация, обработка ошибок, логирование без PII.
- Мобильная безопасность: Keychain/Keystore, обфускация, root/jailbreak-детект.
- Обязательный secure code review (чек-лист топ-10).
- Автоматизация: SAST, SCA, gitleaks на каждом PR (блокировка merge).
- Git-гигиена и Definition of Done.
- Выход: код, прошедший DoD + отчёты сканирований.

## 6. Documentation (Документация) – `Security_Documentation_MeetWay_v1.0.md`

Фиксируем архитектуру, процессы и контроли для аудитов и инцидентов.
- Архитектурная документация (DFD, модель угроз, ADR).
- Эксплуатационная (deployment/operations/incident runbook'и, план БК/DR).
- Политики: пароли, секреты, зависимости, инциденты, безопасная разработка.
- Документация по данным: карта данных, политика конфиденциальности, согласия, DSAR.
- Техническая: API-спецификация, SBOM, отчёты сканирований и пентестов.
- Выход: полный комплект документации для аудита и эксплуатации.

## 7. Testing (Тестирование) – `Security_Testing_MeetWay_v1.0.md`

Верифицируем, что все требования безопасности выполнены, до релиза.
- Стратегия: SAST, SCA, DAST, MobSF, ручное тестирование, внешний пентест.
- План верификации всех SEC-требований (Pass/Fail).
- Негативное тестирование, fuzzing, тесты бизнес-логики.
- Пентест по OWASP WSTG/MASTG до релиза + ре-тест.
- Классификация дефектов по severity с SLA.
- Критерии выхода: 0 Critical/High, отчёт согласован.
- Выход: решение go/no-go для Deployment.

## 8. Deployment (Развертывание) – `Security_Deployment_MeetWay_v1.0.md`

Разворачиваем систему в защищённой среде, без внесения уязвимостей.
- Релизный процесс с утверждением (go/no-go) и runbook'ами.
- Hardening окружений: образы, сеть, TLS, заголовки, секреты.
- Подпись артефактов, SBOM, проверка целостности.
- Post-deploy security checks (TLS, DAST, порты, алерты).
- Watch window 24-72 часа и план отката (RTO <= 4 часа).
- Выход: развёрнутая и проверенная среда для Maintenance.

## 9. Maintenance (Сопровождение) – `Security_Maintenance_MeetWay_v1.0.md`

Поддерживаем безопасность всю жизнь продукта и безопасно завершаем цикл.
- Непрерывный мониторинг CVE, аномалий, доступа к секретам.
- Patch management: Critical 7 дней, High 30, Medium 90; реакция на 0-day.
- Периодические оценки: квартальный ревью рисков, ежегодный пентест, tabletop, restore drill.
- Ротация ключей, управление доступом, бэкапы (RPO 1 ч / RTO 4 ч).
- Инциденты S1-S4, post-mortem, обновление runbook'ов.
- Безопасный вывод из эксплуатации (retirement): удаление PII, ключей, доступов.
- Выход: уроки и опыт передаются в новый цикл SSDLC.
