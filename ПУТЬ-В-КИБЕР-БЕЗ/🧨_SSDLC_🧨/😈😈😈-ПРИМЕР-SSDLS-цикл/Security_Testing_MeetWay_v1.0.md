## 1. Цель и задачи этапа Testing

Цель – верифицировать, что все требования безопасности (SEC-1..SEC-16) выполнены и риски (RSK/THR) митигированы, до выхода в прод.

Задачи:
- Провести автоматическое и ручное тестирование безопасности.
- Выполнить пентест (внешний) перед релизом.
- Свести результаты к go/no-go решению.

## 2. Стратегия тестирования (уровни)

| Уровень | Инструмент | Запуск | Покрывает |
|---|---|---|---|
| SAST | Semgrep | Каждый PR + nightly | Код: инъекции, XSS, секреты |
| SCA | Dependabot/аналог | Каждый PR + nightly | Зависимости: CVE |
| Секрет-скан | gitleaks | Каждый PR | Секреты в репозитории |
| DAST | ZAP / Burp | Nightly + перед релизом | API: OWASP Top 10 |
| IAST (опционально) | Инструмент в рантайме | Тест-стенд | Точные векторы в рантайме |
| Мобильный анализ | MobSF + Frida | Каждый билд | MASVS V2-V8 |
| Ручное тестирование | Burp, Frida, Wireshark | Функциональные security-тесты | Бизнес-логика, IDOR, обходы |
| Пентест (внешний) | По методологии OWASP WSTG/MASTG | Перед релизом | Независимая проверка |

## 3. План верификации SEC-требований

| SEC | Требование | Метод верификации | Инструмент |
|---|---|---|---|
| SEC-1 | Аутентификация, MFA, rate limit | Функциональные + негативные тесты | Burp, ручные тесты |
| SEC-2 | JWT, ротация, хранение токенов | Тесты сессий, анализ клиента | Burp, MobSF |
| SEC-3 | RBAC, IDOR, presigned URL | Негативные тесты доступа | Burp, ручные |
| SEC-4 | TLS, шифрование at rest | Проверка конфигурации, SSL-скан | SSL Labs, аудит |
| SEC-5 | Валидация ввода, OWASP Top 10 | DAST + ручные тесты | ZAP, Burp |
| SEC-6 | Rate limit API, WebSocket | Нагрузочные + функциональные | Locust, Burp |
| SEC-7 | Пароли (argon2id) | Код-ревью, проверка БД | Semgrep, аудит |
| SEC-8 | Приватность, удаление данных | Функциональные тесты DSAR | Ручные |
| SEC-9 | Мобильная безопасность | MobSF + Frida-тесты | MobSF, Frida |
| SEC-10 | Инфраструктура, секреты | Аудит конфигурации | gitleaks, облачные проверки |

## 4. Виды тестов

### 4.1. Функциональные security-тесты

Позитивные и негативные сценарии по каждой SEC-группе (например: логин с неверным паролем 6 раз -> блокировка; доступ к чужому посту -> 403; загрузка файла с подменённым расширением -> отклонение).

### 4.2. Негативное тестирование и fuzzing

- Fuzzing API: случайные/мутированные входные данные (ZAP fuzzer, Burp Intruder).
- Некорректные типы, длины, кодировки, спецсимволы.
- Тестирование граничных значений (лимиты, пагинация).

### 4.3. Тестирование бизнес-логики

- Обход лимитов (rate limit через смену IP/заголовков).
- Многошаговые сценарии (регистрация -> верификация -> привилегии).
- Повторная отправка (replay), параллельные запросы (race conditions).

### 4.4. Пентест (внешний)

| Параметр | Значение |
|---|---|
| Методология | OWASP WSTG (web/API), OWASP MASTG (mobile) |
| Scope | API /v1/*, мобильные клиенты, админка |
| Вне scope | DoS-атаки, социальная инженерия, физический доступ |
| Окно | За 2 недели до релиза |
| Отчёт | Находки с severity, PoC, рекомендации |
| Ре-тест | После исправлений, до go/no-go |

## 5. Классификация дефектов

| Severity | Определение | SLA на фикс |
|---|---|---|
| Critical | RCE, полная утечка БД, обход аутентификации | Немедленно, блокирует релиз |
| High | IDOR, XSS, утечка PII, эскалация прав | <= 5 рабочих дней |
| Medium | Слабые настройки, информационные утечки | <= 15 рабочих дней |
| Low | Косметика, рекомендации | По плану |

## 6. Критерии выхода (exit criteria)

Тестирование завершено, когда:
- [ ] 100% SEC-требований верифицировано (Pass/Fail зафиксирован).
- [ ] 0 открытых Critical/High дефектов.
- [ ] Пентест завершён, все High исправлены и ре-тест пройден.
- [ ] SAST/SCA/DAST зелёные на релизном билде.
- [ ] Отчёт сформирован и согласован (Security Lead + PM).

## 7. Отчётность

- Дашборд: количество дефектов по severity, статус исправлений, покрытие SEC.
- Отчёт по каждому релизу: результаты всех уровней + пентест + остаточные риски.
- Метрики: % SEC-требований Pass, MTTR дефектов, найденные до/после релиза.

## 8. Передача в Deployment (этап 8)

На этап 8 Deployment передаются:
1. Решение go/no-go с подписями (Security Lead, QA, PM).
2. Отчёт пентеста и список остаточных рисков.
3. Релизный чек-лист (критерии go/no-go из этапа 3, раздел 4.2).
4. SBOM и подписанные артефакты.
