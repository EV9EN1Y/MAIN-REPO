# Threat Modeling – моделирование угроз

> Полное руководство: см. остальные файлы в папке SDLC


**Threat Modeling** – это структурированный процесс выявления, документирования и анализа потенциальных угроз для системы, а также определения мер по их снижению (mitigations).

**Определение (OWASP):** threat model – это структурированное представление всей информации, которая влияет на безопасность приложения. По сути, это взгляд на приложение и его окружение через призму безопасности.
> **OWASP** – Open Web Application Security Project (открытый проект безопасности веб-приложений)


**Типичная модель угроз включает:**
- Описание объекта моделирования (система, приложение)
- Допущения (assumptions), которые можно проверить в будущем
- Потенциальные угрозы для системы
- Действия по снижению каждой угрозы
- Способ валидации модели и проверки результата

**Когда проводить:** в идеале – на этапе дизайна (концепции/планирования) и далее непрерывно, уточняя по мере добавления деталей. Каждое крупное архитектурное изменение – повод обновить модель угроз.

**Процесс threat modeling (5 шагов):**
1. **Определить границы** – что входит в систему, а что нет
2. **Построить DFD** – диаграмму потоков данных (см. раздел 6)
3. **Определить угрозы** – применить методологию (STRIDE, LINDDUN и др.)
4. **Оценить риски** – приоритизировать (DREAD, CVSS, риск-матрица)
5. **Определить контрмеры** – что делаем с каждой угрозой: устраняем, снижаем, принимаем, переносим
> **LINDDUN** – Linkability, Identifiability, Non-repudiation, Detectability, Disclosure of information, Unawareness, Non-compliance (связываемость, идентифицируемость, неотказуемость, обнаруживаемость, раскрытие информации, неосведомлённость, несоответствие)

> **DREAD** – Damage, Reproducibility, Exploitability, Affected users, Discoverability (ущерб, воспроизводимость, эксплуатируемость, затронутые пользователи, обнаруживаемость)

> **STRIDE** – Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege (подмена, вмешательство, отказ, раскрытие информации, отказ в обслуживании, повышение привилегий)

> **DFD** – Data Flow Diagram (диаграмма потоков данных)

> **CVSS** – Common Vulnerability Scoring System (общая система оценки критичности уязвимостей (0-10))


**Инструменты threat modeling:**
- **Microsoft Threat Modeling Tool** – бесплатный, поддерживает STRIDE, рисует DFD
- **OWASP Threat Dragon** – бесплатный, open-source, веб/desktop
- **IriusRisk** – коммерческий, автоматизация
- **Threatspec / pytm** – threat modeling as code
- **Devici / Security Compass** – коммерческие

**Manifesto моделирования угроз (2020)** – набор ценностей и принципов практики, написанный сообществом практиков. Ключевые ценности: моделирование угроз должно быть командной культурой, а не разовой активностью.

## 📎 Пример: настоящий документ моделирования угроз (шаблон)

> Документ: `Threat_Model_MeetWay.md` – модель угроз социальной сети
> Это шаблон того, как выглядит реальный артефакт threat modeling в компании.

```markdown
# Модель угроз: социальная сеть "MeetWay"

Версия: 1.1 | Дата: 31.07.2026 | Автор: AppSec-инженер
Статус: утверждена | Обновлять: при каждом изменении архитектуры

## 1. Объект моделирования
- Мобильное приложение (iOS/Android) + REST API + БД (YDB)
- Функции: регистрация, профили, посты, чаты, поиск людей
- Технологии: Swift/Kotlin, FastAPI, Yandex Cloud, PostgreSQL/YDB

## 2. Границы системы (trust boundaries)
- Граница 1: Клиент (мобильное приложение) <-> Интернет
- Граница 2: Интернет <-> API Gateway (TLS termination)
- Граница 3: API Gateway <-> Бэкенд-сервисы (внутренняя сеть)
- Граница 4: Бэкенд <-> БД (внутренняя сеть, изолирована)
- Граница 5: Бэкенд <-> Внешние сервисы (SMS, push, storage)

## 3. Активы
| Актив | Критичность | Где находится |
|-------|-------------|---------------|
| ПДн пользователей (ФИО, телефон, email) | Высокая | БД |
| Сообщения чатов | Высокая | БД, в полёте |
| Пароли (хэши) | Критическая | БД |
| JWT-ключ подписи | Критическая | KMS/секреты |
| Фото пользователей | Средняя | Object Storage |
| Данные для аналитики | Низкая | Логи |

## 4. Допущения
- Внутренняя сеть между сервисами доверенная (сегментация настроена)
- Админы БД проходят MFA и аудит
- Мобильное приложение может быть взломано (root/jailbreak) - не доверяем клиенту

## 5. Угрозы (STRIDE по каждому элементу)

### 5.1 Мобильное приложение (клиент)
| # | Категория | Угроза | Риск | Контрмеры |
|---|-----------|--------|------|-----------|
| T1 | Spoofing | Подмена пользователя чужим JWT | Высокий | Валидация подписи JWT, короткий TTL |
| T2 | Tampering | Изменение запросов (реверс, Frida) | Высокий | Не доверять клиенту, валидация на сервере |
| T3 | Info Disclosure | Извлечение ключей/токенов из приложения | Средний | Ключи в Keychain/Keystore, обфускация |
| T4 | Tampering | Подмена трафика (MITM, нет pinning) | Высокий | TLS + certificate pinning |

### 5.2 API Gateway
| # | Категория | Угроза | Риск | Контрмеры |
|---|-----------|--------|------|-----------|
| T5 | DoS | DDoS на API | Высокий | WAF, rate limiting, балансировка |
| T6 | Spoofing | Брутфорс логина | Высокий | Rate limiting, капча, блокировка |
| T7 | Info Disclosure | Раскрытие структуры API (ошибки) | Низкий | Общие сообщения об ошибках |

### 5.3 Бэкенд-сервисы
| # | Категория | Угроза | Риск | Контрмеры |
|---|-----------|--------|------|-----------|
| T8 | Elevation | IDOR: доступ к чужим данным по id | Критический | Проверка прав на каждый запрос |
| T9 | Injection | SQL-инъекции в поиске | Критический | Параметризованные запросы, ORM |
| T10 | Injection | XSS в постах/комментариях | Высокий | Экранирование, CSP |
| T11 | Info Disclosure | Утечка ПДн через API | Критический | Контроль доступа, маскирование |
| T12 | Repudiation | Отказ от действий (перевод, пост) | Средний | Аудит-логи, неизменяемость |

### 5.4 База данных
| # | Категория | Угроза | Риск | Контрмеры |
|---|-----------|--------|------|-----------|
| T13 | Tampering | Изменение данных (взлом БД) | Критический | Шифрование at-rest, ограничение доступа |
| T14 | Info Disclosure | Утечка дампа БД | Критический | Шифрование, минимизация данных |
| T15 | DoS | Исчерпание ресурсов БД | Средний | Лимиты, пулы соединений |

### 5.5 Внешние сервисы (SMS, push)
| # | Категория | Угроза | Риск | Контрмеры |
|---|-----------|--------|------|-----------|
| T16 | Spoofing | Перехват SMS-кода (SIM swap) | Средний | MFA-приложение, алерты |
| T17 | Tampering | Подмена push-уведомлений | Низкий | Подпись push, HTTPS |

## 6. Приоритизация (риск-матрица)
| Уровень | Кол-во угроз | Действие |
|---------|--------------|----------|
| Критический (T8, T9, T11, T13, T14) | 5 | Устранить ДО релиза, неделя |
| Высокий (T1, T2, T4, T5, T6, T10, T16) | 7 | Устранить до релиза или компенсировать |
| Средний (T3, T12, T15, T17) | 4 | Запланировать, задокументировать |

## 7. Остаточные риски (принятые)
- T3 (извлечение ключей из клиента): принят, компенсируется серверной валидацией
- T15 (исчерпание БД): принят, мониторинг + автоскейлинг

## 8. Верификация
- [ ] Контрмеры T1-T17 реализованы (ссылки на задачи)
- [ ] Пентест подтвердил отсутствие T8-T10
- [ ] Модель обновлена после внедрения чата v2
```

## 📎 Пример: таблица угроз в Excel-стиле (краткий формат для трекера)

```markdown
| ID | Элемент | Угроза (STRIDE) | Вероятность | Влияние | Риск | Контрмера | Статус |
|----|---------|-----------------|-------------|---------|------|-----------|--------|
| T1 | API     | Spoofing (подделка JWT) | 3 | 5 | 15 | Валидация подписи | ✅ |
| T2 | API     | Tampering (изменение данных) | 2 | 5 | 10 | Подпись/целостность | ✅ |
| T3 | БД      | Info Disclosure (утечка) | 2 | 5 | 10 | Шифрование at-rest | 🔄 |
| T4 | Web     | XSS (инъекция скриптов) | 3 | 4 | 12 | Экранирование, CSP | ✅ |
| T5 | API     | DoS (перегрузка) | 4 | 3 | 12 | Rate limiting | 🔄 |
| T6 | Auth    | Elevation (IDOR) | 3 | 5 | 15 | Проверка прав | ✅ |

# Шкала: Вероятность/Влияние 1-5. Риск = В x Вл. > 12 = высокий.
```
