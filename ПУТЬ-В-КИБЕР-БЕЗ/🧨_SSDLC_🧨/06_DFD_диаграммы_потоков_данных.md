# DFD – диаграммы потоков данных

> Полное руководство: см. остальные файлы в папке SDLC


**DFD (Data Flow Diagram)** – диаграмма потоков данных. Графическое представление того, как данные движутся через систему: кто их создаёт, обрабатывает, хранит и потребляет.
> **DFD** – Data Flow Diagram (диаграмма потоков данных)


**Основные элементы DFD (нотация Yourdon/De Marco или Gane-Sarson):**

| Элемент | Символ | Описание |
|---------|--------|----------|
| **Внешняя сущность (External Entity)** | прямоугольник | Пользователь, внешняя система, сервис. Вне границ системы |
| **Процесс (Process)** | окружность/овал | Преобразует данные, выполняет логику |
| **Хранилище данных (Data Store)** | две параллельные линии | БД, файл, кэш, очередь |
| **Поток данных (Data Flow)** | стрелка | Движение данных между элементами |
| **Граница доверия (Trust Boundary)** | пунктирная линия | Граница, через которую данные переходят из доверенной зоны в недоверенную |

**Зачем DFD для безопасности:**
- Показывает **границы доверия** – места, где нужно проверять данные (это ключ к threat modeling)
- Показывает **хранилища данных** – что нужно шифровать и защищать
- Показывает **внешние входы** – поверхности атаки
- Помогает команде говорить на одном языке об архитектуре

**Пример простого DFD (банковское приложение):**
```
[Пользователь] --(HTTP)--> [Web-сервер] --(SQL)--> [БД пользователей]
      |                        |
      |                    (Trust Boundary: интернет -> DMZ)
      |                        |
      +--(HTTPS)--> [API Gateway] --(внутр. сеть)--> [Сервис платежей] --> [БД транзакций]
```

**Как строить DFD:**
1. Начать с контекстной диаграммы (вся система как один процесс + внешние сущности)
2. Детализировать до уровня 1: основные процессы, хранилища, потоки
3. Отметить границы доверия (trust boundaries)
4. Каждый элемент DFD затем анализируется на угрозы (например, через STRIDE)
> **STRIDE** – Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege (подмена, вмешательство, отказ, раскрытие информации, отказ в обслуживании, повышение привилегий)

## 📎 Пример: DFD-диаграмма социальной сети (SVG-схема)

> Схема создана кодом и лежит в папке: `06_DFD_схемы/DFD_MeetWay_соцсеть.svg`
> Открой её в браузере или Obsidian (вложение), чтобы увидеть картинку.

**Что изображено на схеме (соцсеть MeetWay):**

```
[Пользователь] --> [Мобильное приложение] --> [API Gateway] --> [Сервисы]
                     (устройство)             (TLS, auth)        |    |    |
                                                                 v    v    v
                                                          [Auth] [Post] [Chat] [Search]
                                                            |      |      |      |
                                                            v      v      v      v
                                                          [БД Users] [БД Posts] [БД Chats] [Redis]
```

**Элементы DFD на схеме:**
| Элемент | На схеме | Описание |
|---------|----------|----------|
| Внешняя сущность | Пользователь, SMS/Push, Object Storage | За границами системы |
| Процесс | Приложение, API Gateway, Auth/Post/Chat/Search | Обработка данных |
| Хранилище | БД Users/Posts/Chats, Redis | Где данные лежат |
| Граница доверия | Пунктирные линии | Устройство и внутренняя сеть |

**Ключевые потоки данных:**
1. **Авторизация:** Пользователь → Приложение → Gateway → Auth Service → БД Users (проверка пароля, выдача JWT)
2. **Посты:** Пользователь → Приложение → Gateway → Post Service → БД Posts + Object Storage (фото)
3. **Чат:** Пользователь → Приложение → Gateway → Chat Service → БД Chats → push-уведомление получателю
4. **Поиск:** Пользователь → Приложение → Gateway → Search Service → БД Users (индекс) + Redis (кэш)

**Где границы доверия (trust boundaries) – ключ для threat modeling:**
- **Граница 1:** устройство пользователя (может быть скомпрометировано) → не доверяем клиенту
- **Граница 2:** интернет → API Gateway (внешняя поверхность атаки)
- **Граница 3:** Gateway → сервисы (внутренняя сеть, доверенная)
- **Граница 4:** сервисы → БД (изолированная сеть)

**Как читать для угроз (STRIDE):**
- Через границу 1 (устройство) → угрозы Spoofing (подделка JWT), Tampering (подмена запросов)
- Через границу 2 (интернет) → DoS, брутфорс, инъекции
- Между процессами → Information Disclosure (утечка между сервисами)
- К хранилищам → Tampering (изменение данных), Info Disclosure (утечка БД)

## 📎 Пример: как строить DFD пошагово (мини-гайд)

1. **Контекстная диаграмма:** вся система = 1 процесс, вокруг внешние сущности
2. **Уровень 0:** основные процессы (Auth, Posts, Chat, Search)
3. **Уровень 1:** детализация каждого процесса + хранилища
4. **Отметить границы доверия** (пунктиром)
5. **Проверить:** каждый поток данных имеет начало и конец, нет "висячих" стрелок
6. **Прогнать STRIDE** по каждому элементу и потоку

**Инструменты для рисования DFD:**
- draw.io (diagrams.net) – бесплатно, шаблоны
- Microsoft Threat Modeling Tool – DFD + STRIDE автоматически
- OWASP Threat Dragon – бесплатно, open-source
- PlantUML / Mermaid – DFD кодом (можно в git)
