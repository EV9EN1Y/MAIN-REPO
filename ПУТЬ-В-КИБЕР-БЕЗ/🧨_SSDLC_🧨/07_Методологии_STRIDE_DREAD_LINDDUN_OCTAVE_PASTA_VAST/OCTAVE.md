# OCTAVE – организационная оценка рисков (CERT/SEI)

> Отдельный файл методологии · часть 🧨_SDLC_🧨/07_Методологии

**OCTAVE (Operationally Critical Threat, Asset, and Vulnerability Evaluation)** – методология оценки рисков на уровне ОРГАНИЗАЦИИ, разработана CERT/SEI (Carnegie Mellon University). В отличие от STRIDE (фокус на приложении), OCTAVE оценивает риски бизнеса и инфраструктуры целиком.

## Варианты

| Вариант | Для кого | Особенность |
|---------|----------|-------------|
| OCTAVE | Крупные организации | Полный процесс, 3 фазы |
| OCTAVE-S | Малые организации | Упрощённый, меньше ресурсов |
| OCTAVE-Allegro | Все | Ориентация на активы и риски, быстрый старт |

## Три фазы OCTAVE (классическая)

### Фаза 1: Построение профилей активов
- Определить критичные активы организации
- Оценить их важность (критичность для бизнеса)
- Определить требования безопасности к каждому активу

### Фаза 2: Идентификация уязвимостей инфраструктуры
- Проанализировать ключевые компоненты (сеть, серверы, приложения)
- Найти слабые места (уязвимости, конфигурации)
- Оценить, как уязвимости влияют на активы

### Фаза 3: Разработка плана безопасности
- Оценить риски (вероятность x влияние)
- Определить стратегии: снизить, устранить, принять, перенести
- Составить план мероприятий с приоритетами

## Пример: профиль актива

```markdown
## Актив: БД клиентов (ПДн)

Важность: Критическая (10/10)
Требования безопасности:
- Конфиденциальность: доступ только авторизованным сервисам
- Целостность: изменения только через API
- Доступность: 99.9%

Угрозы:
- Утечка через инсайдера (вероятность: средняя, влияние: катастрофическое)
- Компрометация через уязвимость приложения (высокая, критическое)
- Физическая кража сервера (низкая, высокое)

Уязвимости инфраструктуры:
- Доступ DBA без MFA
- Отсутствие шифрования бэкапов
- Слабые пароли сервисных учёток

План:
1. MFA для всех админов БД (2 недели)
2. Шифрование бэкапов (1 месяц)
3. Ротация сервисных паролей (1 неделя)
```

## Отличие от STRIDE

| | STRIDE | OCTAVE |
|--|--------|--------|
| Уровень | Приложение/компонент | Организация |
| Фокус | Угрозы системе | Активы и риски бизнеса |
| Результат | Список угроз + контрмеры | План безопасности организации |
| Кто проводит | Разработчики + AppSec | Руководство + ИБ |

**Когда применять:** стратегическое планирование ИБ, аудит, построение СУИБ (ISO 27001), оценка рисков для руководства.
