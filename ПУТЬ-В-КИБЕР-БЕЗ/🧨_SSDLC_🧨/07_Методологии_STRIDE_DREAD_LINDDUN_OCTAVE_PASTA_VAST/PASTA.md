# PASTA – Process for Attack Simulation and Threat Analysis

> Отдельный файл методологии · часть 🧨_SDLC_🧨/07_Методологии

**PASTA** – атак-центричная методология моделирования угроз (attack-centric). Связывает бизнес-цели с техническими угрозами и использует реальные данные об уязвимостях (CVE). Разработана Tony UcedaVelez.

## 7 ступеней PASTA

### Ступень 1: Определение целей (business objectives)
- Определить бизнес-цели системы
- Определить требования соответствия (ФЗ-152, PCI DSS)
- Определить KPI безопасности

### Ступень 2: Определение технического скоупа
- Технологии, архитектура, интеграции
- Границы системы
- Технический стек

### Ступень 3: Декомпозиция приложения
- Построить DFD
- Отметить trust boundaries
- Определить компоненты и данные

### Ступень 4: Анализ угроз
- Классификация угроз (STRIDE-подобная)
- Сопоставление угроз с элементами DFD
- Сценарии атак

### Ступень 5: Анализ уязвимостей
- Сопоставление с CVE/CWE (реальные уязвимости)
- Анализ зависимостей (SCA)
- Анализ кода (SAST)
- Анализ конфигурации

### Ступень 6: Анализ атак (моделирование)
- Построение деревьев атак (attack trees)
- Сценарии: "атакующий X хочет достичь Y через Z"
- Оценка вероятности успеха

### Ступень 7: Анализ рисков и контрмер
- Оценка риска (вероятность x влияние)
- Приоритизация контрмер
- План внедрения

## Пример: дерево атаки (ступень 6)

```text
Цель: получить доступ к аккаунту администратора
├── 1. Подобрать пароль (брутфорс)
│   ├── 1.1 Слабый пароль
│   └── 1.2 Нет rate limiting
├── 2. Перехватить сессию
│   ├── 2.1 XSS (украсть cookie)
│   └── 2.2 Нет HttpOnly cookie
├── 3. Сбросить пароль
│   ├── 3.1 Ответы на секретные вопросы угадываемы
│   └── 3.2 Ссылка сброса не одноразовая
├── 4. Эксплуатировать уязвимость
│   └── 4.1 CVE в админ-панели (например, CVE-2024-XXXX)
└── 5. Социальная инженерия
    └── 5.1 Фишинг на админа
```

Для каждой ветки - контрмера: rate limiting, MFA, HttpOnly, одноразовые ссылки, патчи.
