# Шпаргалка: из MASVS/MASTG в требования безопасности

Версия: 1.0 | Дата: 04.08.2026 | Назначение: быстрый сбор требований безопасности для любого мобильного проекта

> Логика: тип проекта → уровень защиты (MASVS L1/L2/R) → категории → тест-кейсы MASTG → готовые формулировки требований → критерии приёмки.

---

## 1. Как пользоваться (3 шага)

1. **Определи тип проекта** и уровень защиты (раздел 2).
2. **Пройди по категориям V1-V8** (разделы 4-8), выбери релевантные тесты, вычеркни нерелевантное.
3. **Преврати тест в требование**: скопируй готовую формулировку из колонки «Требование», добавь критерий приёмки, присвой ID (SEC-X.X).

## 2. Уровни MASVS – кому что брать

| Уровень | Кому подходит | Примеры | Объём |
|---|---|---|---|
| **L1** (базовый) | Всем приложениям без исключения | Утилита, фонарик, игра | Обязательный минимум |
| **L2** (чувствительные данные) | Приложения с PII, деньгами, приватным контентом | Соцсеть, мессенджер, банк, health | L1 + усиление |
| **R** (устойчивость к реверсу) | Высокий риск реверса/тампера, анти-фрод | Банки, DRM, платные сервисы | L2 + защита от реверса |

Правило: **L1 – обязателен всем. L2 – если работаешь с PII/деньгами. R – если защищаешься от взлома клиента.**

## 3. Категории MASVS (v2) – обзор

| ID  | Категория                                     | О чём                                |
| --- | --------------------------------------------- | ------------------------------------ |
| V1  | Архитектура, угрозы, дизайн (MASVS-ARCH)      | Threat modeling, secure by design    |
| V2  | Хранение данных и приватность (MASVS-STORAGE) | Где лежат данные, секреты, бэкапы    |
| V3  | Криптография (MASVS-CRYPTO)                   | Алгоритмы, ключи, параметры          |
| V4  | Аутентификация и сессии (MASVS-AUTH)          | Вход, MFA, биометрия, rate limit     |
| V5  | Сеть (MASVS-NETWORK)                          | TLS, pinning, MITM                   |
| V6  | Платформа (MASVS-PLATFORM)                    | WebView, IPC, десериализация         |
| V7  | Качество кода (MASVS-CODE)                    | Ошибки, память, подпись, зависимости |
| V8  | Устойчивость к реверсу (MASVS-RESILIENCE)     | Обфускация, root/jailbreak, отладка  |

## 4. V2. Хранение данных и приватность (STORAGE)

| Тест MASTG | Уровень | Готовое требование | Критерий приёмки |
|---|---|---|---|
| MASVS-STORAGE-1: безопасное хранилище | L1 | Чувствительные данные (токены, ключи, пароли) хранить только в Keychain (iOS) / Keystore+EncryptedSharedPreferences (Android) | MobSF + Frida: секретов нет в UserDefaults/SharedPreferences, файлах, БД |
| MASVS-STORAGE-2: бэкапы | L2 | Запрет попадания чувствительных данных в облачные бэкапы (iCloud/Google Drive) | Проверка бэкапа устройства: нет токенов/ключей |
| MASVS-STORAGE-3: минимальная поверхность | L2 | Не хранить чувствительные данные дольше необходимости (минимизация) | Аудит данных: нет лишних PII на устройстве |
| MASVS-STORAGE-4: скриншоты/кэш | L2 | Запрет попадания чувствительных данных в кэш, скриншоты, кэш клавиатуры (snapshot-защита, `FLAG_SECURE`) | Скриншот экрана с данными пустой/заблокирован |
| MASVS-STORAGE-5: приватность ввода | L2 | Отключить автоподстановку/кэширование ввода для чувствительных полей; защита clipboard | Ввод пароля/кода не остаётся в кэше и буфере |
| MASVS-STORAGE-6: секреты в коде | L1 | Запрет секретов (API-ключи, пароли) в исходниках и конфигах приложения | gitleaks + grep по репозиторию: 0 находок |

## 5. V3. Криптография (CRYPTO)

| Тест MASTG | Уровень | Готовое требование | Критерий приёмки |
|---|---|---|---|
| MASVS-CRYPTO-1: стандартная криптография | L1 | Использовать только проверенные стандартные алгоритмы (AES-256-GCM, RSA/ECDSA, SHA-256+); запрет самописной криптографии | Код-ревью, Semgrep-правила |
| MASVS-CRYPTO-2: параметры | L1 | Корректные параметры: режим GCM (не ECB), ключи >= 128 бит, безопасные протоколы (TLS 1.2+) | Аудит криптопараметров, SAST |
| MASVS-CRYPTO-3: защита ключей | L2 | Ключи шифрования хранить в Keystore/Keychain, не в коде и не в SharedPreferences | Frida/MobSF: ключ не извлекается |
| MASVS-CRYPTO-4: криптография против реверса | R | Белый ящик/обфускация криптографических операций | Реверс-тест: ключи не находятся статически |

## 6. V4. Аутентификация и сессии (AUTH)

| Тест MASTG | Уровень | Готовое требование | Критерий приёмки |
|---|---|---|---|
| MASVS-AUTH-1: локальная/удалённая аутентификация | L1 | Критичные операции (вход, платежи) аутентифицировать на сервере, не на клиенте | Обход клиентской проверки невозможен |
| MASVS-AUTH-2: устойчивость к брутфорсу | L1 | Rate limit на попытки входа/PIN: не более 5 попыток за 15 минут, блокировка + CAPTCHA | 6-я попытка блокируется |
| MASVS-AUTH-3: смена PIN/пароля | L2 | Возможность смены PIN/пароля/биометрии; принудительная смена при компрометации | Сценарий смены работает, старый пароль не принимается |
| MASVS-AUTH-4: сессии | L1 | Серверные сессии: TTL, инвалидация при logout, отзыв токенов | Старый токен после logout даёт 401 |
| MASVS-AUTH-5: MFA | L2 | Поддержка MFA (TOTP/SMS); обязательна для админов | Вход без OTP отклоняется |
| MASVS-AUTH-6: биометрия | L2 | Биометрия как удобство, НЕ замена пароля; fallback на пароль | Проверка сценариев биометрии |
| MASVS-AUTH-7: блокировка экрана | L2 | Автоблокировка и повторная аутентификация после простоя | Тест: после N минут простоя требуется повторный вход |
| MASVS-AUTH-8: повторная аутентификация | L2 | Повторный ввод пароля/PIN для чувствительных операций (платёж, смена email) | Тест чувствительной операции |
| MASVS-AUTH-9: общий доступ к аккаунту | L2 | Детект/ограничение использования одного аккаунта на многих устройствах | Тест мультиустройств |

## 7. V5. Сеть (NETWORK)

| Тест MASTG | Уровень | Готовое требование | Критерий приёмки |
|---|---|---|---|
| MASVS-NETWORK-1: TLS | L1 | Весь трафик по TLS; запрет cleartext (ATS / network security config) | mitmproxy не видит plaintext |
| MASVS-NETWORK-2: версии TLS | L1 | Только TLS 1.2+ с сильными шифрами; запрет SSL/TLS 1.0-1.1 | SSL Labs: A+ |
| MASVS-NETWORK-3: проверка сертификата | L1 | Проверка цепочки доверия на клиенте; pinning для критичных доменов | Подмена сертификата блокируется |
| MASVS-NETWORK-4: безопасный handshake | L2 | Отдельные профили соединения для чувствительных операций, нет fallback на небезопасное | Тест downgrade-атак |
| MASVS-NETWORK-5: MITM-предупреждение | L2 | Предупреждать пользователя о недоверенном сертификате (не молча продолжать) | Тест с перехватом |

## 8. V6. Платформа (PLATFORM)

| Тест MASTG | Уровень | Готовое требование | Критерий приёмки |
|---|---|---|---|
| MASVS-PLATFORM-1: безопасные API платформы | L1 | Использовать платформенные API безопасно (безопасные интенты, без опасных permissions) | Код-ревью, SAST |
| MASVS-PLATFORM-2: IPC | L2 | Защита межпроцессного взаимодействия: проверка отправителя, запрет небезопасных компонентов | Тест intent'ов |
| MASVS-PLATFORM-3: WebView | L2 | WebView: запрет `file://` доступа и JS для недоверенных URL | Тест WebView-сценариев |
| MASVS-PLATFORM-4: JS-мосты WebView | L2 | Валидация входных данных JS-мостов, минимум интерфейса | Тест моста |
| MASVS-PLATFORM-5: десериализация | L2 | Запрет десериализации недоверенных данных (безопасные форматы: JSON + schema) | SAST, тесты |
| MASVS-PLATFORM-6: поверхность атаки | L2 | Отключить ненужные фичи (экспортируемые компоненты, отладка, бэкап данных) | Проверка манифеста/plist |

## 9. V7. Качество кода (CODE)

| Тест MASTG | Уровень | Готовое требование | Критерий приёмки |
|---|---|---|---|
| MASVS-CODE-1: безопасность кода | L1 | Нет опасных паттернов: небезопасные функции, утечки памяти, гонки | SAST + код-ревью |
| MASVS-CODE-2: целостность | L1 | Проверка подписи приложения; запрет повторной подписи | Тест переподписанного APK/IPA |
| MASVS-CODE-3: настройки компиляции | L1 | Включить защитные механизмы: PIE, stack protector, ARC, запрет debug-сборок в prod | Проверка билда (MobSF) |
| MASVS-CODE-4: обработка ошибок | L1 | Ошибки не раскрывают внутренности, нет PII/секретов в логах | Проверка ответов и логов |
| MASVS-CODE-5: память | L2 | Безопасная работа с памятью (для C/C++ компонентов) | SAST, фаззинг |
| MASVS-CODE-6: зависимости | L1 | SCA-сканирование зависимостей, политика по CVE, SBOM | SCA-отчёт: 0 критичных CVE |

## 10. V8. Устойчивость к реверсу (RESILIENCE) – уровень R

| Тест MASTG | Уровень | Готовое требование | Критерий приёмки |
|---|---|---|---|
| MASVS-RESILIENCE-1: затруднение реверса | R | Обфускация кода, запутывание строк (строки-ключи, домены) | Реверс: ключевая логика не читается за разумное время |
| MASVS-RESILIENCE-2: тампер-детект | R | Детект root/jailbreak и модифицированных сред с реакцией | Тест на root-устройстве: реакция срабатывает |
| MASVS-RESILIENCE-3: самооборона | R | Защита от Frida/подключения отладчика, целостность рантайма | Тест с Frida: детект срабатывает |
| MASVS-RESILIENCE-4: детект отладки | R | Детект отладочных режимов и эмуляторов | Тест в эмуляторе |
| MASVS-RESILIENCE-5: целостность приложения | R | Проверка повторной подписи/модификации при запуске | Переподписанный билд не работает |
| MASVS-RESILIENCE-6: серверная валидация | R | Критичные решения принимаются на сервере, клиентские защиты не единственный барьер | Обход клиентских проверок не даёт привилегий |

## 11. V1. Архитектура (ARCH) – обязательно всем

| Тест | Готовое требование | Критерий приёмки |
|---|---|---|
| MASVS-ARCH-1: безопасная архитектура | Threat modeling (STRIDE) для каждой крупной фичи, DFD, trust boundaries | Наличие модели угроз, ревью архитектуры |
| MASVS-ARCH-2: разделение данных | Чувствительные данные изолированы, минимум привилегий | Код-ревью |
| MASVS-ARCH-3: серверные проверки | Клиент не является источником доверия; все проверки дублируются на сервере | Тест обхода клиента |

## 12. Серверная часть (когда есть бэкенд/API)

| Стандарт | Что даёт | Ключевые категории |
|---|---|---|
| OWASP ASVS (L1/L2/L3) | Требования к веб/API: валидация, аутентификация, доступы, криптография | V2 (аутентификация), V3 (сессии), V4 (доступ), V5 (валидация), V6 (хранилища) |
| OWASP API Security Top 10 | API-специфика | BOLA/IDOR, broken auth, mass assignment, rate limit, SSRF |
| OWASP Top 10 | Базовый чек-лист веб-уязвимостей | A01-A10 |
| NIST SSDF (SP 800-218) | Процессы безопасной разработки (для процессов, не кода) | PW (проектирование), PS (защита), PW (код), SR (реагирование) |

Пример быстрого маппинга для API: IDOR → ASVS 4.2.1 → требование «ownership-проверки на каждом эндпоинте» → приёмка «запрос чужого ID возвращает 403».

## 13. Шаблон превращения теста в требование

```markdown
### SEC-X.X. [Название требования]

- Категория MASVS: [V2-V8, ID теста]
- Уровень: L1 / L2 / R
- Требование: [формулировка из шпаргалки, адаптированная под проект]
- Обоснование (угроза): ...
- Критерий приёмки: [как проверить, из теста MASTG]
- Приоритет (MoSCoW): Must / Should / Could
- Статус: Draft / Reviewed / Approved
```

## 14. Пример: MeetWay (соцсеть = L2)

| Категория | Выбранные тесты | Получившиеся требования в SRS |
|---|---|---|
| STORAGE | 1, 2, 4, 6 | SEC-2.2, SEC-9.1, SEC-9.3 (Keychain/Keystore, бэкапы) |
| CRYPTO | 1, 2, 3 | SEC-4.1, SEC-4.2, SEC-4.5 (TLS, at rest, AES-GCM) |
| AUTH | 2, 4, 5, 8 | SEC-1.1, SEC-1.3, SEC-1.6, SEC-2.1 (rate limit, MFA, JWT) |
| NETWORK | 1, 2, 3 | SEC-4.1 (TLS 1.2+, pinning) |
| PLATFORM | 3, 4, 6 | SEC-9.2, защита WebView (в Development) |
| CODE | 1, 2, 3, 6 | SEC-12.1, SEC-12.3, DoD (SEC-16.1) |
| RESILIENCE | 2, 3 | SEC-9.2 (root/jailbreak, Frida) |

## 15. Чек-лист: чего минимум хватать по типу проекта

| Тип проекта | Минимальный набор |
|---|---|
| Утилита без данных | L1: STORAGE-6, NETWORK-1/2/3, CODE-1/2/3/6, ARCH-1 |
| Соцсеть/мессенджер | L2: + STORAGE-1/2/4/5, AUTH-2/4/5, PLATFORM-3/4, NETWORK-5 |
| Банк/платежи/медицина | L2+R: + CRYPTO-4, RESILIENCE-1..6, AUTH-8/9, ASVS L2+, PCI DSS/HIPAA |
| Игра/развлечения | L1 + RESILIENCE-1/2 (анти-чит), CODE-6 |
