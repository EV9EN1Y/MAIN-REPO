##### перед этой темой можно прочесть тему [[X-509]]
PKI — это государство, а X.509 — это паспорт его гражданина 

PKI (Public Key Infrastructure) — это **вся система**, которая эти паспорта [[X-509]] выдает, проверяет, отзывает и вообще следит, чтобы никто не подделал документы

---


###  что входит в эту "систему" (PKI)?

Если X.509 — это просто формат бумажки, то PKI — это гигантская машина, которая включает в себя:

| Компонент PKI                         | Что делает? (Аналогия с паспортным столом)                                                                                         |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Центр сертификации (CA)**           | **Паспортный стол**. Единственный, кто имеет право подписывать и выдавать готовые паспорта (сертификаты)                           |
| **Регистрационный центр (RA)**        | **Очередь и проверка документов**. Проверяет, действительно ли ты — это ты, и передает данные в CA                                 |
| **Владелец сертификата**              | **Ты сам**. Человек, у которого на руках есть паспорт                                                                              |
| **Сторона, проверяющая сертификат**   | **Пограничник**. Тот, кто смотрит в твой паспорт и решает, пускать тебя или нет                                                    |
| **Хранилище сертификатов (CRL/OCSP)** | **База данных украденных паспортов**. Список, который проверяет пограничник, чтобы убедиться, что твой паспорт не числится в угоне |

PKI решает главную проблему интернета: **как доверять незнакомцу**. Она гарантирует, что:

1. **Ты — это ты** (аутентификация)
2. **Никто не прочитает твои данные** (шифрование) 
3. **Файл не подменили** (целостность)
    

Где встречается:

- **HTTPS и SSL/TLS** - Когда ты видишь замочек в браузере — это работает PKI
    
- **Электронная подпись** - Подпись документов в госуслугах, банках
    
- **VPN и Wi-Fi** -: Корпоративные сети, чтобы пускать только своих сотрудников
    
- **Подпись кода (Code Signing)** - : Чтобы ты был уверен, что скачанная программа не содержит вирус

------

#### допустим - я - владелец сайта!

Если ты просто создаешь сайт и хочешь, чтобы он работал по HTTPS (зеленый замочек в браузере), тебе **ничего не нужно знать про PKI глубоко**. Ты просто:

1. Идешь к **центру сертификации (CA)** — Let's Encrypt, DigiCert, GlobalSign
    
2. Получаешь SSL/TLS сертификат для своего домена
    
3. Ставишь его на сервер
    
4. PROFIT — браузеры доверяют тебе, потому что твой сертификат подписан CA, которому браузеры доверяют 
   

**Что ты делаешь руками:**

```bash
# Для Let's Encrypt вообще одна команда
certbot --nginx -d твойсайт.ru


Всё. Ты даже не в курсе, что там внутри X.509, PEM, ASN.1 — тебе это не нужно 
```

## когда PKI реально трогают руками 

А вот когда ты работаешь в корпорации, банке, госструктуре или разрабатываешь что-то серьезное — там начинается жесть

### 1. **Системный администратор / DevOps**

Работает с PKI постоянно:

- Настраивает **внутренний CA** для своих сервисов (чтобы не покупать внешние сертификаты для каждого внутреннего API) 
    
- Раздает **клиентские сертификаты** сотрудникам для доступа к VPN, Wi-Fi, внутренним порталам 
    
- Управляет **сроками годности** сертификатов (чтобы сайт не лег в понедельник утром)
    

Почему не взять внешний CA? Потому что внешние сертификаты нельзя выпустить на внутренние IP типа 10.0.0.1 или на домены типа `internal.company.local` — CAB Forum запрещает 

### 2. **Разработчики 

Код, который реально дергает PKI:

**Бэкенд-разработчик:**

```python
# Проверка сертификата клиента в коде
if not verify_client_certificate(request.cert):
    return 403 "Ты кто такой?"
```

**Фронтенд-разработчик:**

- Встраивает библиотеки для шифрования на клиенте (например, платежные формы с RSA) 
- Работает с Web Crypto API для подписи данных прямо в браузере
    

**Разработчик мобильных приложений:**

- Добавляет поддержку токенов и смарт-карт для аутентификации 
- Встраивает криптобиблиотеки для работы с PKCS#11 (железные ключи)
   

### 3. **Архитектор безопасности (AppSec)**

Проектирует всю систему:

- Как ключи хранить? (HSM модули — отдельные железки, откуда ключ невозможно вытащить) 
   
- Какую длину ключа использовать? (RSA 2048 уже на грани, 4096 норм)
   
- Как организовать PKI для тысяч IoT-устройств? 
   

### 4. **Инженер по электронному документообороту**

Работает с юридически значимыми подписями:

- Квалифицированная электронная подпись (КЭП) — это тоже PKI 
    
- Службы штампов времени (TSP) — чтобы доказать, что документ подписан именно в тот момент 
- 
- OCSP-серверы — проверка, не отозван ли сертификат прямо сейчас
