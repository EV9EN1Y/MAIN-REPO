

## Что такое Clickjacking

Clickjacking это интерфейсная атака при которой пользователя обманом заставляют кликнуть на скрытый элемент другого сайта. Жертва думает что нажимает на видимую кнопку а на самом деле кликает по невидимому iframe с целевым сайтом. В результате выполняются нежелательные действия перевод денег смена email или подписка на страницу.

От CSRF атака отличается тем что пользователь реально кликает а CSRF подделывает запрос без участия жертвы. CSRF токены тут не защищают потому что запрос идёт в рамках нормальной сессии просто внутри скрытого iframe.

### разница  CSRF и Clickjacking

| Характеристика       | CSRF (Cross-Site Request Forgery)                                                                               | Clickjacking (Подделка клика)                                                                                                                                             |
| -------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Роль жертвы**      | Пассивная. Жертва даже не знает, что атака происходит                                                           | Активная. Жертва сама кликает на нужную кнопку, думая, что делает что-то другое                                                                                           |
| **Суть атаки**       | Подделка запроса. Браузер жертвы сам отправляет вредоносный запрос                                              | Подделка интерфейса. Жертву обманом заставляют кликнуть по нужному элементу                                                                                               |
| **Что доставляется** | Вредоносный запрос (например, через форму, которая отправляется автоматически с помощью JavaScript)             | Визуальный интерфейс (HTML и CSS), который маскирует целевой сайт                                                                                                         |
| **Пример**           | Жертва заходит на сайт атакующего, и её браузер незаметно отправляет POST-запрос на смену пароля на сайте банка | Жертва заходит на сайт атакующего, видит кнопку "Получить скидку", кликает на неё, но на самом деле кликает по скрытой кнопке "Подтвердить перевод" на сайте своего банка |

## Как построить базовую атаку

Кликджекинг использует CSS для наложения слоёв. Целевой сайт загружается в iframe который делается прозрачным и размещается поверх приманки.
```html

<head>
	<style>
		#target_website {
			position:relative;
			width:128px;
			height:128px;
			opacity:0.00001;
			z-index:2;
			}
		#decoy_website {
			position:absolute;
			width:300px;
			height:400px;
			z-index:1;
			}
	</style>
</head>
<body>
	<div id="decoy_website">
	...контент приманки...
	</div>
	<iframe id="target_website" src="https://example.com">
	</iframe>
</body>
```
Параметры подбираются так чтобы iframe точно накладывался на приманку независимо от размеров экрана. z-index управляет порядком слоёв а opacity делает iframe невидимым. Современные браузеры могут блокировать iframe с очень низкой прозрачностью поэтому opacity выставляют чуть выше порога срабатывания защиты.

Для быстрого создания PoC можно использовать Clickbandit инструмент в Burp Suite. Он записывает действия на странице и сам генерирует HTML с overlay.

## Разновидности атак

### Clickjacking с предзаполненной формой

Если сайт позволяет передавать параметры формы через GET то URL целевой страницы модифицируется с нужными значениями. Пользователь видит приманку а кликает по невидимой кнопке отправки формы с уже введёнными данными.

### Multistep clickjacking

Для сложных операций требующих нескольких шагов добавляют несколько iframe или слоёв которые последовательно активируются. Например добавить товар в корзину а потом оформить заказ. Такие атаки сложнее в реализации но возможны.

### Комбинация с DOM XSS

Кликджекинг становится особенно опасным когда используется как доставщик XSS атаки. Уязвимость XSS внедряется в URL целевого сайта а клик запускает её выполнение.

### DoubleClickjacking

Новая техника 2025 года обходит классические защиты X-Frame-Options и CSP. Атака строится на тайминге между двумя кликами. Жертва заходит на сайт атакующего открывается окно с безобидной капчей требующей двойного клика. Пока пользователь делает второй клик окно подменяется на страницу подтверждения опасного действия. Жертва кликает второй раз уже по подтверждению ничего не подозревая.

## Обход frame busting скриптов

Некоторые сайты защищаются JavaScript проверками запрещающими фрейминг.

text

if (top != self) top.location.href = location.href;

Это легко обходится через атрибут sandbox у iframe.

text

<iframe src="https://example.com" sandbox="allow-forms"></iframe>

Если не указывать allow-top-navigation то iframe не может проверить является ли он верхним окном и frame buster не срабатывает. При этом функциональность внутри iframe сохраняется.

## Как защищаться

### X-Frame-Options

Старый заголовок который поддерживается всеми браузерами но имеет ограничения.

text

X-Frame-Options: deny
X-Frame-Options: sameorigin
X-Frame-Options: allow-from https://example.com

Директива allow-from работает не во всех браузерах поэтому полагаться только на неё нельзя.

### Content Security Policy

Современный стандарт который гибко управляет фреймингом через директиву frame-ancestors.

text

Content-Security-Policy: frame-ancestors 'none';
Content-Security-Policy: frame-ancestors 'self';
Content-Security-Policy: frame-ancestors example.com;

Можно перечислять несколько доверенных источников. CSP перекрывает X-Frame-Options и считается надёжной защитой если правильно настроена.

### Многоуровневая защита

Рекомендуется комбинировать оба подхода устанавливать и CSP и X-Frame-Options. Для защиты от DoubleClickjacking отключать чувствительные кнопки по умолчанию требовать нажатие клавиш модификаторов или движение мыши перед действием. Браузерные вендоры работают над новыми стандартами против тайминговых атак.

## Итог

Кликджекинг технически простая атака но очень эффективная против сайтов без защитных заголовков. Современные браузеры поддерживают надёжные механизмы защиты через CSP которые нужно правильно настраивать. Новые вариации типа DoubleClickjacking показывают что даже классические защиты могут не спасать и требуют дополнительных мер на уровне интерфейса
