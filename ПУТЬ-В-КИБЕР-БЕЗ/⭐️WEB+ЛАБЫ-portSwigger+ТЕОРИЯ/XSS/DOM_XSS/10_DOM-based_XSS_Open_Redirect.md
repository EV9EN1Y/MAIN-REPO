на главной странице нашел!!! `GET / HTTP/2`

```html
<script>

   window.addEventListener('message', function(e) {
      var url = e.data;
      
   f (url.indexOf('http:') > -1 || url.indexOf('https:') > -1) {
              location.href = url;
             }
       }, false);
       
</script>
```

это - функция для приёма сообщений от других источников (окон, iframe’ов) через механизм `postMessage`

**`window.addEventListener('message', ...)`** — слушатель, который ждёт, когда с текущей страницей кто-то захочет поделиться данными через `postMessage`

Отправителем может быть:
- Сама страница (если в ней есть несколько iframe'ов)
- **Другая вкладка** того же браузера
- **Совершенно другой сайт**, загруженный в iframe на этой странице. Это и есть **кросс-доменное взаимодействие**

**`location.href = url;`** — **перенаправляет всю страницу** на эказанный URL


-------

чтобы это использовать - нужно просто отправить мессадж на адресс этого сайта
нужно чтобы жертва перешла по ссылке


можно отправить жертву на свой сайт ,на котором сработает iframe src и автоматом подгрузит эту ссылку с пейлоадом


```js


<iframe src="https://0a2100e2047e62b983d15b5e00120021.web-security-academy.net/" onload="this.contentWindow.postMessage('<img src=x onerror=print()>', '*')">


```
--- не сработал скрипт!


разбор:

```js

this.contentWindow.postMessage('<img src=x onerror=print()>', '*')
```

- `this` — это сам iframe
- `contentWindow` — это окно внутри iframe (та самая загруженная страница)
- `postMessage()` — метод, который **отправляет сообщение** в это окно
- `'<img...>'` — само сообщение (пейлоад)
- `'*'` — разрешено отправлять на любой домен (небезопасно)



**onload** — это событие, которое срабатывает, когда элемент полностью загрузился

1. **Сначала:** iframe начинает загружать страницу по указанному `src`
2. **Потом:** когда страница **полностью загрузилась** — срабатывает `onload`
3. **И только тогда:** выполняется код внутри `onload`

проверка `indexOf('http:') > -1` или `indexOf('https:') > -1` =никуда не годится так как она сработает на любой строке, где встречается `"http:"`, например: `https://evil.com#http:`

-------



```html
<iframe src="https://0af4000d04784985809917ba001f0014.web-security-academy.net/" onload="this.contentWindow.postMessage('javascript:print()//http:','*')">
```

сработало!!!!!ё

#### выводы

здесь есть уязвимость в обработчике веб-сообщений для DOM-based открытого перенаправления и выполнения JavaScript

На странице был код, который слушал сообщения через `postMessage`, искал в них подстроки `"http:"` или `"https:"` и при их наличии делал `location.href = url`

санитаризайции не было, что приходит - тому и верим

обработчик увидел `http:`, выполнил `location.href = 'javascript:print()//http:'`, что привело к выполнению `print()` в контексте страницы

отсутствие проверки происхождения сообщения (параметр `'*'`) позволило атаковать с любого сайта

#### защита

первое, при использовании `postMessage` всегда нужно проверять происхождение сообщения через `e.origin` и сравнивать с белым списком доверенных доменов

второе, проверка протокола должна быть строгой - сравнивать начало строки, а не искать подстроку где попало

третье, запрещать использование `javascript:`схемы в URL, особенно при установке `location.href`

четвертое, применять Content Security Policy с директивой `script-src`, блокирующей выполнение инлайн-скриптов

пятое, не использовать конструкцию `'*'` в `postMessage` без крайней необходимости
