<h2 id="^cors">🏆 # 🟢 CORS (Cross-Origin Resource Sharing)</h2>
# 🧟‍♂️

1 🟢 -   есть есть в ответах заголовок `Access-Control-Allow-Credentials: true` Access-Control-Allow-Origin ,  если подменяя Origin или хост или рефер данные отражается в ответе от сервера. то уже есть причины проверять на CORS!

подставил в запросе в Origin: мой сервер и он отразился в ответе в Control-Allow-Origin , + был заголовок в ответе Access-Control-Allow-Credentials. 
ну а потом на своем сервере разместил скприт  (можно посмотреть в этой лабе 01_CORS_Origin) и когда жертва перешла на мой сайт - то
на тот реефер откуда пришел (вернее с какого сайта пришла жертва -) то на этот сайт отправляется запрос на передачу куки (отправку кку) на мой сервер обратно!) короче сайт разрешил перекинуть все данные на мой сервер по запросу с моего сервера

2 🟢 - при отправке ==Origin: null== сервер вернул `Access-Control-Allow-Origin: null` с разрешением кук. Создал iframe с ==sandbox="allow-scripts allow-forms"== и ==data: URL==, origin такого iframe становится null. Внутри iframe скрипт запрашивал `/accountDetails` и отправлял данные на мой сервер  
==null origin можно подделать через sandbox iframe; если сервер доверяет null - это критическая уязвимость==


3 🟢 - сервер доверял всем своим поддоменам независимо от протокола. Один из поддоменов (`==stock.*==`) работал по HTTP и имел XSS в параметре `==productId==`. Через XSS внедрил скрипт, который с куками жертвы запрашивал `==/accountDetails==` на основном HTTPS-сайте. Так как поддомен был в белом списке, CORS разрешил чтение данных  
==доверие к поддоменам с HTTP, если основной сайт на HTTPS — опасно; XSS на любом доверенном поддомене дает полный доступ к данным==


| 🟢Способ                    | Пример                                                          | Защита                                                  |
| --------------------------- | --------------------------------------------------------------- | ------------------------------------------------------- |
| Origin reflection           | `Origin: evil.com` → отражается в `Access-Control-Allow-Origin` | Строгий белый список                                    |
| Null origin whitelist       | `Origin: null` → сервер доверяет null                           | Не добавлять null в белый список                        |
| Trusted subdomain with HTTP | XSS на HTTP-поддомене → чтение данных с HTTPS                   | Все поддомены на HTTPS, одинаковый уровень безопасности |
