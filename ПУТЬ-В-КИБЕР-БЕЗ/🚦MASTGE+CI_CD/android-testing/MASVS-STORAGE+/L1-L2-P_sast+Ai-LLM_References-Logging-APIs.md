# MASTG-TEST-0231: References to Logging APIs
https://mas.owasp.org/MASTG/tests/android/MASVS-STORAGE/MASTG-TEST-0231/

----
Тест проверяет, используются ли в приложении API для логирования (`Log`, `System.out`, `printStackTrace`). Наличие этих API само по себе не является уязвимостью, но указывает на потенциальную возможность утечки данных, если разработчик не удалил логи из продакшн-версии.

не должны логироваться конфиденциальные данные , пароли/ логины и тому подобные данные!

-----

задача - найти в коде_приложения вызовы API логирования типа

нужно выполнить поиск через JADX в коде:

- `Log.d(` — для поиска дебаг-логов.
    
- `Log.i(` — для поиска информационных логов.
    
- `Log.e(` — для поиска логов ошибок.
    
- `Log.w(` — для предупреждений.
    
- `Log.v(` — для verbose-логов.
    
- `System.out.print` — для вывода в стандартный поток.
    
- `System.err.print` — для вывода ошибок.
    
- `printStackTrace` — для печати стека ошибок.

```c
jadx-gui ~/Desktop/meetway.apk
```

```bash
# Log.d() - дебаг логи
grep -rn "Log\.d(" app/src/ | wc -l
# Log.i() - информационные
grep -rn "Log\.i(" app/src/ | wc -l
# Log.e() - ошибки
grep -rn "Log\.e(" app/src/ | wc -l
# Log.w() - предупреждения
grep -rn "Log\.w(" app/src/ | wc -l
# Log.v() - verbose
grep -rn "Log\.v(" app/src/ | wc -l
# System.out/err
grep -rn "System\.out\|System\.err" app/src/
# printStackTrace
grep -rn "printStackTrace" app/src/
```

### что на самом деле в логах

**Log.d() — 121 штука**

тут жесть. через дэбаг логи утекает:
- EncryptionUtil — длина ключа шифрования, passphrase, ID участников чата
- ChatViewModel — расшифрованный текст сообщений (первые 40 символов)
- ObjectStorageService — S3 SigV4 DEBUG с полной структурой подписей
- SecureStorage — длина JWT, сохранение myID

```kotlin
Log.d(TAG, "🔓 decryptMessages: my=[$myUid], other=[$otherUserId]")
Log.d(TAG, "✅ Расшифровано: id=${msg.id}, текст=${plain.take(40)}")
```

**Log.i() — 315 штук**

самая большая цифра. часть из них безобидная ("App started"), но:
- CloudFunctionService логирует RAW RESPONSE с email и полным профилем
- AuthViewModel — yandex_id в каждом логе
- ProfileViewModel — список ключей поиска (интересы, хобби, города)

```kotlin
Log.i(TAG, "📤 Параметры: yandexId=\"$yandexId\"")
Log.i(TAG, "📤 RAW RESPONSE [getUserData]: code=200, body={\"success\":true...}}")
```

**Log.e() — 109 штук**

стандартные обработчики ошибок — сообщения об ошибках без чувствительных данных

**Log.w() — 10 штук**

тоже без чувствительных данных — в основном "что-то пошло не так"

**printStackTrace — 4 штуки**

все в UI скринах — для отладки, не опасно
