# MASTG-TEST-0339: SQL Injection in Content Providers
https://mas.owasp.org/MASTG/tests/android/MASVS-CODE/MASTG-TEST-0339/

**не уязвимо ли приложение для SQL-инъекций через Content Provider**



## тест жестко завязан на **Content Providers** и локальную **SQLite** базу данных внутри самого приложения



### -------=-=-=-=-=-=-=--------


Content Providers - это компоненты Android, которые позволяют приложениям обмениваться структурированными данными. Если разработчик в Content Provider'е формирует SQL-запросы, напрямую вставляя в них данные из URI (например, из `getPathSegments()`) или из аргументов `selection`, без использования параметризации, это создает риск SQL-инъекции

Злоумышленник, имеющий доступ к Content Provider, может подсунуть специально сформированный URI или аргументы, которые изменят логику запроса, что может привести к утечке данных, их изменению или удалению

естественно - это актуально, если в приложении используются бд

-------


чек сигнатур для поиска

1. **`execSQL`** — метод, выполняющий произвольный SQL-запрос (не только выборку). Очень опасен, если в него подставляются данные извне
    
2. **`update`** — метод ContentProvider'а для обновления данных. Проверь, не формируется ли запрос с использованием пользовательского ввода
    
3. **`delete`** — метод для удаления данных. Аналогично, если в условие удаления подставляются данные из URI — это уязвимость
    
4. **`insert`** — метод для вставки данных. Если вставляются данные из внешнего источника без проверки — тоже риск
    
5. **`SQLiteDatabase`** — класс для работы с базой данных. Ищи его использование в контексте ContentProvider'а
    
6. **`rawQuery`** — уже есть в твоем списке, но проверь также его перегрузки
    
7. **`compileStatement`** — используется для компиляции SQL-запросов. Может быть опасен, если в него подставляются данные
    
8. **`String.format`** — часто используется для формирования запросов. Если в `String.format`подставляются данные из URI, это может быть небезопасно
    
9. **`+ "`** — конкатенация строк. Ищи паттерны, где к SQL-запросу прибавляются данные из `getPathSegments()` или `selection`

### Что использует MeetWay вместо SQL

Приложение **не использует SQLite вообще**. Вся работа с данными идёт через:
- **Firebase Firestore** - NoSQL, документная БД
- **Yandex Cloud Functions** — HTTP API
- **SharedPreferences** (EncryptedSharedPreferences) — локальное хранение
- **ContentValues** (2 вхождения — для сохранения медиа в галерею через MediaStore)

MeetWay **не имеет собственного ContentProvider** — в манифесте только FirebaseInitProvider и AndroidX InitializationProvider (оба стандартные, системные).

###  Итог

Все 10 000+ совпадений - **в библиотеках** (Firebase, AndroidX, GMS, CameraX).
App-код не содержит:
- Собственных ContentProvider
- SQL-запросов
- SQLite-операций
- SQL-инъекций
