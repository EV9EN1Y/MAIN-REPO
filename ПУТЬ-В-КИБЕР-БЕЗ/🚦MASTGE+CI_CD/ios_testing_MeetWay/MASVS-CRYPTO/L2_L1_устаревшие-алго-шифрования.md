# MASTG-TEST-0210: Broken Symmetric Encryption Algorithms


данный тест проверяет, не использует ли приложение слабые/устаревшие симметричные алгоритмы шифрования

Такие алгоритмы (DES, 3DES, RC2, RC4, Blowfish) ломаются современными методами. Если их используют для защиты пользовательских данных, конфиденциальность нарушается

**Вердикт:** FAIL, - >  когда приложение вызывает `CCCrypt` с небезопасным алгоритмом (например, `kCCAlgorithmDES`) или использует небезопасную библиотеку типа OpenSSL с Blowfish

```c
- kCCAlgorithmAES128
- kCCAlgorithmDES
- kCCAlgorithm3DES
- kCCAlgorithmCAST
- kCCAlgorithmRC4
- kCCAlgorithmRC2
- kCCAlgorithmBlowfish
```

тест можно провести - проверив бинарник

1 шаг тестирования

```q
искать вызовы CCCrypt

is | grep CCCrypt

далее нужно проверить кв найденных результатах каждый аргумент

mov  x2, #0x0          ; ← alg = kCCAlgorithmAES128 (✅ это гуд!)
mov  x2, #0x1          ; ← alg = kCCAlgorithmDES  (⚠️ FAIL)
mov  x2, #0x2          ; ← alg = kCCAlgorithm3DES (⚠️ FAIL)
mov  x2, #0x3          ; ← kCCAlgorithmCAST (сомнительный 🟠 )
mov  x2, #0x4          ; ← kCCAlgorithmRC4  (⚠️ FAIL)
mov  x2, #0x5          ; ← kCCAlgorithmRC2  (⚠️ FAIL)
mov  x2, #0x6          ; ← kCCAlgorithmBlowfish (⚠️ FAIL)
= 0x01  // kCCOptionECBMode ; ← kCCAlgorithmBlowfish (⚠️⚠️⚠️ FAIL)


mov  x0, #0x0          ; op (kCCEncrypt)
mov  x1, #0x0          ; alg (AES — хорошо)
mov  x2, #0x1          ; options (ECB — ⚠️ плохо)
mov  x3, x8            ; key (указатель)
mov  x4, #0x10         ; keyLength (16 байт — 128 бит — норма)
mov  x5, #0x0          ; iv (NULL — ❌ для CBC это FAIL!)
br   sym.imp.CCCrypt
```

также обратить внимание в ## `CCCrypt`

на **`keyLength`** - если короче 128 бит - то это слабый ключ (можно сломать перебором)

**`options`** = `0x01` (ECB) или `0x00` (без IV) - ECB небезопасен, отсутствие IV для CBC - оч плохо



что касается **CryptoKit** 
**CryptoKit не поддерживает слабые алгоритмы**
Если приложение использует только CryptoKit, тест автоматом **можно сказать - что норм, но!** (но это не снимает ответственности за проверку случайности IV и длины ключа)

НЕ НАЙДЕНЫ ОПАСНЫЕ АЛГОРИТМЫ
используется только CryptoKit

>CryptoKit - уже современный криптофреймворк от Apple, который:

>- Не позволяет использовать слабые алгоритмы (DES, RC4 и т.д)
>- По умолчанию требует безопасные параметры (AES-GCM, ChaChaPoly)  
>- Сам генерирует случайные IV/nonce

в том числе найдены 
0x00aa5fa5 hit6_41 .ricKeyVtKFZ_$s9CryptoKit3AESO3👉👉GCM👈👈O4seal_
0x00aa601b hit6_42 .otocolRzlFZ_$s9CryptoKit3AESO3👉👉GCM👈👈O5Nonce

и это - прямое указание на использование **AES-GCM**, одного из самых безопасных симметричных шифров
