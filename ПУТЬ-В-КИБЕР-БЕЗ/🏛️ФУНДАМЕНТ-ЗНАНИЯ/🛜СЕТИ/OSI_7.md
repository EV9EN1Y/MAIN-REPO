В контексте SSRF управление протоколами и командами. 
Здесь живут схемы URI, синтаксис команд для сервисов.

`gopher://`, `dict://`, `ldap://`, `tftp://`, `file://`, команды **`stats`** и **`quit`**

- **`stats` и `quit`**: Это **команды прикладного уровня протокола Memcached**.  (L7 OSI)
- Аналогично существуют команды `GET / HTTP/1.1` для HTTP, `AUTH` для SMTP и т.д.
- Это конкретные инструкции для сервиса Memcached.
- 
    
- **Схемы URI (`gopher://`, `dict://`, `file://` и др.)**: 
- Это **указатели на обработчик протокола** на сервере. Когда вы передаёте `gopher://`, мы говорим библиотеке (cURL, PHP) использовать обработчик протокола Gopher для формирования пакета данных. Каждая схема диктует свои правила формирования сообщения (синтаксис) на прикладном уровне.

-------
- ==STATUS==: Сервер возвращает статистику: версию, список всех ключей кэша, их размеры. Это **основная команда разведки**.
    
- ==QUIT==: Корректно завершает сессию.

Обе команды запускаются на сервере **Memcached** (демон `memcached`), который по умолчанию слушает **порт 11211/TCP** (иногда UDP). https://ru.wikipedia.org/wiki/Список_портов_TCP_и_UDP?ysclid=ml3b5u4jg4698644058
**Memcached** — программное обеспечение, реализующее сервис кэширования данных в оперативной памяти на основе хеш-таблицы. Цель — оптимизировать производительность приложений за счёт снижения нагрузки на серверы баз данных
**Сервер Memcached чаще всего используется для кэширования** веб-страниц, результатов запросов к базе данных и других данных, требующих быстрого доступа




----

**Memcached — это НЕ браузерная технология и не устанавливается на обычные ПК пользователей.** Это сугубо серверная технология.

### 🌐 * Memcached**

**Memcached (от _Memory Caching Daemon_)** — это высокопроизводительная, распределенная система **кэширования в оперативной памяти (RAM)**.

- **Представьте себе**: У интернет-магазина есть главная страница, которую сложно сгенерировать (туда тянется информация о товарах, акциях, отзывах). Чтобы не делать эту работу каждый раз для каждого посетителя, сервер **один раз создает страницу и кладет ее в Memcached** (в оперативку). Следующие 5 минут все пользователи получают эту же страницу из быстрой памяти, а не из медленной базы данных.
    
- **Главная цель**: Чрезвычайно быстро отдавать часто запрашиваемые данные, снижая нагрузку на основную базу данных (MySQL, PostgreSQL) или тяжелые приложения.
    
- **Простой протокол**: Работает по принципу `ключ -> значение`. Запись: `SET user_balance_12345 100`. Чтение: `GET user_balance_12345` (вернет `100`). Именно поэтому его так легко атаковать через SSRF — команды текстовые и предсказуемые.
    

### 🖥️ **Где он работает и кто его использует?**

**1. Где работает физически:**

- **На стороне сервера (Backend)**: Устанавливается как отдельная служба (демон) на **серверах в дата-центре или облаке**. Часто на тех же серверах, где работает веб-приложение (`localhost`), или на выделенных нодах.
    
- **Среда выполнения**: Это самостоятельная программа, написанная на C. Она запускается в фоне и слушает сетевой порт (обычно **11211**).
- 
==**`stats` и `quit`** — это **команды текстового протокола Memcached**. Они выполняются сервисом Memcached (демоном на порту 11211).==

    

**2. Кто и зачем его использует:**

- **Крупные высоконагруженные сайты и приложения**: Facebook (они его и создали), Wikipedia, Twitter, YouTube, Reddit, [Booking.com](https://booking.com/) и тысячи других.
    
- **Для ускорения всего, что часто читается**: HTML-фрагменты страниц, результаты сложных запросов к БД, сессии пользователей, данные профилей.

#### ==**`gopher://`, `dict://`, `ldap://`, `tftp://`, `file://`**

- **Что это?** **Схемы URL (URI schemes)**. Это указатели для библиотек (cURL, libwww) по какому протоколу устанавливать соединение.
- **Как работают и где формируются?**
    
    1. Атакующий передает URL со схемой в параметр уязвимого приложения (например, `?url=gopher://...`).
    2. Серверная библиотека (например, cURL в PHP) **интерпретирует схему** и формирует соответствующее сетевое сообщение на **прикладном уровне (L7)**.
    3. Это сообщение отправляется через транспортный уровень (L4, TCP/UDP) на целевой хост и порт.

----

==**`gopher:// или Gopher (устаревший)==
**Самый мощный.** 
Позволяет сформировать **любой сырой TCP-пакет**. Через него можно говорить на протоколах Redis, Memcached, MySQL, SMTP.

`gopher://127.0.0.1:6379/_*1%0d%0a$7%0d%0aCOMMAND%0d%0a`(отправляет команду `COMMAND` в Redis).

**Передает любые данные.** Через него можно отправить команды Memcached (`stats`), Redis, MySQL, SMTP и т.д.

-----

==**`dict://`**|**DICT** ==(словарный протокол).
Позволяет отправлять текстовые команды в открытое соединение. 
Подходит для взаимодействия с Memcached, Redis.

`dict://127.0.0.1:11211/stats`(аналогично команде `stats` в Memcached).



---
==**`ldap://   LDAP (служба каталогов)==

Атака на LDAP-серверы внутри сети. Может использоваться для слепого сканирования или инъекций.
`ldap://internal.corp.net:389` — проверка доступности LDAP-сервера.
Для подключения к серверам каталогов.

----

==**`tftp://`**==
**TFTP** (простой файловый протоколд)
Атака на TFTP-серверы, часто используемые в сетевом оборудовании. 
Реже для загрузки/выгрузки файлов.
`tftp://192.168.1.1/etc/passwd` — попытка чтения файла.
Для простой передачи файлов (часто в сетевом оборудовании).

------

==**`file:// `**== **Файловая система**

Не сетевой протокол. Но позволяет **читать локальные файлы** на сервере. Критично для утечки данных.

`file:///etc/passwd`                — чтение файла пользователей. 
`file:///proc/self/environ`  — переменные окружения процесса.

# ==**`fsockopen`, `11211`, `:11211aaa`**

- Это **эксплуатация уязвимости в коде** на стороне сервера.
    
- **==fsockopen()==** — функция PHP для открытия сетевого сокета. Часто встречается в уязвимом коде:
- ```php
  $host = $_GET['host']; // Пользовательский ввод!
  $fp = fsockopen($host, 80); // Допустим, разработчик думает, что порт всегда 80
  ```
**`:11211aaa`** — **трюк с парсингом строки**
- Функция `fsockopen()` извлекает номер порта из строки `$host`, если в ней есть двоеточие. Она парсит числа, пока не встретит не-цифру.
    
    - `fsockopen("evil.com:11211", 80)` → подключится к порту **11211** evil.com (игнорирует второй аргумент `80`).
        
    - `fsockopen("127.0.0.1:11211aaa", 80)` → также подключится к порту **11211** (символы `aaa`отбрасываются).
        
- Это способ **подменить целевой порт** и перенаправить запрос с веб-порта (80) на порт внутреннего сервиса (11211), облегчая доступ к Memcached.

---

# ==**`fd://` и `/proc/self/fd/`**

**Доступ к файловым дескрипторам** процесса.
- В Linux всё — файл. Открытое сетевое соединение (сокет) — это тоже файловый дескриптор (например, номер 3).
- **`/proc/self/fd/`** — виртуальная директория, где для каждого процесса отображаются все его открытые дескрипторы.
- **`fd://`** — специальная схема в PHP (если включено), позволяющая обращаться к дескриптору по номеру.
- Веб-сервер уже держит соединения с внутренними сервисами (БД, кэшем, облачным мета-сервером). Через `fd://3`  можно **переиспользовать это уже установленное и авторизованное соединение**, обходя все сетевые фильтры и проверки доступа.


-----


`127.0.0.1` — это такой **«короткий внутренний номер» для любого компьютера или сервера**. Это зарезервированный IP-адрес, который всегда означает **«это устройство, на котором я сейчас нахожусь»**.
