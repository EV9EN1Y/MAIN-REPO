```js

// Браузерный процесс (Browser Process) — главный диспетчер

// Проверка кэша (уровень 7)

    - Проверяет дисковый кэш браузера
    - Проверяет memory-кэш
    - Смотрит Service Worker кэш (если установлен)
```

### Акт 3: DNS-похождения (Уровень 7 → Уровень 5)

Этот акт — целое приключение по поиску адреса сервера 


```js

// Этап 3.1: DNS-резолвер (поиск IP-адреса)

NetworkThread: "У меня есть домен example.com, нужен IP-адрес!"


// 3.1.1 Проверка локальных кэшей DNS

Операционная система DNS: "Проверяю hosts-файл (C:\Windows\System32\drivers\etc\hosts или /etc/hosts)"

if (запись найдена в hosts) {
    return IP-адрес из hosts
}

ОС: "Проверяю локальный DNS-кэш (в памяти)"
if (запись найдена в кэше) {
    return IP-адрес
}


// 3.1.2 Запрос к рекурсивному DNS-резолверу

ОС: "Эй, мой DNS-сервер (обычно провайдерский или 8.8.8.8), какой IP у example.com?"


Рекурсивный DNS-сервер: "Сейчас гляну..."
    - Проверяет свой кэш
    - Если нет — начинается иерархическое путешествие
      
      
      
// 3.1.3 Иерархическое разрешение (DNS-путешествие) [citation:7]

Рекурсивный сервер -> Корневой DNS-сервер: "Где найти .com?"

Корневой сервер: "Иди к TLD-серверу .com, вот его адрес"

Рекурсивный сервер -> TLD-сервер .com: "Где найти example.com?"

TLD-сервер: "Иди к авторитативному серверу для example.com, вот его адрес"

Рекурсивный сервер -> Авторитативный DNS-сервер example.com: "Какой IP у example.com?"

Авторитативный сервер: "Вот IP-адрес: 93.184.216.34 (запись типа A или AAAA)" [citation:7]

// 3.1.4 Возврат ответа
Рекурсивный сервер: (кеширует ответ) "Держи IP, клиент!"

ОС: (кеширует ответ) "Держи IP, браузер!"

NetworkThread: "Есть IP: 93.184.216.34!"


// Защита: DNSSEC (если настроено)

DNSSEC: проверяет цифровую подпись DNS-ответа, чтобы убедиться, что это не спуфинг


```

### Акт 4: Установка соединения (Транспортный уровень — Уровень 4)
#### рукопожатие
```js
// Этап 4.1: TCP-рукопожатие [citation:3][citation:9]

NetworkThread: "IP знаю, порт 443 (HTTPS). Начинаю TCP-рукопожатие"

Клиент (браузер) -> Сервер: "SYN" (хочу соединиться, мой sequence number = X)

Сервер -> Клиент: "SYN-ACK" (ок, готов, мой seq = Y, твой X получил, жду X+1)

Клиент -> Сервер: "ACK" (ок, подтверждаю, seq = X+1, твой Y получил, жду Y+1)

TCP-соединение УСТАНОВЛЕНО! [citation:9]


// Этап 4.2: TLS-рукопожатие (Уровень 5-6 — Сеансовый/Представления) [citation:3][citation:8]

// ВАЖНО: TLS работает над TCP, но до HTTP [citation:8]
Клиент: "ClientHello"
    - "Привет! Я Chrome 120. Поддерживаю TLS 1.3, 1.2"
    - "Вот список Cipher Suites, которые я знаю: TLS_AES_256_GCM_SHA384, TLS_CHACHA20_POLY1305_SHA256..."
    - "Вот мои расширения: SNI (Server Name Indication — я хочу example.com)"
    - "Вот мой Client Random (случайное число): 0x7a4f8e2b..."
    - "Поддерживаю протоколы ALPN: h2 (HTTP/2), http/1.1"
      
      
Сервер: "ServerHello"
    - "Привет! Выбираем TLS 1.3"
    - "Выбираем Cipher Suite: TLS_AES_256_GCM_SHA384"
    - "Вот мой Server Random: 0x3d8f1a6c..."
    - "Вот мой Server Certificate (сертификат X.509)" [citation:8]
      
      
Клиент: (валидация сертификата — КРИТИЧЕСКИ ВАЖНО!)
    - "Проверяю цепочку сертификатов: example.com -> Let's Encrypt R3 -> ISRG Root X1"
    - "Проверяю срок действия: ок"
    - "Проверяю подписи: использую встроенный в ОС/браузер публичный ключ корневого CA"
    - "Проверяю отозван: через OCSP или CRL" [citation:7]
    - "Проверяю Subject Name: совпадает с example.com"
    - "Всё ок, серверу можно верить!"
      
      
// Обмен ключами (для TLS 1.3 — это встроено в приветствия)
Клиент: (генерирует ключи) "Вот мой Key Share (публичный ключ для ECDHE)"

Сервер: (генерирует ключи) "Вот мой Key Share"

Оба: вычисляют общий секрет через ECDHE (эллиптический Диффи-Хеллман)
    - У каждого теперь есть одинаковый Master Secret
    - Из Master Secret генерируются сессионные ключи (для шифрования и MAC)
      
Клиент: "Change Cipher Spec" (теперь буду шифровать) — для старых версий

Клиент: "Finished" (зашифровано сессионным ключом) — "Всё готово, у меня ключи сошлись"

Сервер: "Finished" (зашифровано) — "И у меня готово, погнали!" 

TLS-туннель УСТАНОВЛЕН! Всё дальнейшее общение шифруется [citation:8]
```

про шифрование  Диффи-Хеллман вот тут у меня есть легкое понятное обьяснение

- **Интернет** — это **глобальная сеть (WAN)**, которая соединяет миллионы устройств по всему миру с помощью сложной системы протоколов (вроде TCP/IP) . Он отвечает на вопрос **"где находится сервер?"** по всему земному шару
    
- **Ethernet** — это самая популярная **технология для локальных сетей (LAN)**. Это набор правил и стандартов, который определяет, как именно твой компьютер, роутер, принтер или смарт-телевизор будут обмениваться данными **в пределах одного дома, офиса или здания** по проводам

### Акт 7: Обработка ответа браузером (Рендеринг) 

```js
// Снова на клиенте
NetworkThread: получает зашифрованные данные

TLS-слой: расшифровывает

NetworkThread: "У нас ответ! Статус 200, Content-Type: text/html"

BrowserProcess: "Renderer Process, прими данные для таба №5!"

RendererProcess (главный поток): начинает магию рендеринга [citation:5]

// 7.1 Парсинг HTML и построение DOM [citation:5]
HTML-парсер: читает поток байтов, конвертирует в токены
    - Встречает <html> — создаёт узел html
    - Встречает <head> — создаёт узел head
    - Встречает <body> — создаёт узел body
PreloadScanner: бежит впереди парсера
    - Находит <link rel="stylesheet"> — отправляет запрос на CSS
    - Находит <img src="..."> — отправляет запрос на изображение
    - Находит <script src="..."> — отправляет запрос на JS
      
      
// 7.2 Парсинг CSS и построение CSSOM [citation:5]
CSS-парсер: читает CSS-правила
    - Строит CSSOM-дерево (CSS Object Model)
      
      
// 7.3 JavaScript [citation:5]
if (встретился <script src="..."> без async/defer) {
    HTML-парсер: "Стоп! Жду пока загрузится и выполнится JS"
    // Потому что JS может изменить DOM через document.write()
    JS-движок (V8/SpiderMonkey): загружает, компилирует, выполняет
    HTML-парсер: "Продолжаем"
}


// 7.4 Построение Render Tree [citation:5]
RenderEngine: "Соединяю DOM и CSSOM"
    - Проходит по DOM-дереву
    - Для каждого видимого узла применяет вычисленные стили из CSSOM
    - Получается Render Tree (только видимые элементы)
      
      
// 7.5 Layout (Reflow) [citation:5]
LayoutEngine: "Считаю геометрию"
    - Вычисляет ширину, высоту, позицию каждого элемента
    - Учитывает viewport (размер окна браузера)
    - Учитывает CSS: box model, position, float, flex, grid
      
      
// 7.6 Paint [citation:5]
PaintEngine: "Рисую пиксели!"
    - Заполняет цветом фоны
    - Рисует текст, границы, тени
    - Создаёт слои (layers) для сложных эффектов


// 7.7 Composite [citation:5]
CompositeThread: "Собираю слои в финальную картинку"
    - Отправляет в GPU-процесс
    - GPU рендерит на экран
Браузер: "Готово! Показываем страницу пользователю"


// Асинхронные события
window.dispatchEvent(new Event('DOMContentLoaded')) // DOM готов

// после загрузки всех ресурсов
window.dispatchEvent(new Event('load')) // ВСЁ загружено

```

**Таб (вкладка)** — это **отдельный, изолированный «мини-браузер» внутри основного окна**. Когда ты открываешь новую вкладку — ты запускаешь **новый процесс** в операционной системе. Именно поэтому, если одна вкладка зависла или упала, остальные продолжают работать


Современные браузеры (Chrome, Edge, Firefox, Safari) используют **многопроцессную архитектуру**. Это как многоквартирный дом, где каждая вкладка — отдельная квартира.

|Компонент|Аналогия|Что делает|
|---|---|---|
|**Browser Process**|Управляющая компания|Управляет окнами, адресной строкой, закладками, историей. Он координирует всё, но сам страницы не рисует .|
|**Renderer Process** (Таб №5)|Квартира №5|Живёт в изоляции. Здесь парсится HTML/CSS, выполняется JavaScript (включая твой любимый XSS-код), строится DOM и рисуется страница .|
|**GPU Process**|Коммунальные службы|Отдельный процесс для общения с видеокартой, чтобы отрисовка была быстрой и не тормозила остальное .|
|**Network Process**|Почтовая служба|Отдельный процесс для всей сетевой кухни (DNS, TLS, HTTP). Раньше это было в BrowserProcess, но для безопасности вынесли отдельно .|
|**Storage Process**|Кладовка|Управляет файловыми системами, IndexedDB, локальным хранилищем — всем, что сохраняется на диск.|

**Главное, что должен вынести senior:** 
Весь этот путь — это **система вложенных доверий**.
DNS доверяет корневым серверам, 
TLS доверяет CA, 
браузер доверяет сертификату. 

Каждый уровень добавляет безопасность, и если хоть один уровень сломается 
(DNS-спуфинг, скомпрометированный CA, уязвимость в парсере) — вся цепочка рухнет к куям собачим!
