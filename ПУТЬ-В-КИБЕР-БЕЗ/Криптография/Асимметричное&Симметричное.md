#### Асимметричное / Симметричное

- ==Симметричные алгоритмы (HS256)==: один секретный ключ и для подписи, и для проверки.
    
- ==Асимметричные (RS256, ES256)==: пара ключей. Приватный подписывает, публичный проверяет

#### Эпизод I: Скрытая угроза (Симметричное шифрование)

Представь себе старую-добрую Галактическую Республику
Вся информация — военные приказы, логистика, переписка джедаев — передается по голографическим каналам. 
И есть у них один главный секрет — ==симметричное шифрование=

**Как это работает?** Это как если бы у тебя был один световой меч на двоих с Йодой. Ты им и атакуешь, и защищаешься. В криптографии это называется ==один ключ для всего==  
Алиса шифрует сообщение этим ключом, Боб получает и расшифровывает тем же самым ключом  
Всё просто и безумно быстро, как полёт «Тысячелетнего сокола» в гиперпространстве 

- **Пример из жизни (Оби-Вана):** Оби-Ван хочет отправить секретный приказ Допустим, Энакину. 
- У них есть общий код — например, сдвиг алфавита на 3 буквы (шифр Цезаря, древний, как само Сила) 
- «Атакуй» превращается в «гфхцл». 
- Быстро и сердито. Но враг (Ситхи) перехватит этот код и, если узнает алгоритм, расшифрует всё за секунду
    

**В чём же скрытая угроза, спросишь ты?** 

А в том, что этот ключ нужно как-то передать адресату. А если канал связи прослушивается? Как отправить ключ, чтобы его не стырили? Это называется ==«проблема курицы и яйца»== (или обмена ключами). 

Ты не можешь безопасно передать ключ по незащищенному каналу, потому что он незащищенный. 
И чтобы его защитить, тебе нужен другой ключ... Замкнутый круг, как бесконечные сражения на Татуине. 
Если злобная Ева (перехватчица) узнает ключ — всё, галактика пала

#### Эпизод II: Атака клонов (Асимметричное шифрование)

И тут на сцену выходят гении-джедаи — Уитфилд Диффи и Мартин Хеллман. Они изобрели ==асимметричное шифрование== — настоящий световой меч с двумя режимами 
Это переломило ход войны!

**Как это работает?** Забудь про один ключ. Теперь у тебя есть **связка «Палач — Тень»**. А точнее, пара ключей:

- **Публичный ключ (Открытый):** Это как твой номер корабля или адрес голопочты. Ты можешь разослать его всем контрабандистам, повстанцам и даже шпионам Империи. Этим ключом **только шифруют**. Любой может запереть сообщение в ящик твоим замком 
    
- **Приватный ключ (Закрытый):** Это твой личный, заветный кристалл Кайбер, который ты хранишь в сейфе на базе «Эхо». Только он может **открыть** этот ящик 

>> 	то есть публичным ключом все шифруется таким образом - что расшифровать возможно (не используя публичный ключ) -  только с помощью приватного

**В чём сила?** Люк хочет отправить Лее секретный план «Звезды Смерти». Он берет её **публичный ключ** (который висит у неё на страничке в Голонете), шифрует им сообщение. Даже если Империя перехватит это сообщение и будет знать публичный ключ Леи, она **НИЧЕГО не сделает**. 

Потому что расшифровать это можно только **приватным ключом**, который есть только у Леи  Проблема передачи ключа решена! Атака клонов провалилась 

>>	то есть у меня как у владельца приложения - на сервере лежит приватный ключ и им я могу пользоваться. и этот ключ никогда не покидает мой сервер и хранится в тайне

#### Эпизод III: Месть ситхов (Гибридная схема)

Казалось бы, вот оно, счастье! Но не тут-то было. Асимметричное шифрование — штука мощная, но **медленная**, как прогулочный шагоход Империи . Шифровать им гигабайты данных с Тактической голограммы — себя не уважать. А симметричное — быстрое, но с ключами морока. Как быть?

Джедаи нашли компромисс — **гибридную схему**, которая используется везде: в TLS (той штуке, что делает сайты безопасными), в PGP, в защите сообщений в мессенджерах 

Это как тактика мастера Йоды:

1. **Шаг 1 (Асимметричный):** Стороны договариваются о сеансе связи (рукопожатие TLS). Используя асимметричную криптографию, они безопасно обмениваются **одноразовым сессионным ключом** для симметричного шифрования  Это как передать ключ от гипердвигателя в запечатанном контейнере, который открыть может только адресат
    
2. **Шаг 2 (Симметричный):** Дальше, когда ключ уже у обоих, начинается быстрая и эффективная передача данных с помощью симметричного шифрования (типа AES — расширенного стандарта шифрования) . Тут уже можно гонять хоть всю базу данных повстанцев

(пример - вебсокет, установил соединение, потом пользуешься)

#### Эпизод IV: Новая надежда (RSA и дискретный логарифм)

А на чем же держится вся эта магия? Почему приватный ключ невозможно подобрать? 
В основе лежат сложнейшие математические задачи, которые даже суперкомпьютеры Империи не могут решить быстро

- ==RSA== (Ривест — Шамир — Адлеман): Самый известный асимметричный алгоритм
- Его сила — в сложности **разложения огромного числа на простые множители** . Если число — это размер Звезды Смерти, то найти два простых числа, которые при умножении дают его — это как найти две едва заметные вентиляционные шахты на её поверхности. Теоретически можно, но практически — никуя не получиться
   
- **Эль-Гамаль и Диффи-Хеллман:** Тут в ход идет задача **дискретного логарифмирования** . Представь, что ты знаешь результат возведения в степень в конечном поле (гигантское поле битвы). А найти саму степень (то есть ключ) — это как уследить за перемещениями Дарта Мола в толпе дроидов. Почти невозможно 
   
==AES==
**Золотой стандарт сегодня — AES (Advanced Encryption Standard)** для симметричного шифрования и всё те же RSA/ECC для асимметричных обменов  Именно они защищают твои пароли, переводы в криптовалюте  (спасибо TLS!)

## AES
##  Симметричное шифрование (Один ключ на всё)
##  Пример на Python (AES)

```python

from cryptography.fernet import Fernet

# 1. Генерируем ОДИН ключ (его надо хранить в тайне)
key = Fernet.generate_key() # ну либо придумаем его, 


cipher = Fernet(key)
print(f"Секретный ключ: {key.decode()}")



# 2. Шифруем сообщение
message = b"Привет, бро! Это секретно капец как"
encrypted = cipher.encrypt(message)
print(f"Зашифровано: {encrypted}")




# 3. Расшифровываем (тем же ключом!)
decrypted = cipher.decrypt(encrypted)
print(f"Расшифровано: {decrypted.decode()}")

```

**Что тут происходит:**

- Один ключ (`key`) и для шифрования, и для расшифровки
- Если ключ потеряешь — данные никогда не восстановить
- Скорость — бешеная

### RSA
### Асимметричное шифрование (Пара ключей)
### Пример на Go (RSA)


```go
package main
import (
    "crypto/rand"
    "crypto/rsa"
    "crypto/sha256"
    "fmt"
)
func main() {
    // 1. Генерируем ключи
    privateKey, _ := rsa.GenerateKey(rand.Reader, 2048)
    publicKey := &privateKey.PublicKey
    fmt.Println("🔐 Приватный ключ: ТОЛЬКО НА СЕРВЕРЕ")
    fmt.Println("🔓 Публичный ключ: отдаём клиентам")
    // 2. Сообщение
    secret := []byte("Люк, я твой отец!")
    // 3. Шифрование публичным ключом (делает клиент)
    ciphertext, _ := rsa.EncryptOAEP(
        sha256.New(),
        rand.Reader,
        publicKey,
        secret,
        nil,
    )
    fmt.Printf("📦 Зашифровано клиентом: %x...\n", ciphertext[:20])
    // 4. Расшифровка приватным ключом (делает сервер)
    plaintext, _ := rsa.DecryptOAEP(
        sha256.New(),
        rand.Reader,
        privateKey,
        ciphertext,
        nil,
    )
    fmt.Printf("📨 Сервер расшифровал: %s\n", plaintext)
}
```

## Гибридная схема (Как работает HTTPS)
**Транспортное HTTPS**
  комбинация обоих методов:


```python
from cryptography.hazmat.primitives.asymmetric import rsa, padding
from cryptography.hazmat.primitives.ciphers import Cipher, algorithms, modes
from cryptography.hazmat.primitives import hashes
import os

# ===== СЕРВЕРНАЯ ЧАСТЬ =====

# 1. У сервера есть пара RSA-ключей
server_private = rsa.generate_private_key(public_exponent=65537, key_size=2048)
server_public = server_private.public_key()


print("🚀 Сервер готов, публичный ключ разослан клиентам")



# ===== КЛИЕНТСКАЯ ЧАСТЬ =====


# 2. Клиент получает публичный ключ сервера

print("\n📱 Клиент хочет отправить секретные данные")


# 3. Клиент генерирует СИММЕТРИЧНЫЙ ключ (для AES)

session_key = os.urandom(32)  # 256 бит

print(f"🔑 Клиент создал сессионный ключ: {session_key.hex()[:16]}...")



# 4. Клиент шифрует ЭТОТ КЛЮЧ публичным ключом сервера (RSA)

encrypted_key = server_public.encrypt(
    session_key,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None
    )
)


# 5. Клиент шифрует ДАННЫЕ сессионным ключом (AES)

message = b"Ваш баланс: 1 000 000 BTC, только никому не говори!"
iv = os.urandom(16)  # вектор инициализации
cipher = Cipher(algorithms.AES(session_key), modes.CBC(iv))
encryptor = cipher.encryptor()


# Добавляем паддинг (дополнение до блока)

padded_message = message + b" " * (16 - len(message) % 16)
encrypted_data = encryptor.update(padded_message) + encryptor.finalize()
print(f"📦 Клиент отправляет на сервер:")
print(f"   - Зашифрованный ключ: {encrypted_key.hex()[:30]}...")
print(f"   - Вектор IV: {iv.hex()}")
print(f"   - Зашифрованные данные: {encrypted_data.hex()[:30]}...")


# ===== СЕРВЕРНАЯ ЧАСТЬ =====


# 6. Сервер получает всё это и расшифровывает

print("\n🖥️ Сервер получил данные:")


# 7. Сервер расшифровывает сессионный ключ своим приватным ключом
decrypted_key = server_private.decrypt(
    encrypted_key,
    padding.OAEP(
        mgf=padding.MGF1(algorithm=hashes.SHA256()),
        algorithm=hashes.SHA256(),
        label=None
    )
)

print(f"🔓 Сервер восстановил сессионный ключ: {decrypted_key.hex()[:16]}...")


# 8. Сервер расшифровывает данные сессионным ключом

cipher = Cipher(algorithms.AES(decrypted_key), modes.CBC(iv))
decryptor = cipher.decryptor()
decrypted_data = decryptor.update(encrypted_data) + decryptor.finalize()
decrypted_data = decrypted_data.rstrip(b' ')  # убираем паддинг
print(f"📨 Расшифрованное сообщение: {decrypted_data.decode()}")

```
