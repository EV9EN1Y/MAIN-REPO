### SDLC / SSDLC
- **Этапы SDLC:** требования → анализ → планирование → дизайн → разработка → тестирование → деплой → поддержка
- **SSDLC** = безопасность на КАЖДОМ этапе, а не в конце
- **На этапе требований AppSec:** проверяет security-требования, задаёт вопросы аналитикам, определяет регуляторные требования
- **Инструменты тестирования:** SAST (Semgrep, SonarQube), DAST (Burp, ZAP), SCA (Dependency-Check, Trivy), IAST (Contrast), RASP
> **ZAP** – Zed Attack Proxy (инструмент OWASP для тестирования безопасности веб-приложений)

> **SCA** – Software Composition Analysis (анализ состава программного обеспечения)

> **RASP** – Runtime Application Self-Protection (самозащита приложения во время выполнения)

> **IAST** – Interactive Application Security Testing (интерактивное тестирование безопасности приложений)

> **DAST** – Dynamic Application Security Testing (динамическое тестирование безопасности приложений)

> **SAST** – Static Application Security Testing (статическое тестирование безопасности приложений)

> **SSDLC** – Secure Software Development Life Cycle (безопасный жизненный цикл разработки программного обеспечения)

> **SDLC** – Software Development Life Cycle (жизненный цикл разработки программного обеспечения)

> **AppSec** – Application Security (безопасность приложений)


### Threat Modeling
- **STRIDE:** Spoofing, Tampering, Repudiation, Info Disclosure, DoS, Elevation of Privilege
- **DREAD:** Damage, Reproducibility, Exploitability, Affected users, Discoverability
- **DFD** – основа: внешние сущности, процессы, хранилища, потоки, границы доверия
- **Вопросы на собесе:** "построй модель угроз для нашего сервиса" → DFD → STRIDE по каждому элементу → контрмеры
> **DoS** – Denial of Service (отказ в обслуживании)

> **DREAD** – Damage, Reproducibility, Exploitability, Affected users, Discoverability (ущерб, воспроизводимость, эксплуатируемость, затронутые пользователи, обнаруживаемость)

> **STRIDE** – Spoofing, Tampering, Repudiation, Information disclosure, Denial of service, Elevation of privilege (подмена, вмешательство, отказ, раскрытие информации, отказ в обслуживании, повышение привилегий)

> **DFD** – Data Flow Diagram (диаграмма потоков данных)


### Инструменты (SAST/DAST/SCA)
- **SAST** – статически, без запуска, много false positives
- **DAST** – динамически, чёрный ящик, нужен запуск
- **IAST** – агент в runtime, точно
- **RASP** – защита в рантайме, блокирует атаки
- **SCA** – зависимости, CVE, лицензии
- **SBOM** – список компонентов (SPDX/CycloneDX), для реакции на CVE
> **SPDX** – Software Package Data Exchange (формат обмена данными о пакетах ПО (Linux Foundation))

> **CVE** – Common Vulnerabilities and Exposures (общие уязвимости и факторы воздействия (реестр известных уязвимостей))

> **SBOM** – Software Bill of Materials (ведомость (спецификация) состава программного обеспечения)


### CVE-процесс
- **CVE-YYYY-NNNN** – идентификатор
- **Где искать:** NVD, cve.org, GitHub Advisory, OSV, БДУ ФСТЭК
- **Реакция:** detect → assess (SBOM!) → prioritize (CVSS+EPSS) → mitigate (патч/контрмеры) → verify → document
- **Log4j (CVE-2021-44228):** критичная, эксплуатируемая, патч 2.17.0
> **БДУ** – Threat Data Bank (банк данных угроз (ФСТЭК))

> **ФСТЭК** – Federal Service for Technical and Export Control (Федеральная служба по техническому и экспортному контролю)

> **OSV** – Open Source Vulnerabilities (открытая база уязвимостей открытого ПО (Google))

> **NVD** – National Vulnerability Database (национальная база данных уязвимостей (США, NIST))

> **EPSS** – Exploit Prediction Scoring System (система прогнозирования вероятности эксплуатации уязвимостей)

> **CVSS** – Common Vulnerability Scoring System (общая система оценки критичности уязвимостей (0-10))


### Приоритизация
- Сначала: Critical/High + эксплуатируемые + internet-facing
- Убрать false positives и тестовый код
- CVSS + EPSS + бизнес-контекст
- CISA KEV – активно эксплуатируемые
> **CISA** – Cybersecurity and Infrastructure Security Agency (Агентство по кибербезопасности и защите инфраструктуры (США))

> **KEV** – Known Exploited Vulnerabilities (каталог известных эксплуатируемых уязвимостей (CISA))


### Российское регулирование
- **ФЗ-152** – персональные данные, согласие, права субъекта, уведомление РКН
- **ГОСТ Р 57580** – финансы; **ГОСТ Р 56939** – безопасная разработка
- **ФСТЭК:** приказы 21 (ПДн), 17 (ГИС), 239 (КИИ), БДУ ФСТЭК
- **КИИ/ГосСОПКА** – для критической инфраструктуры
> **ГосСОПКА** – State System for Detection, Prevention and Elimination of Computer Attacks (государственная система обнаружения, предупреждения и ликвидации последствий компьютерных атак)

> **РКН** – Roskomnadzor (Federal Service for Supervision of Communications, IT and Mass Media) (Роскомнадзор (надзор в сфере связи, информационных технологий и массовых коммуникаций))

> **ПДн** – Personal Data (персональные данные)

> **ГИС** – State Information System (государственная информационная система)

> **КИИ** – Critical Information Infrastructure (критическая информационная инфраструктура)

> **ФЗ-152** – Federal Law No. 152 «On Personal Data» (федеральный закон №152 «О персональных данных»)

> **ГОСТ** – State Standard (государственный стандарт (РФ))


### Docker
- **Dockerfile:** FROM, RUN, COPY, WORKDIR, ENV, EXPOSE, USER, CMD
- **Образ** – шаблон, **контейнер** – экземпляр
- **Container Escape** – побег на хост (privileged, CVE в runc, docker.sock)
- **Безопасность:** non-root, --cap-drop ALL, read-only, сканирование (Trivy), подпись (Cosign)

### Git
- **merge** – ветвистая история, **rebase** – линейная (переписывает)
- **pull** = fetch + merge
- **Секреты:** .gitignore + gitleaks + git filter-repo для истории

### Мобильная безопасность
- Перехват: Burp + CA-сертификат + proxy
- SSL Pinning обход: Frida, objection, SSL Kill Switch
- Инструменты: Frida, MobSF, apktool, jadx, r2
> **CA** – Certificate Authority (центр сертификации (удостоверяющий центр))

> **SSL** – Secure Sockets Layer (протокол защищённых сокетов (предшественник TLS))
