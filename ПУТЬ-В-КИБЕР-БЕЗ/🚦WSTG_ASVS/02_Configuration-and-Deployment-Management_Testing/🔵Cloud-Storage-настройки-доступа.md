# WSTG-CONF-11 - Тестирование облачных хранилищ

## 1. Описание теста

Этот тест посвящен проверке безопасности облачных хранилищ (например, Amazon S3, Azure Blob Storage, Google Cloud Storage), которые используются приложением для хранения статики, пользовательских файлов, бэкапов и других данных. 

Основная проблема - неправильная настройка прав доступа, из-за которой хранилище становится общедоступным. Это позволяет любому читать, загружать, изменять или удалять файлы, что ведет к утечке данных, или к rce

------


##  Цели теста

1. **Обнаружить URL-адреса облачных хранилищ**, используемых приложением
   
2. **Проверить, можно ли прочитать файлы из хранилища** без авторизации

3. **Проверить, можно ли загрузить файлы** в хранилище без авторизации
   
4. **Проверить, можно ли удалить файлы** из хранилища без авторизации
   
5. **Оценить риски** утечки данных или компрометации через хранилище
   
--------


## Как выполнять тест 

### Шаг 1: Обнаружение URL хранилищ

#### В Black-box тестировании

Я ищу ссылки на облачные хранилища в HTTP-ответах приложения:

- В HTML-коде: `<img src="https://my-bucket.s3.amazonaws.com/puppy.png">`
   
- В CSS: `background-image: url(https://my-bucket.s3.amazonaws.com/background.jpg)`
   
- В JavaScript: ссылки на загрузку файлов или API
   
- В ответах API: JSON-поля с URL-адресами файлов

- Также перехватом запросов через прокси - бурп в помощь

- В коде приложения (если это мобилка)
   

#### В Gray-box тестировании

Если у меня есть доступ к исходному коду, конфигурациям или документации, я ищу там URL хранилищ, имена бакетов и ключи доступа

---------


#### также будет нужно найти формат URL для исследуемого облачного хранилища

-----

### Шаг 2: Проверка прав доступа через `curl` или прокси 

После того как я нашел URL бакета или конкретного объекта, я проверяю, какие операции доступны анонимн

#### Проверка чтения файла



```c
curl -X GET https://my-bucket.s3.amazonaws.com/sensitive-file.pdf
```

**Успех:** Если файл скачивается, значит бакет позволяет публичное чтение.

#### Проверка загрузки файла

```q
curl -X PUT -d "test" "https://my-bucket.s3.amazonaws.com/test.txt"
```

**Успех:** Если файл создается (ответ `200 OK` или `204 No Content`), значит бакет позволяет публичную запись. Это критическая уязвимость, т.к. можно загрузить шелл или вредоносный контент.

#### Проверка листинга бакета

Иногда бакет позволяет получить список всех объектов. Я пробую:

```c
curl -X GET https://my-bucket.s3.amazonaws.com/
```

**Успех:** Если я получаю XML-ответ со списком файлов (ListBucketResult), значит бакет открыт на листинг - это утечка информации о структуре данных


все это можно сделать через бурп или зап, перехватив оригинальные запросы и пробовать получать данные используя их

##  Интерпретация результатов

**Что считать успехом (находкой):**

- Обнаружено публично доступное хранилище с чувствительными данными (пароли, ключи, персональные данные пользователей)
- Возможность загрузить файлы в публичное хранилище (можно разместить вредоносный контент или попытаться выполнить RCE через файлы на сайте)
- Возможность удалить файлы из хранилища (риск потери данных)    
- Листинг содержимого бакета, который раскрывает структуру данных и имена файлов
  


## Важные нюансы

1. **Наличие публичного доступа - не всегда очевидно.** Бакет может быть закрыт для публичного чтения, но открыт для загрузки файлов (например, для формы на сайте). Проверяй все операции
   
2. **AWS S3 имеет два типа публичного доступа:** на уровне бакета (политика бакета) и на уровне отдельных объектов (ACL). Бакет может быть закрыт, но отдельные файлы могут быть открыты
   
3. **Загрузка файлов в бакет может быть опасной.** Если бакет используется для хранения файлов, которые потом отображаются на сайте, загрузка HTML-файла с JavaScript может привести к XSS-атаке или дефейсу, RCE
   
4. **Всегда проверяй, что бакет действительно открыт.** Иногда ошибка доступа может быть вызвана неверным регионом или неправильным URL, а не отсутствием прав
   
5. **Чувствительные данные могут быть в неочевидных местах.** Проверяй не только основной бакет, но и любые другие, которые упоминаются в коде или документации
