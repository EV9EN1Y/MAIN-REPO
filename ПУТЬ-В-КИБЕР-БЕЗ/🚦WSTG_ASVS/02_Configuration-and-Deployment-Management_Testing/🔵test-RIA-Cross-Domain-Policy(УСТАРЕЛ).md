

Раньше этот тест был посвящен проверке политик кросс-доменного доступа для **Rich Internet Applications (RIA)** - в основном, для приложений на **Adobe Flash** и **Microsoft Silverlight**. Эти технологии использовали специальные файлы политик (`crossdomain.xml` для Flash и `clientaccesspolicy.xml` для Silverlight), чтобы разрешать или запрещать доступ к ресурсам с других доменов

**Причина удаления:** Adobe Flash официально прекратил поддержку 31 декабря 2020 года, а Silverlight также давно не используется. Технологии, для которых этот тест был актуален, мертвы, поэтому OWASP решил удалить этот тест как устаревший



-----

в редких случаях ты можешь столкнуться со старыми системами, где эти файлы все еще есть

#### Файл `crossdomain.xml` (для Flash)

Этот файл размещался в корне сайта и определял правила кросс-доменных запросов. Опасная конфигурация выглядела так:

```xml
<cross-domain-policy>
    <allow-access-from domain="*" />
</cross-domain-policy>
```

Это разрешало **любому** сайту выполнять запросы к твоему ресурсу от имени пользователя, что вело к CSRF-атакам и краже данных

#### Файл `clientaccesspolicy.xml` (для Silverlight)

Аналогичный файл для Silverlight. Опасная конфигурация:

```xml
<?xml version="1.0" encoding="utf-8"?>
```
<access-policy>
    <cross-domain-access>
        <policy>
            <allow-from http-request-headers="*">
                <domain uri="*"/>
            </allow-from>
            <grant-to>
                <resource path="/" include-subpaths="true"/>
            </grant-to>
        </policy>
    </cross-domain-access>
</access-policy>

### Что тебе делать

1. **Пропусти этот тест** в своем конспекте как неактуальный
   
2. **Если ты тестируешь** очень старое приложение (2015 года и старше) и подозреваешь, что там используется Flash или Silverlight, проверь наличие этих файлов в корне веб-сервера: `https://example.com/crossdomain.xml` и `https://example.com/clientaccesspolicy.xml`
   
3. Если они есть и содержат `<allow-access-from domain="*" />` — задокументируй как критическую уязвимость
   
### Итог для твоего конспекта

- **WSTG-CONF-08 удален из актуальной версии OWASP WSTG**
   
- Вместо него можно просто запомнить: если встретишь старые технологии (Flash, Silverlight), проверь файлы политик кросс-доменного доступа
   
- В современных приложениях аналогичная функциональность реализуется через политику CORS (это отдельный большой тест)
