**WSTG-CONF-10: Test for Subdomain Takeover**(Тестирование на захват поддомена)

**Обнаружить все поддомены**, которые могут быть уязвимы к захвату

тест проверяет, можно ли захватить контроль над поддоменом цели. 

### Атака работает, если DNS-запись поддомена (например, CNAME или A) указывает на внешний ресурс (облачный сервис, хостинг), который больше не существует или был удалён, но сама DNS-запись осталась висеть!!

Злоумышленник может зарегистрировать этот ресурс (например, создать бакет в AWS S3 с тем же именем) и получить контроль над поддоменом, чтобы размещать на нём фишинговые сайты, воровать куки или подделывать контент

> **AWS S3 (Amazon Simple Storage Service)** - это обычное облако для хранения даных от амазон

=======================================================================
##  Цели теста

1. **Обнаружить все поддомены**, которые могут быть уязвимы к захвату
   
2. **Проверить каждую DNS-запись** (A, CNAME, MX, NS) на наличие внешних ресурсов, которые больше не существуют
   
3. **Подтвердить возможность захвата**, сверив ответ сервера с базой известных сигнатур уязвимых сервисов
-----------

-----

##  Как выполнять тест 

Этот тест состоит из трёх основных этапов: поиск поддоменов, автоматическая проверка и ручное подтверждение.

### 🔵 1: Поиск поддоменов (Enumeration)

Сначала мне нужно собрать как можно 3больше поддоменов цели. Для этого я использую ==инструменты пассивной и активной разведки==

**Инструменты:**

- **Subfinder:** Быстрый пассивный сбор поддоменов из открытых источников. `subfinder -d victim.com -o subdomains.txt`
   
- **Amass:** Более мощный инструмент для глубокого поиска поддоменов
   
- **dnsrecon:** Для активного перебора поддоменов через словари
   
- **dig/nslookup:** Для ручной проверки отдельных поддоменов

--------

### 🔵 2: Автоматическая проверка на уязвимость

На этом шаге я прогоняю список собранных поддоменов через специализированные сканеры, которые сравнивают HTTP-ответы с базой известных "дырных" сигнатур

**База сигнатур:** Проект **can-i-take-over-xyz** поддерживает базу данных с характерными ответами от разных сервисов (GitHub Pages, AWS S3, Heroku, Fastly, Azure и др.), когда запрошенный ресурс не существует

**Инструменты:**

- **Subzy:** Простой и быстрый сканер.
   
```c
subzy run --targets subdomains.txt
```

- **Nuclei:** Более точный и мощный сканер со специальными шаблонами для захвата поддоменов

```c
nuclei -l subdomains.txt -t takeovers/
```

**Что ищут эти инструменты:**

- Для **GitHub Pages**: ответ `HTTP/1.1 404 Not Found` с фразой `"There isn't a GitHub Pages site here."`
   
- Для **AWS S3**: ответ с ошибкой `NoSuchBucket`
   
- Для **Heroku**: ответ `HTTP/1.1 404 Not Found` с фразой `"No such app"`
   
- Для **Azure App Service**: характерные страницы ошибок 404

---------

### 🔵  3: Ручное подтверждение (Validation)

Автоматические сканеры дают ложные срабатывания. Поэтому каждую находку я проверю вручную

**Что я делаю:**

1. Проверяю DNS-запись и куда она ведёт:
 
```q
dig CNAME subdomain.victim.com
```
2. Отправляю HTTP-запрос к поддомену и смотрю на ответ:

```q
curl -i http://subdomain.victim.com
```

3. Сравниваю полученный ответ с сигнатурами из базы **can-i-take-over-xyz**
   
4. Проверяю, действительно ли ресурс никем не занят (но не пытаюсь его зарегистрировать без разрешения!)
   
---------

**Что считать успехом (находкой):**

- DNS-запись поддомена указывает на внешний сервис, а сам поддомен возвращает ошибку, характерную для незанятого ресурса
   
- Подтверждено, что ресурс не существует (например, бакет AWS S3 не найден, проект GitHub Pages удалён)
   
- Есть возможность зарегистрировать этот ресурс (но я этого не делаю без письменного разрешения)
   
**Как я документирую:**

- Уязвимый поддомен (например, `coderepo.victim.com`)
   
- Тип DNS-записи (например, `CNAME`)
   
- Внешний сервис, на который указывает запись (например, `username.github.io`)
   
- Код ответа и строка ошибки (например, `404 Not Found: "There isn't a GitHub Pages site here."`)
   
- Потенциальное воздействие (например, фишинг, кража сессий, XSS)
   
- Рекомендация: удалить устаревшую DNS-запись
   
##  Инструменты

|Инструмент|Применение|
|---|---|
|**Subfinder**|Пассивный сбор поддоменов|
|**Amass**|Глубокое перечисление поддоменов (пассивное и активное)|
|**dnsrecon**|Активный перебор поддоменов|
|**Subzy**|Быстрая автоматическая проверка на захват|
|**Nuclei**|Точная проверка с использованием шаблонов takeovers|
|**Dig / nslookup**|Ручная проверка DNS-записей|
|**Curl**|Ручная проверка HTTP-ответа поддомена|
|**can-i-take-over-xyz**|База данных сигнатур для автоматических инструментов|

## Примеры атак

**Пример 1: GitHub Pages**

Цель: `coderepo.victim.com`  
DNS-запись: `CNAME coderepo.victim.com -> pizdatiy.github.io`  
Ситуация: Владелец удалил проект на GitHub, но забыл удалить CNAME-запись.  
Ответ: `404 Not Found: "There isn't a GitHub Pages site here."`  
Атака: Злоумышленник создаёт на GitHub Pages сайт с именем `pizdatiy` и получает контроль над `coderepo.victim.com`

**Пример 2: AWS S3**

Цель: `assets.victim.com`  
DNS-запись: `CNAME assets.victim.com -> bucket.s3.amazonaws.com`  
Ситуация: Владелец удалил S3-бакет `bucket`, но оставил запись  
Ответ: `NoSuchBucket`  
Атака: Злоумышленник создаёт S3-бакет с именем `bucket` в любом регионе и заливает туда свой контент

**Пример 3: Просроченный домен**

Цель: `www.victim.com`  
DNS-запись: `CNAME www.victim.com -> victimotherdomain.com`  
Ситуация: Домен `victimotherdomain.com` истёк и стал доступен для регистрации.  
Атака: Злоумышленник регистрирует `victimotherdomain.com` и получает контроль над `www.victim.com`

##  Важные нюансы

1. **Не все уязвимые поддомены видны.** Иногда запись указывает на IP-адрес (A-запись), и ресурс может быть недоступен, но без HTTP-ответа сложно подтвердить уязвимость
    
2. **Некоторые сервисы меняют сигнатуры.** Базу `can-i-take-over-xyz` нужно обновлять, так как провайдеры могут менять тексты ошибок
    
3. **Не пытайся зарегистрировать ресурс!** Это может быть расценено как злонамеренное действие и нарушить условия тестирования
    
4. **NS-записи особенно опасны.** Если NS-запись указывает на внешнего провайдера, а тот удалил зону, захват даёт контроль над всем доменом
