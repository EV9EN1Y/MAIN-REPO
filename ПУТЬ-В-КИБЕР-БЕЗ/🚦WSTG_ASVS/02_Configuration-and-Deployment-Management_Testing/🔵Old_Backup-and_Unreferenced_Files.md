# Review Old Backup and Unreferenced Files for Sensitive Information
#### (Проверка старых, бэкапных и неиспользуемых файлов на наличие чувствительной информации)

То есть это грубо говоря дурацкий баг- что кто-то возможно когда-то в прошлом делал какой-то бэкап и он почему-то был в открытом виде в сети и почему-то как-то так случилось что про него забыли, я могу его найти...

-----
тест посвящён поиску файлов, которые не должны находиться в веб-доступных каталогах, но по ошибке или небрежности там оказались. Это могут быть старые версии файлов, автоматические бэкапы, созданные редакторами или администраторами, временные файлы, архивы, логи и другие "забытые" артефакты

#### Цели теста

1. **Обнаружить старые, бэкапные и неиспользуемые файлы** в веб-доступных каталогах
   
2. **Проанализировать найденные файлы** на наличие чувствительной информации (исходный код, пароли, пути, логи)
   
3. **Выявить файлы, которые могут быть выполнены или обработаны сервером небезопасным образом** (например, отдача исходного кода вместо его выполнения)

# Специализированные утилиты для Теста !!

- **Backup-Finder (Burp Suite Extension)**: Это расширение для Burp Suite генерирует **динамические пейлоады** на основе структуры сайта, а не просто прогоняет статический словарь [](https://github.com/mdiqbalahmad/Backup-Finder). Например, если он находит каталог `/upload`, он сам проверит `/upload/upload.zip`, `/upload/index.php~` и т.д. [](https://github.com/eraldkaraj/Backup-Finder). Это делает его **самым умным**инструментом в этой категории. Устанавливается через BApp Store или вручную через JAR-файл [](https://github.com/mdiqbalahmad/Backup-Finder)
   
- **BackupFinder (Go)**: Отдельная консольная утилита, которая тоже генерирует тысячи потенциальных имен бэкап-файлов на основе целевого домена [](https://github.com/MuhammadWaseem29/BackupFinder). Использует ==92 паттерна== в базовом режиме и более ==1900== - в расширенном (`-w`). Команда для базового скана: `backupfinder -u https://example.com` [](https://github.com/MuhammadWaseem29/BackupFinder)
   
- **Nuclei Template (backup-file-finder)**: Если используешь фреймворк для сканирования **Nuclei**, для него есть готовая и популярная конфигурация (темплейт) для поиска бэкап-файлов [](https://github.com/valaDevs/nuclei-backupfile-finder). Запускается командой `nuclei -u https://example.com -t backup-file-finder.yaml` [](https://github.com/valaDevs/nuclei-backupfile-finder). Удобно, если ты уже работаешь в экосистеме Nuclei

- **Acunetix**: Коммерческий сканер, который имеет **высокую точность** в обнаружении старых, бэкапных и неиспользуемых файлов [](https://www.acunetix.com/blog/news/acunetix-comparison-web-application-scanners/?msclkid=681f5fc5289211e1d4e13a0e2538a64e&utm_campaign=414009479&utm_campaign=414009479&utm_content=1327112178351709&utm_content=1327112178351709&utm_medium=cpc&utm_medium=cpc&utm_source=bing&utm_source=bing&utm_term=scan%20vulnerability&utm_term=scan%20vulnerability)
   
- **Burp Suite Scanner**: Встроенный сканер в Burp Suite имеет специальную проверку (BChecks) для поиска бэкап-файлов [](https://portswigger.net/burp/documentation/scanner/bchecks/worked-examples/path#step-2-configure-file-extensions). Он проверяет наличие файлов с типичными расширениями бэкапов и минимизирует ложные срабатывания [](https://portswigger.net/burp/documentation/scanner/bchecks/worked-examples/path#step-2-configure-file-extensions)
   
- **Wapiti**: Бесплатный сканер, входящий в Kali Linux, который может искать копии (бэкапы) скриптов на сервере [](https://www.kali.org/tools/wapiti/?utm_source=toolkitly&utm_medium=marketplace&utm_campaign=toolkitly)

### Шаг 1: Логический анализ структуры приложения

   изучаю структуру URL и имена файлов, чтобы понять логику именования. Если я вижу файл `viewuser.php`, я логически предполагаю существование `adduser.php`, `edituser.php`, `deleteuser.php`. Я проверяю эти предположения, переходя по соответствующим адресам

### Шаг 2: Поиск подсказок в опубликованном контенте

Я просматриваю исходный код HTML, JavaScript и CSS страниц в поисках закомментированных ссылок, скрытых форм, путей к неиспользуемым файлам

**Что я ищу:**

- Закомментированные HTML-ссылки: `<!-- <A HREF="uploadfile.jsp">Загрузить файл</A> -->`
   
- JavaScript-код, который создаёт ссылки на неочевидные страницы (например, панель администратора, доступная только при определённых условиях)
   
- Скрытые поля или кнопки в формах
   
- Пути к файлам в CSS-стилях

### Шаг 3: Использование файла robots.txt

Я всегда проверяю файл `robots.txt`, который часто содержит директивы для поисковых роботов и может раскрывать скрытые каталоги:

```q
User-agent: *
Disallow: /Admin
Disallow: /uploads
Disallow: /backup
Disallow: /include
```
### Шаг 4: Угадывание имён файлов (Blind Guessing)

Это ключевой метод. Я использую списки (словари) для перебора возможных имён файлов и каталогов. Основные техники:

**Использование стандартных словарей:**

- Запускаю `Gobuster` или `dirb` со словарями, которые содержат общие имена файлов и каталогов

[[gobuster]] - здесь подробнее

- Использую расширения: `.bak`, `.old`, `.zip`, `.tar`, `.gz`, `~`, `.swp`, `.txt`, `.src`, `.dev`, `.inc`, `.orig`, `.copy`, `.tmp`, `.log`
   

**Кастомизация словаря:**

- На основе найденных файлов создаю свой список. Например, если я нашёл `index.php`, я проверяю `index.php.bak`, `index.php~`, `index.old`, `index.php.old`, `index.txt`
   
- Подставляю все возможные расширения до и после оригинального расширения
   

**Использование расширений редакторов:**

- Для `file.php` я проверяю `file.php~` (бэкап Emacs), `file.php.swp` (бэкап Vim), `file.php.bak` (общее), `file.php.old`
   

### Шаг 5: Поиск архивов и бэкапов

Особое внимание я уделяю поиску архивов (`.zip`, `.tar`, `.tar.gz`, `.tgz`, `.rar`, `.7z`). Если я найду архив в корне сайта или в одном из каталогов, он может содержать полную копию всего приложения, включая исходники и конфиги


### Шаг 6: Проверка системных снимков (snapshots)

Некоторые файловые системы (например, ZFS, NetApp, некоторые NAS) создают автоматические снимки каталогов. Они могут быть доступны через пути типа `/.snapshot/`, `/.zfs/snapshot/` или `~/.snapshot/`. Я проверяю такие пути, если подозреваю, что сервер использует подобные технологии

-----
### Шаг 7: Использование поисковых систем

Я использую Google или другие поисковики для поиска страниц, которые уже не связаны с основным сайтом, но всё ещё существуют и были проиндексированы

**Полезные операторы Google:**

- `site:example.com` - найти все страницы на домене
    
- `site:example.com filetype:bak` - найти файлы с расширением `.bak`
    
- `site:example.com "index of"` - найти открытые директории
    
- `site:example.com intitle:"backup"` - найти страницы с заголовком "backup"




### Шаг 8: Проверка на 8.3-имена (Windows)

Если сервер работает на Windows, я проверяю доступность файлов по их сокращённым 8.3-именам (см. отдельный тест WSTG-CONF-03 для деталей). Это может помочь обойти фильтры и получить доступ к файлам, которые защищены по полному имени
