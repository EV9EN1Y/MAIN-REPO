тест проверяет наличие и корректность заголовка **Strict-Transport-Security** (HSTS). 
HSTS - это механизм, который заставляет браузер **всегда** использовать HTTPS для подключения к сайту, даже если пользователь вводит `http://` в адресной строке или переходит по HTTP-ссылке. 

Это защищает от атак типа "понижение протокола" (SSL stripping), когда злоумышленник пытается перехватить трафик, заставив браузер использовать незащищённое HTTP-соединение

## Цели теста

1. **Проверить наличие** заголовка `Strict-Transport-Security` в ответе сервера
   
2. **Проверить параметры** заголовка: значение `max-age`, наличие `includeSubDomains` и `preload`
   
3. **Убедиться, что настройки соответствуют политике безопасности** (достаточное время жизни, покрытие поддоменов)
----

 
>- **Strict-Transport-Security** - принудительно переводит браузер на HTTPS, блокируя попытки подключения по незащищенному протоколу. Главный щит от MITM-атак.
    
>- **max-age** - время жизни HSTS-политики в секундах. Указывает браузеру, как долго он должен запоминать, что сайт открывается только через HTTPS.
    
>- **includeSubDomains** - флаг, который распространяет действие HSTS на все поддомены сайта. Защищает всю инфраструктуру в зоне домена.
    
>- **preload** - неофициальный, но важный флаг. Сообщает браузерам, что домен уже включен в их встроенный список HSTS. Браузер будет использовать HTTPS даже при первом посещении.

-------

**то считать успехом (находкой):**

- **Заголовок отсутствует** - критическая проблема: пользователи не защищены от MITM-атак
   
- **`max-age` слишком маленькое** (например, 3600 или 86400) - недостаточная защита
   
- **Отсутствует `includeSubDomains`** - поддомены не защищены
   
- **Заголовок присутствует только на главной странице**, но не на всех поддоменах (нужно проверять отдельно)

# выполнение теста

### Шаг 1: Проверка наличия заголовка

```q
curl -s -D- https://example.com | grep -i "strict-transport-security"

или в прокси проверить ответ сервера..

должно быть в ответе примерно так 
Strict-Transport-Security: max-age=31536000; includeSubDomains окей
```


--------

### Шаг 2: Проверка параметров заголовка


#### 🔵 `max-age`

- Значение в секундах, в течение которого браузер должен запоминать, что сайт нужно открывать только через HTTPS
   
- **Минимально рекомендуемое значение:** 31536000 (1 год)
   
- **Критично низкое:** меньше 30 дней (2592000) - недостаточная защита
   

#### 🔵 `includeSubDomains`

- Опциональный флаг
   
- Если есть - HSTS действует на все поддомены (например, `admin.example.com`, `api.example.com`)
   
- **Рекомендуется:** всегда включать, чтобы защитить всю инфраструктуру
   

#### 🔵 `preload`

- Неофициальный флаг, но поддерживается браузерами
   
- Указывает, что домен включён в предустановленный список HSTS  - hstspreload.org
   
- Браузеры будут использовать HSTS даже при первом посещении, без первого запроса

------------

### Шаг 3: Проверка наличия HSTS через HTTP

Важно: HSTS **не действует** при подключении по HTTP. Если я делаю запрос по HTTP, заголовка HSTS не будет. Поэтому я всегда проверяю только через HTTPS:

```q
curl -s -D- https://example.com | grep -i HSTS
```


--------

### Шаг 4: Проверка возможности обхода HSTS

Если сайт поддерживает HSTS, я проверяю, не может ли пользователь обойти защиту, если у него есть старый HTTP-закладка или если он переходит по HTTP-ссылке. Для этого я делаю запрос по HTTP и смотрю, происходит ли редирект на HTTPS:

```q
curl -v http://example.com
```

Если я вижу `301 Moved Permanently` или `302 Found` с `Location: https://example.com/` — это хорошо, но HSTS добавляет защиту даже на уровне браузера, без необходимости редиректа с сервера


----------





```c
Базовый минимум:

Strict-Transport-Security: max-age=31536000




Рекомендуемый для продакшена:

Strict-Transport-Security: max-age=31536000; includeSubDomains




Для включения в Preload List ([hstspreload.org](https://hstspreload.org/)):

Strict-Transport-Security: max-age=31536000; includeSubDomains; preload



```




1. **HSTS действует только для HTTPS-запросов.** Чтобы он вступил в силу, пользователь должен хотя бы раз открыть сайт по HTTPS
   
2. **`preload` требует осторожности.** Включение в предустановленный список означает, что браузеры никогда не смогут подключиться по HTTP - это нельзя быстро отменить
   
3. **Проверяй HSTS на всех поддоменах.** Если у тебя есть `admin.example.com`, а HSTS настроен только для `example.com` без `includeSubDomains`, поддомен не защищён
   
4. **Убедись, что `max-age` - это разумное значение.** 1 год (31536000) - стандарт. Меньше - снижает защиту
