
тест посвящен анализу безопасности конфигурации всей сетевой инфраструктуры, на которой работает веб-приложение. Сюда входят веб-серверы, базы данных, системы аутентификации, обратные прокси и другие компоненты. Если где-то в этой цепочке есть слабое звено (например, старая версия веб-сервера с известной уязвимостью или административный интерфейс с дефолтным паролем), это может скомпрометировать всё приложение, даже если само приложение написано идеально

Ошибки в конфигурации сетевых компонентов (веб-сервер, база данных, прокси) часто приводят к утечке данных, удаленному выполнению кода или полной компрометации сервера


## Цели теста

1. **Проверить конфигурацию сетевых компонентов** на наличие известных уязвимостей
    
2. **Выявить небезопасные настройки** по умолчанию (логины/пароли, открытые порты, излишние сервисы)
    
3. **Оценить безопасность административных интерфейсов** и инструментов управления
    
4. **Проверить актуальность ПО** и наличие необходимых патчей безопасности
    
5. **Составить список необходимых портов** и проверить, не открыто ли лишнее

### Проверка на известные уязвимости

- **Nmap** со скриптами vuln:

   ```q
   nmap -sV --script vuln 93.184.216.34

   ```
- **`-sV`**: Эта часть команды говорит Nmap «определи версию ПО» [](https://nmap.org/nsedoc/scripts/vulners.html). Это критично, потому что уязвимости привязаны к конкретным версиям.
    
- **`--script vuln`**: А это команда «исполнить все скрипты из категории `vuln`» . Скрипт `vuln`(или его расширенная версия `vulners`) затем берёт определённые версии софта (Apache, MySQL, OpenSSH) и проверяет их по базе данных уязвимостей

здесь подробнее [[NMAP]]

-----

- **Nikto** для веб-сервера:
   
 ```q
   nikto -h https://example.com
 ```

подробнее в этом файле про - > [[Nikto]]


- **Поиск в базах данных:** NVD (NIST), Exploit-DB, CVE Mitre, а также поиск через `searchsploit` в Kali

**он ищет:**

- **Устаревшее ПО:** «например,  Apache версии 2.4.6, а ему уже 8 лет. Пора обновляться!»
   
- **Служебные файлы:** Находки типа `/phpinfo.php`, которые раскрывают конфигурацию сервера, или `/manual/` с открытым листингом директорий
   
- **Стандартные конфигурации:** Например, определение панели администратора WordPress (`/wp-admin/`), которая может быть точкой входа для брутфорса 
   
- **Опасные методы HTTP:** Проверяет, не разрешены ли потенциально опасные методы запросов

### Анализ административных интерфейсов

если административные панели доступны из интернета
то нужно их проверить!

- Есть ли стандартные логины/пароли: `admin/admin`, `root/root`, `tomcat/tomcat`

- Можно ли получить доступ к панели управления (например, `/admin`, `/webadmin`, `/cpanel`, `/phpmyadmin`)
   
- Используется ли HTTPS для административных интерфейсов
   
- Есть ли защита от брутфорса (CAPTCHA, ограничение попыток)
   
- Ограничен ли доступ по IP-адресам

### Проверка открытых портов и сервисов

сканирование сетевых порты, чтобы убедиться, что открыты только необходимые для работы приложения

```q
nmap -p- -sV -T2 93.184.216.34
```

подробнее здесь [[NMAP]]

- **22/tcp (SSH):** если открыт, можно ли подключиться с пустым паролем? Есть ли защита от брутфорса (fail2ban)?
   
- **21/tcp (FTP):** разрешен ли анонимный доступ?
   
- **3306/tcp (MySQL), 5432/tcp (PostgreSQL):** открыты ли базы данных наружу? Это грубая ошибка конфигурации
   
- **8080/tcp, 8443/tcp, 9000/tcp:** часто используются для админок или альтернативных веб-интерфейсов
   
- **Нестандартные порты:** любые открытые порты я проверяю на предмет того, что это за сервис
   

**Вывод:** я составляю список "разрешенных" портов и сравниваю с реальностью. Всё, что не нужно - должно быть закрыто файрволом

### Проверка конфигурации TLS/SSL (если применимо)

Если приложение использует HTTPS, я проверяю настройки TLS

```q
testssl.sh https://example.com
```

**Что проверяю:**

- Используются ли устаревшие протоколы (SSLv2, SSLv3, TLSv1.0)
- Используются ли слабые шифры (с длиной ключа < 128 бит)
- Правильно ли настроены заголовки HSTS, CSP, X-Content-Type-Options

подробнее про testssl в этом файле [[testssl_sh]]

### Тестирование безопасности административных протоколов

Администрирование часто ведется по FTP, WebDAV, NFS, SMB. Я проверяю:

- Используется ли шифрование (FTP → SFTP/FTPS)
- Доступны ли эти сервисы из интернета
- Используются ли стандартные учетные данные
