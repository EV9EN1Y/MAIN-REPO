# Enumerate Infrastructure and Application Admin Interfaces
# WSTG-CONF-05 - Перечисление административных интерфейсов


тест посвящён поиску скрытых или недостаточно защищённых административных интерфейсов. Речь идёт о панелях управления, которые позволяют привилегированным пользователям выполнять действия, меняющие работу сайта: управление учётными записями, изменение дизайна, настройка конфигурации, работа с данными. Часто такие интерфейсы плохо защищены, используют стандартные пути или слабые пароли, что делает их лёгкой добычей для атакующего

-----

- **Не все админ-панели видны снаружи.** Иногда доступ ограничен по IP-адресу. Я проверяю, могу ли я получить доступ к странице, если нахожусь в той же сети, или через прокси/обход
   
- **Наличие админ-панели не всегда уязвимость.** Но если она не защищена должным образом - это критическая проблема
   
- **Брутфорс может привести к блокировке.** Я всегда согласовываю такие тесты с заказчиком и использую осторожные настройки (задержки, малые объёмы попыток)
   
- **Ошибки при входе (400, 500) могут раскрывать информацию.** Я анализирую ответы сервера, чтобы понять, есть ли аутентификация и где её можно обойти

--------

## Цели теста

1. **Обнаружить все административные интерфейсы**, связанные с приложением и инфраструктурой
    
2. **Проверить, доступны ли они из интернета** или защищены (например, по IP)
    
3. **Проверить, используют ли они стандартные учётные данные** или слабые пароли
    
4. **Выявить, можно ли обойти аутентификацию** или получить доступ без прав администратора

----------

# как выполнить тест

### Шаг 1: Перебор стандартных путей

Я использую словари для поиска стандартных путей к админ-панелям:

- `/admin`, `/administrator`, `/manager`, `/webadmin`, `/cpanel`
    
- `/wp-admin/` (WordPress), `/administrator/` (Joomla), `/admin/` (Drupal)
    
- `/manager/html` (Tomcat), `/server-status` (Apache), `/nginx_status` (Nginx)
    
- `/phpmyadmin`, `/mysqladmin`, `/dbadmin` (инструменты управления БД)
    

**Инструменты:** Gobuster, dirb, ZAP Forced Browse, или в бурпе вручную подключить словари и искать через интрудер со своим скриптом


**Пример:**

здесь подробнее файл про Gobuster = [[gobuster]]

```c
gobuster dir -u https://example.com -w /usr/share/wordlists/dirb/common.txt -x php,html,asp
```

------

### Шаг 2: Поиск подсказок в коде и комментариях

Я просматриваю HTML и JavaScript-код страниц в поисках ссылок на админ-панели:

```q
<!-- <a href="/admin_old/login.php">Admin Login</a> -->
```

```js
if (user.isAdmin) {
    window.location.href = "/dashboard/admin/";
}
```

также можно использовать программу [[URL-map]]  - ищет в html пути

-----
### Шаг 3: Проверка нестандартных портов

Иногда административные интерфейсы висят на других портах, чтобы их было сложнее найти. 
Я сканирую порты сервера (см. WSTG-CONF-01) в поисках веб-интерфейсов на портах 8080, 8443, 9000, 8888 и других


-------

### Шаг 4: Использование Google-операторов (Google Dorks)

использование поисковых систем для поиска страниц, которые не должны быть публично доступны:

- `site:example.com inurl:admin`
   
- `site:example.com inurl:login`
   
- `site:example.com intitle:"admin"`

------

### Шаг 5: Проверка защиты от брутфорса

Если я нашёл админ-панель с формой входа, я проверяю, есть ли защита от подбора паролей: CAPTCHA, ограничение попыток, блокировка по IP. Если защиты нет - это потенциальная уязвимость для атаки перебором

это большая дыра, так как если ее нет - или если она слабая - то нет особой сложности это обойти или угадать, вопрос времени

-----

### Шаг 6: Проверка возможности обойти аутентификацию

Я пробую:

- Подставить параметр `admin=true` или `useradmin=1` в URL, тело POST-запроса или Cookie
   
- Использовать стандартные пары логин/пароль: `admin/admin`, `admin/123456`, `root/root`, `administrator/password`
   
- Попытаться получить доступ к файлам, которые не должны быть доступны без авторизации (например, `/admin/index.php` минуя `/admin/login.php`)

	обход этапов проверки

	Атака одним пакетом (Single-packet attack)

	можно написать скрипт который будет обходить слабую защиту на количество попыток входа

	убрать токены или куки

	подобрать 4х-значные коды

	отправить код смены пароля на чужой емейл адресс

	стандартные пароли

	возможно на микросекунду подгружается часть страницы админки из-за логической ошибки

##  Инструменты

| Инструмент                | Применение                                      |
| ------------------------- | ----------------------------------------------- |
| **Gobuster / dirb**       | Перебор стандартных путей к админкам            |
| **ZAP (Forced Browse)**   | Автоматический поиск скрытых каталогов и файлов |
| **Burp Suite (Intruder)** | Перебор параметров для обхода аутентификации    |
| **THC-HYDRA**             | Брутфорс паролей на найденных формах входа      |
| **Google Dorks**          | Поиск административных страниц через Google     |
| **Nmap**                  | Сканирование нестандартных портов               |
