

задача - найти и проанализировать служебные файлы на веб-сервере. Они могут выдать скрытые разделы сайта, его структуру, технологии и контакты разработчиков, что значительно упрощает дальнейшее тестирование

####  Цели теста

1. **Обнаружить скрытые пути и функциональность** сайта, которые не предназначены для публичного доступа
   
2. **Собрать дополнительную информацию** о технологиях и людях, стоящих за проектом
   

---

### Что конкретно искать и как это делать



#### 1. Файл `robots.txt` (самый важный)

- **Где лежит**: Всегда в корневой директории сайта. Пример: `https://example.com/robots.txt`
    
- **Как проверить**:
 
    ```bash
    curl -O -Ss https://example.com/robots.txt && cat robots.txt
    ```
   
   Иkи просто открыть в браузере.
   
- **Что мы ищем**: Директиву **`Disallow`**. Она показывает, какие папки или файлы администратор просит поисковых роботов не индексировать. Как правило, это скрытые, тестовые или административные разделы
    
- **Пример**:

 ```c
    User-agent: *
    Disallow: /admin/
    Disallow: /backup/
    Disallow: /private/
 ```
    
- **Что делать с этим**: `Disallow` - это не технический запрет, а скорее "вежливая просьба". Злоумышленники и пентестеры эти "просьбы" игнорируют. Следовательно, ты **должен попытаться открыть** все перечисленные в `Disallow` пути в браузере или через `curl`. Скорее всего, ты найдёшь там что-то интересное


#### 2. Файл `sitemap.xml`

- **Где лежит**: Обычно в корне сайта. Пример: `https://example.com/sitemap.xml`. Может быть несколько файлов, например, `sitemap_index.xml`, или лежать в подпапках.
    
- **Как проверить**:

    ```bash
    wget --no-verbose https://www.google.com/sitemap.xml && head -n20 sitemap.xml
    ```
    
- **Что мы ищем**: Это карта сайта, созданная для поисковиков. В ней перечислены все URL-адреса, которые разработчик считает важными.
    
- **Что делать с этим**: Это  готовый "список целей". Все ссылки из `sitemap.xml` нужно проверить. Среди них могут быть:
    
    - Страницы, до которых сложно добраться через обычную навигацию
      
    - Старые версии страниц
      
    - Ссылки на файлы (PDF, DOCX), которые тоже стоит проверить
      

#### 3. Файл `security.txt`

- **Где лежит**: В корне сайта или в папке `/.well-known/`. Примеры:
    
    - `https://example.com/security.txt`
        
    - `https://example.com/.well-known/security.txt`
        
- **Как проверить**:

    
    ```q
    wget --no-verbose https://example.com/.well-known/security.txt && cat security.txt
    ```
    
- **Что мы ищем**: Этот файл содержит контактную информацию для сообщений об уязвимостях. В нём могут быть:
    
    - **Email** для связи (`Contact: mailto:security@example.com`)
        
    - **Ссылка на политику безопасности** (`Policy: https://example.com/security-policy`)
        
    - **OpenPGP-ключ** для шифрования сообщений
        
- **Что делать с этим**:
    
    - **OSINT (разведка)**: Найти контакты, имена людей, их должности, что может пригодиться для социальной инженерии
        
    - **Bug Bounty**: Если указана программа вознаграждений, это легальный способ поиска уязвимостей
        
    - **Проверить PGP-ключ**: Если он есть, скачать и посмотреть метаданные (ID, дату создания, имя владельца). Это тоже информация о людях
        

#### 4. Файл `humans.txt`

- **Где лежит**: В корне сайта. Пример: `https://example.com/humans.txt`
    
- **как проверить**

    ```c
    wget --no-verbose https://www.google.com/humans.txt && cat humans.txt
    ```
    
- **Что мы ищем**: Этот файл создаётся, чтобы рассказать о людях, которые делали сайт. В нём часто пишут имена, должности, ссылки на соцсет
   
- **Что делать с этим**: Использовать для OSINT и социальной инженерии. Если ты знаешь, кто в команде, можно попытаться найти их другие аккаунты или использовать имена в фишинговых атаках
   
-----

#### 5. Мета-теги в HTML-коде страниц

- **Где лежит**: Внутри каждой HTML-страницы, в секции `<head>`. Найти можно, посмотрев "Исходный код страницы" в браузере
    
- **Что мы ищем**:
    
    - `<meta name="robots" content="noindex, nofollow">` - говорит поисковикам не индексировать страницу. Если такая страница доступна, её тоже надо проверить
      
    - Другие мета-теги, например, **Open Graph** (`og:title`, `og:description`), **Twitter Cards**, а также `apple-mobile-web-app-title`, `msapplication-TileColor`
        
- **Что делать с этим**: Эти теги могут выдать:
    
    - Используемые технологии и CMS (по специфичным для них мета-тегам)
      
    - Дополнительные пути к изображениям или другим ресурсам
      
    - ID приложений в соцсетях (например, `fb:app_id`), что может быть полезно для OSINT
        

#### 6. Папка `/.well-known/`

- **Где лежит**: В корне сайта. Пример: `https://example.com/.well-known/`
    
- **Что мы ищем**: Это стандартизированная папка для различных файлов конфигурации, описанных в RFC. Кроме `security.txt`, там могут быть и другие файлы, например, для подтверждения владения доменом, настройки прав доступа и т.д
    
- **Что делать с этим**: Полный список стандартных файлов для этой папки можно найти в реестре IANA. Тестировщик может использовать этот список, чтобы попытаться найти дополнительные информативные файлы. Это уже более продвинутый уровень
    

---

###  Инструменты, которые  понадобятся

1. **Браузер и его инструменты разработчика** (F12) для просмотра кода страниц.
   
2. **`curl` и `wget`** в командной строке для прямых запросов к серверу.
   
3. **Burp Suite** или **OWASP ZAP**: Их сканеры автоматически находят эти файлы и парсят их, экономя  время (просто тыкаю везде сайт - и получаю карту всех мест - где был)

4. **`urlmap`** - это быстрый консольный краулер на Go[](https://github.com/aoshimash/urlmap), а `webpalm` может не только построить дерево сайта, но и извлечь структурированные данные
Он автоматически строит карту сайта, проходя по всем ссылкам, которые находит на каждой странице

## urlmap


установка  urlmap
```c

cd ~/Downloads
# Скачай архив
curl -L -o urlmap.tar.gz https://github.com/aoshimash/urlmap/releases/latest/download/urlmap-darwin-arm64.tar.gz

# Распаковка чееек
tar -xzvf urlmap.tar.gz

# 1.  права на выполнение
chmod +x urlmap-darwin-arm64
# 2. Переместить в системную папку (чтобы можно было запускать из любого места)
sudo mv urlmap-darwin-arm64 /usr/local/bin/urlmap
# 3. проверочка
urlmap --help
```

запуск 
```c
# Базовое сканирование
urlmap https://example.com

# С ограничением глубины и ускорением
urlmap https://example.com --depth 3 --concurrent 20

----------
ЭТИЧНЫЙ ЗАПУСК


urlmap https://example.com --depth 2 --concurrent 1 --rate-limit 1

- Ограничит глубину обхода до 2 уровней.
    
- Будет отправлять по одному запросу за раз.
    
- Не превысит скорость в 1 запрос в секунду.

```

настройки скорости и глубины
```c
### Глубина сканирования
- `--depth 1` — проверит только главную страницу и ссылки на ней.
    
- `--depth 2` — перейдет по ссылкам с главной, а затем по ссылкам с этих страниц.
    
- `--depth 5` (по умолчанию) — базовый уровень для средних сайтов.
    
- `--depth 0` — бесконечная глубина (обойдет весь сайт)
  
  
  --------------
  
  
  ### Ускорение сканирования
- `--concurrent 5` (по умолчанию) — безопасный режим.
    
- `--concurrent 20` — ускоряет процесс, но может быть заметен для сервера.
    
- `--concurrent 50` — агрессивный режим, может вызвать блокировку
  
  
```


**Полезные опции:**

- `--depth 3` — ограничить глубину обхода (сколько уровней вложенности пройти) [](https://github.com/aoshimash/urlmap).
    
- `--concurrent 20` — использовать больше одновременных потоков для ускорения [](https://github.com/aoshimash/urlmap).
    
- `--verbose` — видеть больше деталей процесса [](https://github.com/aoshimash/urlmap).
    
- `--rate-limit 5` — ограничить скорость запросов (важно, чтобы не перегрузить сайт)

Для большинства обычных сайтов `urlmap` отработает отлично. Однако у него есть важное ограничение: он анализирует статический HTML-код и **не обрабатывает JavaScript** 
Если сайт написан на React, Vue или Angular (так называемые SPA - Single Page Applications), он может найти не все ссылки, потому что многие из них генерируются динамически уже после загрузки страницы [](https://github.com/aoshimash/urlmap/issues/46). Сейчас в разработке находится версия с поддержкой рендеринга JavaScript, но на данный момент она еще не выпущена
