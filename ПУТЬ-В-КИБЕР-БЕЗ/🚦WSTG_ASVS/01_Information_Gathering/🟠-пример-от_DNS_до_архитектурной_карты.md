# Картирование архитектуры приложения

тест посвящён определению того, как устроено приложение на высоком уровне: из каких компонентов оно состоит, как они взаимодействуют, какие сетевые и защитные элементы стоят между мной и сервером. Понимание этой архитектуры критически важно, чтобы правильно спланировать тестирование и не тратить время на то, что находится вне зоны ответственности заказчика

нужно - чтобы не тестить то - что не входит в скоуп, и чтобы не пропустить нужное

**Цель** - нарисовать для себя карту "боевых действий": где находится приложение, какие технологии используются, где проходят границы дозволенного тестирования и какие защитные механизмы могут помешать

- **Определить основные компоненты приложения:** веб-сервер, база данных, система аутентификации, сторонние сервисы
    
- **Выявить модель хостинга:** классический хостинг, PaaS, serverless, микросервисы
    
- **Обнаружить сетевые компоненты:** обратный прокси, балансировщик нагрузки, CDN
    
- **Идентифицировать средства защиты:** сетевой экран, система обнаружения вторжений (IDS/IPS), Web Application Firewall (WAF)
    
- **Понять схему хранения данных:** статические файлы (S3, Azure Storage), базы данных

### 🟠 этап 1: DNS-разведка c DIG (WSTG-INFO-04)

Начинаю с самого базового - узнаю, где физически находится приложение и как оно доступно извне

**Шаг 1.1: Базовый A-запрос**
подробнее [[DIG]]
```q
dig example.com A +short
```

**Результат:** `93.184.216.34`  
**Что делаю:** получаю основной IP-адрес

**Шаг 1.2: Проверка IPv6**
подробнее [[DIG]]
```q
dig example.com AAAA +short
```

**Результат:** `2606:2800:220:1:248:1893:25c8:1946`  
**Что делаю:** если есть IPv6, добавляю его в список целей

**Шаг 1.3: MX-записи (почта)**

подробнее [[DIG]]
```q
dig example.com MX
```

**Результат:** `10 mail.example.com`  
**Что делаю:** определяю, используется ли почта на этом домене. Если да - проверяю SPF/DKIM/DMARC позже

**Шаг 1.4: NS-записи (хостинг-провайдер)**

подробнее [[DIG]]
```q
dig example.com NS
```

**Результат:** `ns1.cloudflare.com`, `ns2.cloudflare.com`  
**Вывод:** домен использует Cloudflare DNS - это сразу говорит о возможном наличии CDN и WAF

> 	**CDN** - это **Content Delivery Network**
		это огромное количество серверов, разбросанных по всему миру. Они хранят копии твоего сайта (картинки, видео, скрипты, HTML-страницы) и отдают их пользователю с того сервера, который находится к нему географически ближе всего



**Шаг 1.5: TXT-записи (SPF, верификация)**
подробнее [[DIG]]
```q
dig example.com TXT
```

**Результат:** `v=spf1 include:_spf.google.com ~all`, `google-site-verification=...`  
**Вывод:** почта настроена через Google Workspace (SPF), это важно для оценки фишинговых рисков

**Шаг 1.6: Перебор поддоменов (ручной + автоматический)**
подробнее [[DIG]]
```c
for sub in admin mail dev staging api test; do dig $sub.example.com +short; done
```

**Результат:** `admin.example.com` → `93.184.216.34`, `api.example.com` → `93.184.216.35`  
**Вывод:** найдены скрытые поддомены, которые не видны на главной странице. Это расширяет поверхность атаки

**Шаг 1.7: Обратный DNS-запрос (PTR)**
**узнать, какой домен привязан к IP-адресу**
подробнее [[DIG]]
```q
dig -x 93.184.216.34
```

**Результат:** `example.com`  
**Что делаю:** проверяю, совпадает ли обратная запись с прямым именем. Если нет - это может быть shared hosting

нужно для:

- **Подтвердить, что IP принадлежит цели.** Ты сканируешь `93.184.216.34`. Обратный запрос вернул `example.com`. Значит, ты точно попал по адресу, а не на соседний сервер хостинг-провайдера
    
- **Обнаружить shared hosting.** Если обратный запрос вернул `customerHuyNa123.hosting-provider.com`, а не `example.com`, это значит, что на этом IP живёт много сайтов. Это расширяет твою поверхность атаки (надо проверить и соседей) и накладывает ограничения на пентест (нельзя ломать чужое)
   
- **Выявить инфраструктуру.** Обратный ответ может выдать, что сервер находится в облаке Яндекса (как в твоём случае с `unalocated.63.wixsite.com`). Это помогает понять модель хостинга и границы скоупа

**Шаг 2.5: Перебор каталогов (dirbusting)**
через gobuster , но можно и через интрудер

вот тут файл где инсрукция к gobuster - [[gobuster]]

```q
скорость молнии - опасно
gobuster dir -u https://example.com -w /usr/share/wordlists/dirb/common.txt -x php,txt,log,backup -t 50

безопаснее
gobuster dir -u https://example.com -w /usr/share/wordlists/dirb/common.txt -x php,txt,log,backup -t 15 --delay 500ms --timeout 10s -b 404,403 -o results.txt
```
**Нахожу:**

- `/wp-admin` → 302 (редирект на логин)
    
- `/wp-content` → 200 (OK)
    
- `/wp-includes` → 403 (доступ запрещён)
    
- `/phpmyadmin` → 404 (не найдено - хорошо)
    
- `/backup` → 200 (ОПАСНО! найден бэкап)
    

**Вывод:** выявлены все стандартные пути WordPress. Найден открытый бэкап — это критическая находка

**Шаг 2.6: Определение плагинов**

- Проверяю `/wp-content/plugins/`
    
- Использую `wpscan` для автоматического поиска уязвимых плагинов:

здессь файл  подробнее про wpscan - [[[wpscan_для-WordPress]]]

```c
wpscan --url https://example.com --enumerate vp,vt
```

**Результат:** найдены плагины с известными уязвимостями (например, `wp-file-manager`)

### Этап 5: Выявление сетевой архитектуры (WSTG-INFO-10)

Теперь собираю всё воедино, чтобы понять, где и как развёрнуто приложение

**Шаг 5.1: Анализ хостинг-модели**

- NS-записи на `cloudflare.com` → **PaaS или классический хостинг за CDN**
- 
   **NS-записи (Name Server records)** - это как **адресная книга для всего интернета**. Они указывают, какой DNS-сервер является авторитетным ("главным") для конкретного домена и хранит у себя его полную карту
   
- Проверяю IP `93.184.216.34` через `whois` → принадлежит `Example Inc.` → **выделенный сервер**
   
- Вижу `Server: nginx`, `PHP/7.4.33` → **классический LAMP-стек**
   
- **Вывод:** выделенный сервер (dedicated server), не PaaS и не serverless
   

**Шаг 5.2: Проверка наличия CDN**

- `whois 93.184.216.34` → IP принадлежит Cloudflare
   
- Проверяю заголовки: `CF-Cache-Status: HIT` → **CDN Cloudflare в наличии**
   
- **Вывод:** все запросы идут через Cloudflare, который также может выполнять роль WAF
   

**Шаг 5.3: Выявление балансировщика**  
Делаю серию запросов:

```c
for i in {1..10}; do curl -I https://example.com | grep -i "date"; done
```

**Результат:** все даты совпадают → скорее всего, балансировщика нет (или он не выдаёт себя)  
Проверяю наличие куки `BIGipServer` → нет → **балансировщик отсутствует**



**Шаг 5.4: Выявление WAF**  
Отправляю тестовую атаку в параметр:

```q
curl https://example.com/?p=123' OR '1'='1
```

**Результат:** получаю `HTTP/1.1 403 Forbidden` и страницу с "Ray ID: ..." от Cloudflare  
**Вывод:** Cloudflare WAF активен и блокирует SQL-инъекции

**Шаг 5.5: Сканирование портов**

подробне про nmap - здесь в файле [[[NMAP]]]

```q
nmap -p 80,443,22,21,3306,5432 93.184.216.34
```

**Результат:**

```q
PORT    STATE  SERVICE
22/tcp  open   ssh
80/tcp  open   http
443/tcp open   https
3306/tcp closed mysql
5432/tcp closed postgresql
```

**Вывод:** SSH открыт (может быть уязвим к брутфорсу), MySQL и PostgreSQL закрыты. Файрвол есть, так как порты не отвечают (filtered), а не закрыты (closed)

### Этап 6: Картирование внешних зависимостей

Смотрю, что ещё использует приложение

**Шаг 6.1: Анализ DevTools (вкладка Network)**  
Вижу запросы к:

- `https://maps.googleapis.com/maps/api/js?key=AIzaSy...` (Google Maps API)
- `https://www.google-analytics.com/analytics.js` (Google Analytics)

**Шаг 6.2: Идентификация сторонних сервисов**

- Google Maps API Key - виден прямо в запросе. Проверяю ограничения: ключ ограничен только Google Maps API, но не ограничен по HTTP-рефереру. Это рискованно - злоумышленник может использовать ключ на своём сайте
   
- Stripe - платёжная система, её тестирование вне скоупа (это сторонний сервис). Но я должен проверить, правильно ли настроены callback-URL
   

**Шаг 6.3: Проверка конфигурации email**  
SPF-запись указывает на Google Workspace. Проверяю DMARC и DKIM:


```q

dig default._domainkey.example.com TXT
```

**Результат:** DMARC настроен (`p=quarantine`), DKIM тоже есть → защита от подделки писем на хорошем уровне

### 🟠Финальный этап: Составление архитектурной карты🟠

| Компонент             | Детали                                                                                          | Статус (что тестировать)                                               |
| --------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **Объект**            | `example.com` (IP: 93.184.216.34)                                                               | Основная цель                                                          |
| **DNS-хостинг**       | Cloudflare (NS: [ns1.cloudflare.com]                                                            | Публичные записи, все в скоупе                                         |

| **Хостинг-модель**    | Выделенный сервер (dedicated), не PaaS                                                          | Полный доступ к серверной части                                        |
| **CDN / WAF**         | Cloudflare (WAF активен)                                                                        | WAF будет блокировать атаки, нужно учитывать это в сканерах            |
| **Сетевой экран**     | Активен (порты filtered)                                                                        | Порт-сканеры не покажут реальную картину, нужно тестировать через HTTP |
| **Веб-сервер**        | nginx/1.18.0                                                                                    | Проверить на уязвимости этой версии                                    |
| **Язык / Фреймворк**  | PHP/7.4.33, WordPress 5.8.2                                                                     | Искать эксплойты под эту версию WP                                     |

| **Почта**             | Google Workspace (SPF, DKIM, DMARC)                                                             | Проверить на ошибки в SPF                                              |
| **Сторонние API**     | Google Maps (ключ без реферера), Stripe, Google Analytics                                       | Ключ Google Maps - риск (можно использовать повторно)                  |
| **Статические файлы** | Локальные (CDN для CSS/JS)                                                                      | Проверить на открытые бэкапы (уже найден)                              |
| **Ошибки**            | Детальные (выдают пути, IP, версии)                                                             | Подавить, чтобы не давать информацию атакующим                         |
| **Границы скоупа**    | Тестирование самого приложения - в скоупе; тестирование Cloudflare, Stripe, Google - вне скоупа |                                                                        |
