WPScan - это специализированный сканер для WordPress. Он не просто перебирает пути, как Gobuster, а проверяет ядро, плагины, темы и пользователей на наличие известных уязвимостей, используя обширную базу данных. По сути, он делает за тебя всю работу по сбору информации о целевом сайте на WordPress 

**Ключевое отличие от Gobuster:** WPScan "понимает" структуру WordPress. Он знает, какие файлы и папки где лежат, как выглядит типовой код, и использует эту информацию для более точного и глубокого анализа, а не просто для слепого перебора путей

---

##  Полный пример безопасной команды

Вот как может выглядеть твой `wpscan`, который выполнит глубокий, но аккуратный анализ:


```c
wpscan --url https://example.com -e vp,vt,u --plugins-detection passive --api-token ТВОЙ_ТОКЕН --throttle 500 --random-user-agent -o scan_results.txt
```

##  Основные режимы и флаги

Ключевой флаг WPScan для управления сканированием - это `-e` (или `--enumerate`). Он говорит программе, что именно искать 

### 1. `-e` - управление перечислением

С помощью этого флага указываешь, какие компоненты WordPress нужно искать. Значения можно комбинировать через запятую 

|Значение|Расшифровка|Что делает|
|---|---|---|
|`vp`|**V**ulnerable **p**lugins|Ищет плагины с известными уязвимостями [](https://cloud.tencent.com.cn/developer/article/2395980?from=15425)|
|`ap`|**A**ll **p**lugins|Ищет все установленные плагины (может долго) [](https://dockers.xuanyuan.me/image/securecodebox/scanner-wpscan)[](https://www.securecodebox.io/docs/scanners/wpscan/#__docusaurus_skipToContent_fallback)|
|`p`|**P**opular plugins|Ищет популярные плагины (быстрый режим)|
|`vt`|**V**ulnerable **t**hemes|Ищет темы с известными уязвимостями|
|`at`|**A**ll **t**hemes|Ищет все установленные темы|
|`t`|Popular **t**hemes|Ищет популярные темы (быстрый режим)|
|`u`|**U**sers|Перечисляет пользователей WordPress [](https://github.com/dev-angelist/Ethical-Hacking-Tools/blob/main/practical-ethical-hacker-notes/tools/wpscan.md)[](https://cloud.tencent.com.cn/developer/article/2395980?from=15425)|
|`cb`|**C**onfig **b**ackups|Ищет бэкапы файлов конфигурации (`wp-config.php`)|
|`dbe`|**D**ata**b**ase **e**xports|Ищет дампы базы данных|
|`tt`|**T**im**t**humbs|Ищет уязвимые скрипты TimThumb (старый, но опасный)|

**Пример:** `wpscan --url https://example.com -e vp,vt,u` - найдет уязвимые плагины, уязвимые темы и пользователей.

### 2. Ключевые флаги

|Флаг|Что делает|
|---|---|
|`--api-token TOKEN`|**ОБЯЗАТЕЛЬНО.** Без токена WPScan найдёт версии, но **не покажет, есть ли в них уязвимости** [](https://dockers.xuanyuan.me/image/securecodebox/scanner-wpscan)[](https://cloud.tencent.com.cn/developer/article/2395980?from=15425). Токен можно получить бесплатно на сайте WPScan.|
|`--update`|Обновляет локальную базу уязвимостей WPScan [](https://cloud.tencent.com.cn/developer/article/2395980?from=15425). Делай это перед каждым важным сканированием.|
|`--passwords FILE`|Путь до словаря с паролями для брутфорса.|
|`--usernames USER`|Имя пользователя для брутфорса (или список из файла).|
|`--plugins-detection MODE`|Режим обнаружения плагинов: `passive`, `aggressive`, `mixed` (по умолчанию `passive`). `aggressive` может создавать больше шума, но находить больше [](https://trickest.com/tools/wpscan)[](https://dockers.xuanyuan.me/image/securecodebox/scanner-wpscan).|

## 🛡️ Ключевые настройки для безопасного сканирования

WPScan и так довольно "вежливый", но вот что стоит помнить:

### 1. Управляй режимом обнаружения (`--plugins-detection`)

По умолчанию используется `passive` для плагинов. Этот режим анализирует HTML-код и ссылки на страницах — он тихий и не создаёт лишней нагрузки . Режим `aggressive` отправляет больше запросов, пытаясь найти скрытые файлы и папки.



```c
wpscan --url https://example.com -e vp --plugins-detection passive
```

**Для безопасного сканирования:** используй `passive`. Это снизит нагрузку на сервер и шансы быть замеченным

### 2. Используй задержку (`--throttle`)

Этот флаг добавляет задержку между запросами в миллисекундах 
При его использовании количество потоков автоматически устанавливается в 1, что делает сканирование максимально безопасным


```c
wpscan --url https://example.com -e vp --throttle 1000
```
**Почему:** Задержка в 1 секунду делает сканирование абсолютно незаметным для систем мониторинга и защиты

### 3. Ограничь количество потоков (`-t`)

По умолчанию используется 5 потоков. Если ты хочешь ускориться, но не перегружать сервер, можешь увеличить до 10–15 


```c
wpscan --url https://example.com -e vp -t 10
```

**Почему:** Меньше потоков = меньше одновременных запросов = меньше нагрузка.

### 4. Используй случайный User-Agent (`--random-user-agent`)

Скрывает, что ты используешь сканер, маскируясь под разные браузеры 


```c
wpscan --url https://example.com -e vp --random-user-agent
```

**Почему:** Это сбивает с толку примитивные системы защиты, которые банят по User-Agent.

### 5. Не забывай про API-токен

Без него результаты будут неполными - ты увидишь версии, но не узнаешь, есть ли в них реальные уязвимости 
```c
wpscan --url https://example.com -e vp --api-token ТВОЙ_ТОКЕН
```

##  Полный пример безопасной команды

Вот как может выглядеть твой `wpscan`, который выполнит глубокий, но аккуратный анализ:


```c
wpscan --url https://example.com -e vp,vt,u --plugins-detection passive --api-token ТВОЙ_ТОКЕН --throttle 500 --random-user-agent -o scan_results.txt
```

**Что делает эта команда:**

- `-e vp,vt,u` — ищет уязвимые плагины, уязвимые темы и пользователей.
    
- `--plugins-detection passive` — использует пассивный режим, чтобы не шуметь.
    
- `--api-token ...` — подключает базу уязвимостей.
    
- `--throttle 500` — делает паузу в полсекунды между запросами (безопасно и незаметно).
    
- `--random-user-agent` — маскирует сканер.
    
- `-o scan_results.txt` — сохраняет результат в файл.

##  Дополнительно: Брутфорс паролей

WPScan умеет подбирать пароли. Это агрессивный и шумный метод, ИСПОЛЬЗОВАНИЕ его **только с разрешения заказчика**


```c
wpscan --url https://example.com -U admin --passwords /usr/share/wordlists/rockyou.txt
```
- `-U admin` — атака на пользователя `admin`.
    
- `--passwords` — путь к словарю
