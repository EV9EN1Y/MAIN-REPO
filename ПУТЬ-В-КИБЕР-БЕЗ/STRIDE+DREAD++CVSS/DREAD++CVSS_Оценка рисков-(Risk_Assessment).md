# 🟢  DREAD

это старая методология от Microsoft (сейчас используют реже, но простая и наглядная)

Каждая угроза оценивается по 5 шкалам (1–10):

```

D — Damage Potential    (Потенциальный ущерб)

R — Reproducibility     (Воспроизводимость)

E — Exploitability      (Сложность эксплуатации)

A — Affected Users      (Количество затронутых пользователей)

D — Discoverability     (Обнаруживаемость)

```

Финальный балл: `(D+R+E+A+D) / 5`
  
---

#### Шкалы DREAD подробно

### D - Damage Potential (Ущерб)


Балл и  че значит

 0 - Нет ущерба 

 5 -  Утечка нечувствительных данных 

 8 -  Утечка приватных данных пользователей 

 10 -  Полный компромет системы, RCE, доступ к БД 

  ----
  
### R - Reproducibility (Воспроизводимость)


 Балл и  что значит 
| 0 - Очень сложно или случайно 

| 5 - Воспроизводится, но с определёнными условиями 

| 10 -  Всегда воспроизводится при одних и тех же действиях 

  ------

### E - Exploitability (Сложность эксплуатации)

| 0- Нужен доступ к исходникам + спец. оборудование 

| 5 - Требуется аутентификация + специальные условия 

| 8 - Анонимный доступ, но нужны знания 

| 10 - Достаточно браузера, не нужна аутентификация 

  
-------
### A - Affected Users (Количество затронутых)

| 0 - Никто 

| 5 - Часть пользователей 

| 10 - Все пользователи / администраторы 

  ---------

### D - Discoverability (Обнаруживаемость)


| 0 - Почти невозможно найти 

| 5 - Можно найти при анализе 

| 8 - Легко обнаруживается (в логах, коде, ответах) 

| 10 - Информация в открытом доступе / write-up

## Уровни критичности DREAD


```q

Итоговый балл   | Уровень    | Действие

─────────────────┼────────────┼──────────────────────

9 – 10          | CRITICAL   | Фиксить немедленно

7 – 8           | HIGH       | Фиксить в этом спринте

4 – 6           | MEDIUM     | Запланировать

1 – 3           | LOW        | Принять или отложить

```

# CVSS v3 (Common Vulnerability Scoring System)

Промышленный стандарт оценки уязвимостей (NVD, MITRE, все багбаунти)
Сложнее DREAD, но точнее и принят везде

## Три группы метрик

```

Base Metrics     → Постоянные (характеристики уязвимости)

Temporal Metrics → Меняются со временем (есть ли эксплоит, фикс)

Environmental    → Зависят от окружения (как у тебя настроено)

```

Финальный балл: 0.0 – 10.0

---

## 🟠 Base Metrics (базовые)

##### Attack Vector (AV) - Вектор атаки


```q

N (Network)     — Через интернет (удалённо)          ← самый опасный

A (Adjacent)    — Из соседней сети (Wi-Fi, Bluetooth)

L (Local)       — Нужен локальный доступ             ← наименее опасный

P (Physical)    — Физический доступ к устройству

```

##### Attack Complexity (AC) - Сложность атаки

```q

L (Low)         — Никаких специальных условий

H (High)        — Нужны специфические условия (тайминг, race condition)

```

  ##### Privileges Required (PR) - Нужны ли права

```q

N (None)        — Анонимно                                   ← опаснее

L (Low)         — Обычный пользователь

H (High)        — Администратор

```

  ##### User Interaction (UI) - Нужно ли участие пользователя

```q

N (None)        — Злоумышленник делает всё сам                ← опаснее

R (Required)    — Жертва должна кликнуть/скачать

```

  ### Scope (S) - Меняется ли контекст безопасности

```q

U (Unchanged)   — Атака в пределах того же компонента

C (Changed)     — Атака затрагивает другие компоненты         ← опаснее

```

  ##### Impact Metrics  Последствия (CIA)

```q

C — Confidentiality (Конфиденциальность)

I — Integrity       (Целостность)

A — Availability    (Доступность)

  

Каждая: H (High) / L (Low) / N (None)

```

## Пример CVSS для MeetWay (мое приложение)
[[0_MeetWay]]

  

### JWT в логах

```q

AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N

   │   │   │   │   │  │   │   │   │

   │   │   │   │   │  │   │   │   └── Availability: None

   │   │   │   │   │  │   │   └────── Integrity: Low (могут юзать JWT)

   │   │   │   │   │  │   └────────── Confidentiality: High (JWT → доступ к данным)

   │   │   │   │   │  └────────────── Scope: Unchanged

   │   │   │   │   └────────────────── User Interaction: None

   │   │   │   └────────────────────── Privileges: None (аноним из логов?)

   │   │   └────────────────────────── Attack Complexity: Low

   │   └────────────────────────────── Attack Vector: Network

   └────────────────────────────────── Версия CVSS

  

Score: 8.3 → HIGH

```


### Соль AES (kkr15) в UserDefaults (использовалась для шифрования чатов)


```q

AV:P/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N

   │   │   │   │  │   │   │   │   │

   │   │   │   │  │   │   │   │   └── A:N (доступность не страдает)

   │   │   │   │  │   │   │   └────── I:H (можно изменить соль → дешифровка)

   │   │   │   │  │   │   └────────── C:H (соль → расшифровка всего)

   │   │   │   │  │   └────────────── Scope: Unchanged

   │   │   │   │  └────────────────── UI: None

   │   │   │   └────────────────────── PR: Low (обычный юзер или бэкап)

   │   │   └────────────────────────── AC: Low

   │   └────────────────────────────── AV: Physical (нужен физический доступ)

  

Score: 6.2 → MEDIUM (потому что AV:Physical)

```

  

> 💡 Внимание: CVSS ****не учитывает контекст****. Да, AV:Physical снижает балл, но если уязвимость - соль для шифрования, то последствия катастрофические. ****Всегда проверяй Environmental метрики.****

##  воркфлоу AppSec инженера

  

```q

1. STRIDE → нахожу угрозу (например: JWT в логах)

  

2. DREAD → быстро оцениваю (10 минут)

   Damage=9, Reproducibility=10, Exploitability=7,

   Affected=10, Discoverability=8

   Итого: 8.8 → HIGH, фиксим в этом спринте

  

3. CVSS → официальная оценка (кладу в отчёт)

   AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N

   Score: 8.3 → HIGH

  

4. Рекомендация разработчикам:

   «JWT летит в NSLog, утечка. Score 8.3. Фикс: os_log с <private>»

  

5. Проверяю после фикса:

   — Убедиться, что NSLog удалён

   — Проверить логи на устройстве

```
